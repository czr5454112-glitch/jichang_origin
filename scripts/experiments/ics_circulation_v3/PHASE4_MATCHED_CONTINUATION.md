# Phase 4 第七轮：匹配继续策略、搜索覆盖与保守终点容量筛查（2026-10-10）

用户要求继续朝原目标优化，问题通过分析和资料寻找方法解决，过程持续记录，尚未允许提交或推送。本轮继承第六轮同区直接供盘强对照，不修改已冻结的历史结果、默认控制器、业务硬约束或原C++工作区修改。目标仍为两需求、有限托盘循环与模型引导的轻量学习，不把开发诊断当作TRE/CIE或真实业务验收。

## 1. 本轮实际问题

第六轮新慢控制器在27条开发输入中11条降成本、16条持平，但这是慢层变化的效果，并非学习增益。新旧名义轨迹虽都是180次尝试、174个非空候选池，完整公开观察只有127次相同；counterflow的72次中只有19次相同。旧标签的继续控制器也不同，即使当前物理状态一致，后续成本仍可能不同。

另一个缺口是底层单查询有真实搜索截断：old32与old64各50次、新方法93次expansion_budget_exhausted。没有case级删失不等于动作集合完整。旧BudgetGenerator日志没有空盘destination、k、真实调用状态/version与完整诊断；慢层先在scratch提交前面的提案，不能把一次slow入口snapshot当成所有内部搜索的状态。

本轮先解决可恢复真实状态、继续策略一致性和候选覆盖的可核验链条，再判断剩余价值机会与学习投入。第六轮两个非保护服务退步及共享边/预测误差原因仍保留；不会因为仍然准时就下调逐件保护的业务要求。

## 2. 运行前的协议与边界

1. 从原三个nominal初态、原公开预测与原任务流装入same_zone32plus32，完整采集每个真实载盘生成尝试，包括零候选。候选、private replay cache、真实cursor、next-slow、当前有效控制器和合同全部绑定；以实际记录导出分母，不硬套174×4。第六轮记录预期为180尝试、6零池、174非空、692候选，但必须重新验证。
2. 逐物理结果、搜索账、实际机会与第六轮正式nominal核对。采样发生在真实callback、当前候选已生成且尚未选择之时，立即克隆，不能重构“看起来相同”的状态。避免把含engine回指的SlowAuditController或整个查询历史捕入checkpoint。
3. 使用固定的各scene首个非空池和counterflow首个续程池作恢复/资源pilot，先检验正常恢复选择与原部署一致。强制候选是显式替换一次selector调用，其日志差异与物理/搜索差异分别处理，不任意排除有问题的字段。
4. 冻结后对新轨迹全部实际候选执行相同new continuation的完整任务周期评价。真实未来只供离线物理环境；在线策略仍只能看到当时Snapshot与已发布预测。完整任务分母、保护任务、首次完成/排空/控制静止及有限预算停止分别记账，不将未知成本填零。局部选择损失不可相加为闭环收益。
5. 另设明确的历史事后子组：旧counterflow全部12个已审非最优checkpoint，d19/20/21/22/23/40/41/42/43/46/48/50，共48原候选，在同一旧state/cache/cursor下换新继续控制器重评。用于分离继续策略变化和状态迁移，不混成新on-policy数据或独立确认。d40的c0/c1应重现第六轮新方法的148.1/146.7结果。
6. 逐查询透明记录实际Snapshot（包括slow scratch）、bag/tray/destination/k、原始候选、私有cache及search diagnostics。覆盖探针只在保存的同一公开状态作影子搜索：原区域算法扩预算与全图参考分别记录，不把额外候选悄悄喂入已冻结部署，也不把事件搜索的一个最早路线当作完整K候选最优性证明。
7. 查询覆盖单独重录新方法全部27条输入，逐case核对第六轮物理结果、原搜索账、机会及slow动作。全部93个截断查询均进入正式影子分母。成功对照按 `(scene, callsite, source, destination, requested_k, protected)` 匹配，在27条记录中按 `(case_id, time, ordinal)` 取最早成功查询；无对应成功cell记为missing，不挑另一个种子。每状态固定四种搜索：regional原3000、12000、48000扩展预算，以及fullgraph event48000；H180、原K4/1、原validator不变，regional的local_label3/static8不变。全图冷预处理记入预算，没有额外wall截断。该试验区分现预算、区域抽象和局部标签配额的限制，仍不是完整K候选证明。

结果出现前保存协议、输入和源/测试SHA。查询探针与采样器分别实现并由独立审查测试；代码冻结后运行全ICS回归。collector计划3 worker，逐候选评价计划6 worker；本机只读测得22逻辑CPU、16物理核、约33.7GB内存，先用pilot实际CPU/内存验证。历史693个旧候选约8862 CPU秒和1572秒并行wall只作估计，不当成本轮测量或预算替代。

## 3. 资料依据与不采用的保证

Ross与Bagnell的[Reinforcement and Imitation Learning via Interactive No-Regret Learning](https://arxiv.org/html/1406.5979) §2.1、§2.5、§3将动作价值明确为执行当前动作后再跟随某一指定策略的未来成本，并区分策略诱导的状态分布；其限制部分提醒，无法实现的强继续策略可能给出过于乐观的标签。本轮据此显式绑定继续控制器和真实状态来源，但未实现完整AggreVaTe/NRPI训练，也不借用其no-regret或有限样本保证。

Bertsekas的[Dynamic Programming and Suboptimal Control: A Survey from ADP to MPC](https://web.mit.edu/dimitrib/www/ADP-MPC.pdf)关于rollout/base-policy的说明支持把继续策略成本与当前动作联系起来。这里只引用基础策略依赖这一方法结构；本项目有受限候选、有限回放和未校准预测误差，不能直接取得精确策略改进的单调保证。引用不替代本仓库逐实例复现。

针对时间标签搜索膨胀，还查阅了Phillips与Likhachev的[SIPP原文](https://www.cs.cmu.edu/afs/cs.cmu.edu/Web/People/maxim/files/sipp_icra11.pdf) §III算法、假设及定理1。它用位置和连续安全区间压缩时间维度；较早到达支配较晚到达的论证依赖允许原地等待，目标是最短到达时间。本项目含不可等待链、节点/边/接收容量、终点hold、多候选与循环总成本，不能直接删掉较晚标签或套用该保证。若覆盖探针证实标签膨胀为瓶颈，后续可以研究“可等待锚点安全区间＋不可等待链显式时序”；本轮仍执行已冻结影子方案，不因读到新方法而中途改实验。

本项目适用性反例（逻辑推导，不冒充新仿真）：A可等待、B不可等待、C可等待，两段行程各1；C在 `[0,3)` 被占用。到B的t=1标签不能停到t=2，立即前进会在t=2撞上C占用；从A稍晚出发、t=2到B、t=3到C则可行。因此即使B自身同属一个安全区间，也不能只保留其最早到达标签。任何后续压缩都必须保留这种下游窗口信息；当前EventTimeSearch的跨区不可等待链事件投影不能被省掉。
