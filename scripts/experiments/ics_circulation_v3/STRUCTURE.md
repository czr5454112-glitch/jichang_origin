# 时间化表示的保证范围

本笔记对应 V3 §9，给出标准记账关系及选择误差界。它们不是新定理，也不是当前程序已获得全局递归可行性、非阻塞或逐件不增时保证的声明。

## 一次释放移动

固定其他所有供给、需求和已接受调拨。同一个真实托盘在同一个节点的首次可导出空盘时刻从 τ₀ 移到 τ₁，则任意时刻 t 的累计可用量变化是

`δR(t) = 1[t ≥ τ₁] − 1[t ≥ τ₀]`。

这是两个单位阶跃函数相减。若 τ₁ > τ₀，则仅在 `[τ₀, τ₁)` 内减少一盘；若提前释放，交换符号。到达、卸载完成、供应方 hold 结束必须分开，τ 指最后的真正可用时刻。`evaluation.ReleaseChange.cumulative_delta` 表达的正是这个关系。

在**确定性、其他事件冻结、同节点可互换空盘、给定同刻事件顺序**的库存模型中，设旧库存前缀为 E(t)，最低余量为 m(t)。替换后的库存下限可行当且仅当每个事件前缀都有 `E(t)+δR(t) ≥ m(t)`。证明直接由每次事件后的库存守恒式得到；区间内没有其他变化，检查事件边界足够。同刻先供给还是先消费必须与实际事件引擎一致，不能用净量掩盖先消费导致的短缺。

这一必要充分条件只覆盖上述库存子模型。若托盘有不同资格、存在区内运输时间或模块不允许立即导出，同区总库存非负仍可能无法兑现某个节点的任务。若某个候选同时改变通道预约或接收缓冲，还须独立检查这些时空资源。允许替补调拨时，必须真的构造并授权替补；总盘数相等不能代替运输证明。

`CirculationFootprint` 目前同时记录释放移动和预约区间增减；它不是充分状态。未知模块内部状态、未来需求误差、多个未来任务之间的竞争、未承诺循环次数，以及多个决策者对同一资源的同时需求，都可能让同一有限特征对应不同后果。两次提交共享余量的问题由资源所有者处理，不能由上述释放恒等式解决。

## 单次排名误差

设 A 是完全相同的合法候选集合，J(a) 是同一有限时域、同一继续控制器下的真实评价，且对全部 a∈A 有 `|Ĵ(a)−J(a)| ≤ ε`。预测最优 â 与集合内真实最优 a* 满足

`J(â) ≤ Ĵ(â)+ε ≤ Ĵ(a*)+ε ≤ J(a*)+2ε`。

这是标准最小值选择界。没有对全部候选的误差上界时，训练 RMSE、小平均误差或少数测试场景不提供该保证。两条外生轨迹的平均回放标签只是该样本评价的估计，并非已知真实期望。

反复部署会改变状态分布、其他任务的动作和后续盘循环，不能把单次 2ε 直接写成整个系统的服务界。候选生成若截断，A 内最好也不等于物理网络上最好；参考预测回放若枚举完全，最好也只针对声明的有限动作集合和预测代理。

## 本轮结论怎么使用

库存前缀与资源复验用于排除明确违规动作；解析分数与学习器仅在可提交候选内排名。报告应分别给出授权成功、未完成/按时服务、候选 regret、计算与通信口径，以及代理假设。任一平均成本优势均不抵消身份、容量或权限错误。
