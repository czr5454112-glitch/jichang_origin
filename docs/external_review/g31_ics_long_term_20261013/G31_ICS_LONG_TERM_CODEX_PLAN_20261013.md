## 5. P1：让 G31 宿主真正能在线控制、分支和恢复

### 5.1 必须实现的接口

以下名称为职责建议，不要求另建同名大框架；优先在现有类的正确事件边界实现。[D]

```text
NativeSession.initialize(physical_contract, environment_tape)
NativeSession.advance_to_control_boundary(...) / process_next_event(...)
NativeSession.observe(owner_id) -> RegionalObservation
NativeSession.submit_route_intent(request) -> accepted/pending/rejected
NativeSession.submit_transfer_intent(request) -> accepted/pending/rejected
NativeSession.checkpoint() / restore(...) / fork(...)
NativeSession.result_at(common_horizon)
```

不能通过反复调用旧 `run()` 从 time=0 重建世界来冒充在线控制。旧一次性 `run` 可保留为兼容入口，内部复用同一个 session。

session 必须支持业务到达、故障/恢复、工序完成、消息到达和控制请求交错；不是只有所有任务跑完后才允许查询。请求可在非慢层时刻到达，实际提交必须在安全的原子边界。一次优化太慢或消息迟到时，世界仍按明确定义的公共时钟推进，旧候选可能失效。

仿真实验区分确定性逻辑处理延迟和真实测得计算时间，不能把暂停仿真等待优化的单线程过程称为“期间物理持续演化”。可把控制完成作为带版本事件排队；本轮未到的事件、真实到达带仍仅属环境。实际 wall-clock 联机评价另设配置，不用 wall 时间随机扰乱复现实验而不记账。

### 5.2 完整 checkpoint，而不是旧结构里加一个 circulation 字段

逐项覆盖：native 事件堆与序号、同刻微相位、当前待选候选/cursor、所有 BagState/托盘/工序、traversal 与头距尾窗、接收/导出租约、J2 与 P2 能力和代际、故障真实/已通知状态、owner 消息队列与去重/撤销状态、源等待队列、慢层相位、控制器参数与必要缓存、累计成本与结果分母。

静态不可变 topology 可以共享；可变故障、租约、缓存、工厂计账不能跨分支共享。图身份、原生 capability、引用/指针绑定须恢复正确，不能用裸内存复制或旧五类哈希漏掉新状态。持久文件使用版本化受信 schema；不能不核来源就反序列化历史任意对象。

**关键不变性测试：**

- 连续运行 A 与中途 checkpoint→restore→继续 B 的物理事件、动作、成本和未完成总体相同；纯 wall-clock 计量字段可排除，排除理由固定。
- 两个 sibling 分支在第一个不同动作之前一致；A 的动作、消息、缓存和计账不改变 B 或父状态。
- 两条未来带在当前以前完全一样、以后不同，当前所有在线策略输出必须相同。图拓扑预计算可共享；隐藏下一次真实到达/故障时间、未发布 STD、总未来任务数或环境停止时刻不能变成策略特征。
- 在装载、入边承诺后但实际通知前、Storage release、卸载/hold、租约超时和丢 ACK 附近取断点，测试同刻顺序。
- 分支标签替换一次当前决策，不重复执行当前 tick 的其他盘决策或慢层。

### 5.3 验收与自动失败路线

checkpoint 有遗漏时先缩小“允许暂停的安全事件边界”，但不伪称支持全部中间状态；把受支持的边界用于参考。随后补齐必要待选点，不允许永远只在空系统复制。

P1 通过后立即连接 P2/P3。尚未实现 checkpoint 时，P2 输入和区域观察可并行，**反事实标签、公开预测 rollout 的正式比较与最优参考不得放行**。

交付：实际 session 入口、状态覆盖表、restore/fork/未来隔离测试及共同世界续跑样例。只有 schema 和空方法不算完成。

## 6. P2：从合成闭环走向原图任务、合理物理与真正恢复

### 6.1 原图与来源

复用成熟 G31 的地图、工作负载和原始业务身份映射；先查代码及源表，避免混淆物理节点、逻辑设备别名、跨系统重复编号、运输段和业务袋。方向、连接及原始任务不随意改变。

保留原输入和已有显式投射输入为不同因子。静态 OD 不可达时先核图解释、装卸角色、空/载模式权限和业务 crosswalk；没有证据不增边、不改目标、不删任务。新映射只能另立版本和研究组，不替换冻结负对照，不把输入设计收益当算法收益。

按来源合同恢复完整到达总体；首小时/44 袋只用于定位，不能代替完整 1×/2×。后续压力只按已认可的原生成规则增加任务流。原件明确允许的跨系统连接长度档可用原长/2km/5km，保持边数方向；档位是研究设置，不冒充现场值。

### 6.2 必須核对的物理语义

| 语义 | 实施要求 |
|---|---|
| 时间 | 保留 native 事件时间与既有亚秒服务；离散参考的取整/误差必须声明，不能把秒级参考最优外推为连续 native 最优 |
| 服务 | 区分 G31 节点服务、额外卸载、hold、接收；源表一项服务不能既算 native 服务又重复算一次卸载 |
| 等待 | 明确哪些位置空/载允许等待；禁止用所有节点都可停代替无等待链。不能停的路径须提前有安全延续，不在故障发生后临时假设能停车 |
| 容量 | 区分停放、在途、入口间隔、接收位、库位/检索服务；源数据的关闭边与零容量不得悄悄改为可用 |
| 模块 | 研究 port 的 allow/deny、min_stock 只是代理，不是现场原模块；不得开放原模块内部调度权给新算法 |
| 同刻事件 | release-before-acquire 与服务先后必须匹配真实执行，不用浮点 epsilon 人为挤出容量 |
| 正常服务 | 传递 ServiceObligation，不仅事后记 deadline_met；保留任务到达至最终卸载的完整时长与未服务总体 |

未知值必须有显式来源等级：confirmed / calibrated / research_proxy / unknown。未知不等于默认无限容量或禁止全部动作。合同敏感性与模型错误分别处理。

### 6.3 安全失败与运行能力分开

当前 quarantined 实体不消失值得保留，但“全部安全隔离后不再工作”不满足故障应对与吞吐目标。实现**事件驱动、权限受限的重新请求/恢复**：故障修复、接收释放、头距到期、模块新授权、有效新消息可唤醒受影响操作。使用 generation/version 去重，避免每个 tick 全队列重试。

一次被拒绝的 request 保留历史状态；重试使用新 attempt/版本，不复活已经过期的旧权利。未出发失败可释放未使用接收位；真实在途必须保留安全接收/后继义务。恢复动作不能让未完成袋变成空盘。

### 6.4 联合交接域：诊断保守性，不直接删检查

保留当前顺序接纳作为基线。对满泊位链式离开/同时交换，先用小域参考检查是否在**全部**G31/JIT/服务/头距/port 条件下真的有联合可行行动，不仅在抽象图中存在环。

若确有可行域损失，新增拥有明确权限的原子交接：共同预验证参与盘的真实离开/到达、接收权和尾窗，所有权利满足后一次发布；失败不半提交。没有权限的参与者不移除，历史头距不会因节点腾空而消失。

若只是新的执行权限或动作域带来收益，单列其消融；比较方法共享该物理能力。不把原子 batch 或常规 PIBT 自身算新主理论。

### 6.5 on-carrier 与 off-carrier：不能为追求跑完任意换模型

保留已实现 on-carrier 合同作为确定基准；它可能锁盘很久，也可能在正常卸载服务/队列下合理。先诊断，不因负结果自动换模型。

若来源语义要求独立 EBS，或目标研究必须比较托盘循环与库位/检索耦合，做**独立明确的 off-carrier 合同**：入库卸袋消耗接收/库位/服务，盘经过真实释放回系统；袋保留在库；检索需要服务资源和实际可用接载盘，重新绑定 identity 后出库。所有袋和盘分别守恒，固定模块仍有拒绝权。不得用无限库位、零检索时间或免费接载盘“解决缺盘”。

off-carrier 不与 on-carrier 合并报告，也不要求缺现场数据时停止所有方法研发。研究代理和参数敏感性可继续；“真实机场/EBS已校准”的主张保持 blocked。到 P7 必须给出是否必需、已实现/未实现及证据理由，不能悄悄删掉该问题。

### 6.6 先判别瓶颈，再投大计算

输出：可达性下界、必需运输/服务工作量、有限盘循环、库位和接收瓶颈、候选域限制、计算删失六类诊断。

不能把“早包从到达至 release 的全部时间”无条件算作每件必占盘时间：若模型允许晚装载，入库最迟时限又没有定义，该下界可能错误。需要入库窗口或固定模块加载规则才能推出相应强占盘界。

全流本来超过声明物理能力时保留过载组，报告积压及服务缺口；它不是降低目标、删流量或宣称任一算法无用的理由。同时保留同一来源下可行且容量活跃的研究组，避免只研究“全部方法都不可能完成”的区域。

**完成门 P2：** 至少一组原图持续循环开发运行；全部任务及失败可解释；新/旧物理域与测量口径分开；恢复不能靠造盘或取消真实义务。若完整原件确实缺失，则保持原图结构研究并记录 P7 外推限制，不拿新合成数据冒充原运营记录。

## 7. P3：两项原需求都必须成为真正的在线算法

### 7.1 区域自主路由与按需请求

明确三种标识：logistics_zone、control_partition、resource_owner，不能沿用当前唯一 zone 字段混用。每个资源只有一个权威提交位置，策略只能取得本地状态和已到达的合法消息。静态拓扑和预计算势可共享；远端活动队列、全部租约和未来业务不得直接读取。

`RouteIntent` 传递目的地/阶段、允许的局部或区域走向、版本和服务约束；`OwnerGrant` 才是硬权利；`ReleaseForecast` 是条件预测；`ExecutionReceipt` 是真实事件。四者分开，不把预测路径全程锁死后还允许 G31 任意改向。

系统 A* 编解码至少覆盖：路径节点/边映射、business/tray身份、版本、已执行/不可撤前缀、可替换后缀、Storage阶段和拒绝原因；往返 round-trip 保持语义。A*是已有系统接口/明确对照，不成为每一步必调的中央兜底。

将受限观察接入实际 candidate_record/S4 排序及原子提交接点；被上层引导的动作仍必须走 JIT/P2 和新物理复验。若改评分函数，必须明确版本和触及的信息，不把全局优化结果免费塞进每个节点。

请求结果至少区分 updated、valid_old_route、pending、rejected、timeout_unknown、failed_no_safe_continuation。旧路已因故障无效时不能计 valid_old_route；拒绝和 unknown 保留在总请求分母。

消息延迟/丢失/重复、owner不可用、计算完成时版本变化都要实际影响请求链。单进程事件模拟可先证明逻辑边界；P7 再做多进程或显式序列化隔离验证，不能由 C++ 类名字推断部署隔离已成立。

### 7.2 载盘驱动的释放预测

不要把 `HOLD_COMPLETE` 以后才知道的事实叫“预测”。在仍载盘/入库/卸载中的时刻，利用当时可见的阶段、目的地、允许路线/近期意图、现有在途与模块返回估计未来可用盘的地点与时间轮廓。

建立三本语义不同的账：

```text
ActualAvailable：已实际空闲且模块允许使用的实体
FirmRelease / ObligatedArrival：已有承诺支撑的未来供给（仍不是当前空盘）
ConditionalRelease：受路线/服务/故障/授权改变影响的预测供给
```

每次载盘路线/阶段/租约改变，按依赖更新或撤销旧预测；同一 tray 的同一释放只计一次。多周期供给需要真实相继服务模型，不能将同一实体的多个可能未来同时重复抵押。

先使用简单可解释点估计/时间区间和容量松弛，作为所有方法共享的强解析基础。预测误差与取消/陈旧度单独计量；不要先装大型神经预测器。未来需求只使用已发布修订和实际队列，保留过期预测与实际任务的区别。

### 7.3 真正的跨区控制器

移除“必须在输入提前写好 return-T0 才能动”的研究依赖；旧 transfers 输入只作为回放/测试接口保留。慢层在运行中决定新请求、方向、实体/合法数量、连接线和出发窗，通过固定 port 获取接收/导出权。

先做可解释的强解析预测匹配与有限时域滚动决策。候选包含不调拨/稍后调拨、多条允许连接、实际可用盘及有条件未来盘的**意图**；未来盘不能在释放前实际出发，冲突意图不能同时承诺为多个真实供给。

预测窗口与连接提前期、Storage release 和服务周期匹配，不能把旧 20/24 tick 默认值带入 2km/5km 场景，使所有有用供给都落在窗口外。长预测窗不意味着全程硬预约；使用事件/时间桶等有声明误差的表示，并保留窗口以外的终端未完成义务。

目前接收预留从授权直到到达持续占泊位，长线下可能过保守。可研究有真实资源支撑的接收时窗/接管承诺；在其安全实现和所有方法共享之前，不删除已有保护，也不把“免费取消保留”当优化收益。

### 7.4 P3 必须交付的三组分验

- **R1单独：** 关闭预测/学习，保留统一物理；异步请求、故障、局部绕行、边界更新确实工作。至少一个非慢层 tick 的请求能到达和处理。
- **R2单独：** 固定路线策略，同源需求下对比反应式与预测控制。调拨由控制器生成，不预写答案；报告缺盘等待、空行、正常分拣服务和模块拒绝。
- **联合：** 一次载盘选择改变未来盘分布；一次调拨改变共享线/接收占用，继而改变后续合法路由。用开/关反馈确认双向作用，不要求预设一定增益。

**完成门 P3：** 两模块真正介入，信息权限清楚，现有硬保护不放松，完整事件链和失败分母齐全。没有可测收益也不能假称通过方法门，转 P4 查可优化空间。

## 8. P4：强参考和可优化空间必须先于大训练

### 8.1 两条评价轨道，不能混算旧成果

**历史轨道**保留原 G31、HCA、已经忠实复现的其他历史方法及其原协议。相同基线、源端释放、故障等定义不被新 circulation 覆盖。不能把旧不同物理模型的吞吐/时延数字拿来相减，称为新系统提升。

**新系统轨道**在同一 circulation 模型比较所有算法。移植版标为 adapted/common-executor，不冒充原论文 paper-faithful；只完成 S3/S4 可行见证并不等于强优化参考已经齐全。

### 8.2 必须保留的比较组

| 组 | 作用及边界 |
|---|---|
| G31 + 合理反应式空盘 | 不含预测的强工程基线；不是无返回、无源保护的稻草人 |
| G31 + 最强同权限解析预测 | 包括在途、Storage/hold、可用时间、多线、源保护，开发集上认真调优 |
| 预测匹配/滚动指派 | 参考 BPD/CWPD 思想的同权限版本；未取得完整成本公式前明确写自己的解析匹配，不能称完整复现 [W2] |
| 单向耦合与一轮反馈 | 路由→供盘、供盘→路由、一轮真实响应；继续策略和信息一致 |
| 通用局部修复 | 路径/任务先后邻域＋冻结外部的合理适配；供给、权限等基本约束公平补齐 [W1] |
| 全量同域滚动修复 | 使用相同决策变量/预测/物理模型，只不限制修复域，用于质量—计算比较 |
| 小域精确参考 | 明确有限动作/时间/合同域；域内最优、可行解、界和 unknown 分开 |
| 新循环反馈/边界修复 | 主方法，无学习版本先成立 |
| 同机制＋学习 | 相同候选/权限下检验近似评价的增量 |

基本物理与权限必须公平共享；不要把拟议核心修复机制直接免费加给所有基线，再说没有区别。相反，也不能不给基线真实 Storage/返回/头距能力让其必败。更多全局信息、更多计算、不同动作域各自单列，不混为纯算法消融。

### 8.3 参考问题定义

合法动作域包含必要 WAIT/no-transfer、可授权后缀更新、允许的空盘请求和真正支持的联合交接；保留区内模块自动加载规则，不让参考越权重新分配模块内部任务。

从相同实际 checkpoint、相同外生条件和事件相位展开。小域可用显式有限枚举或约束优化；每个候选必须由同宿主/独立物理检查验证。独立检查不能只重复同一段被测 can_enter 代码，否则两者会共享错误。

有限网格时间、整数 tick 或事件候选不等于完整 native 连续动作域。给出域定义、候选截断、时间舍入、允许循环/等待和窗口尾部。预算耗尽不等于无解；可行 incumbent 不等于最优。受限候选优化的最优值一般不是完整问题的下界；经过证明的松弛下界才可以用于 gap。

保留旧 `total_cost` 参考语义，不追溯否定其允许 backlog 的有限域结果；新增服务合同参考明确全部业务总体和接受/完成要求。必要的不动作不能禁掉，但不服务也不能被记成“服务全部通过”。

### 8.4 Headroom 诊断

在真实运行抽取的状态，区分零候选、单候选、多候选与相同实际动作/不同意图。计入全部机会，不只选有可学差异的状态作分母。

当各候选在同一有限域和共同未来下有可比较成本时，记录：

```text
reference_headroom = J(当前强基线动作) - min J(已验证参考动作)
pool_loss          = min J(部署候选池) - min J(参考动作域)
ranking_loss       = J(实际选择) - min J(部署候选池)
```

参考不完整时这些只是已找到的候选比较，不能据平局宣布全动作域最优。零候选单列，不能套差值公式；截止违约、失败和删失不能塞入一个均值掩盖。

### 8.5 自动诊断分支

| 现象 | 先查什么 | 自动转入 |
|---|---|---|
| 所有方法都失败 | 源语义、物理必要界、任务/盘量、故障与端口权限 | P2 的解释/恢复/合同分组；保留完整负结果 |
| 所有方法几乎平局且约束不活跃 | 盘是否过多、时域是否太短、连接是否被避开、候选是否同一动作 | 合法代表工况与原流中瓶颈切片；不按结果删任务 |
| 参考能改进，但部署池没有好动作 | 局部候选和原子域、时间窗口、线路/服务后继 | 修候选与接口，不增网络深度 |
| 好动作在池中，但排序不准 | 输入是否可观察、标签噪声、近似目标与继续策略 | P5 的评价/结构，随后 P6 |
| 好动作必须越权或知道真实未来 | 新方法信息/权限是否不公平 | 修设计；不可用 oracle 收益支撑在线主张 |
| 强解析追平新方法 | 新方法是否更省计算、覆盖是否相同 | 保留平局；若均无优势，重构具体主机制 |

**完成门 P4：** 具备同模型、同权限强参照和可优化空间解释。不要把 2–3 次小实验作为永远停止某研究的充分证据，也不要在没有任何可辨别信号时烧大规模标签。

## 9. P5：主方法只围绕“循环反馈与边界修复”深入

### 9.1 创新风险必须先承认

本轮重新打开 Parimi & Williams 的 arXiv:2603.28968v1：它已在离线 TAPF-PC 中使用任务后继闭合、冻结外部、边界重规划/重定时和阶段化修复。[W1] 因此，“依赖闭合＋只修局部＋最后整体检查”不能直接作为新主张。

本项目可以研究的差异不是机场名称，而是：在线逐跳导致的非预定后继、固定局部模块决定的用盘次序、共享资源容量/接收回压、JIT owner 权利和跨工序入口尾窗，如何共同决定**可以局部更新的后果边界**。这些差异是否构成新的求解机制，必须由实现、反例和公平适配的基线证明。[D]

### 9.2 单一主候选：由变化量和剩余余量决定修复边界

本节是待检验算法提案，不是已证明定理。[D]

对合法局部动作或区域方案 a，相对强基准 a0 构造：

```text
F(z,a) = (Δ时间化资源占用, Δ条件可用盘释放轮廓,
          Δ既有服务义务, 所需授权和预测依赖版本)
```

实际库存只由物理事件更新；F 中的未来预测不作为可导出盘。快层在原 S4 局部代价上评价动作相关的循环后果；慢层用同一实体账和公开预测选择跨区意图。给同一终点所有候选加同一个区域常数会抵消，必须有时间/资源/动作差异。

#### 修复过程

1. 从真正改变的路线/阶段、入边窗口、接收占用或预测修订启动，不扫描任意地理圆圈。
2. 构造有限时域内的类型化依赖：任务工序、同盘相继服务、资源容量与头距、接收/库位、固定模块加载、源保护和 owner 授权。多盘共享容量或可替代供给是多方关系，不能总用单一前驱边代替。
3. 对边界资源计算可以独立核验的剩余容量/时间余量、已承诺释放界和源服务要求。变化被已证明充分的余量吸收时可暂不扩域；不足或无法证明时扩入相应 owner/任务/资源。
4. 在得到的子问题内修复路线/时间/跨区意图，外部的已接受硬义务冻结。使用 P4 的同一基础模型，不给子问题假空盘或取消他人接收权。
5. 各 owner 按当前版本复验并原子发布必要承诺；候选计算后世界已变则准确失效或局部更新。软预测另行修订，不获得硬许可。
6. 依赖无法闭合或超过在线预算，返回未认证/超时并按安全合同保留旧有效操作或上报；不能丢掉越界依赖仍宣称可行。必要时扩大到全域，最坏情况明确计量。

### 9.3 需要避免的“看起来像证明”

- 边界上当前占用不变，不等于外部控制器未来所有动作不变；外部可能读到了不同队列/预测。性能影响的依赖必须包含策略实际读集，或明确只证明当前既有硬承诺兼容。
- 一阶灵敏度、均值预测、匹配秩保持或松弛 dual price，不自动构成多盘时空可行证书。预测误差只能影响评分/意图，不能生成安全授权。
- 仅使用“如果所有跨边界约束都满足，则拼接可行”是通用正确性论证；主贡献必须进一步给出可计算的充分检查、比通用闭合更有价值的求解过程或有证据的计算优势。
- 最短路或简单 DAG 后继可通过时间展开编码部分循环；不要声称其他方法原则上完全无法表达，只比较表达成本、在线信息和实际修复效率。
- 固定半径、固定 K 和事件标签只是受限域；没有完备性证明时如实报告候选损失。

### 9.4 优先深入的结构目标

只选择一个主结构目标深入，其他正确性作为支撑：

**在固定外部硬义务和有版本 owner 接口下，何种可计算边界条件足以保证局部修复不破坏既有资源/源服务承诺；哪些依赖必须扩域，哪些可由余量隔离？**

推导输入条件、检查算法、复杂度和不成立反例。小域上比较局部与全量同域修复的可行域/最优差距；真实原图上比较触及 owner/资源数量、重算量、服务与 wall/CPU。不得许诺任意故障、未知未来下的全局无死锁或严格逐件不退步。

如果不能得到强定理，保留已证的有限合同性质和限制，但必须由真正的新求解机制及高质量实验证据补足；不能补一个通用 2ε 界冒充主理论，也不能宣称只是实现就足够。

### 9.5 必做反证实验

1. **后继 DAG 不足例：** 不同业务袋没有直接 precedence，却因接收满载→盘释放延迟→另区源保护发生传播；公平适配通用任务闭合，看其是否需要全域或资源扩展。
2. **余量吸收例：** 有依赖但变化不越过可验证余量；比较无差别传递闭合是否多修，验证本方法没有漏硬后果。
3. **共同容量例：** 两个局部修复各自通过、合并冲突；owner 共同复验必须拒绝或联合修复。
4. **跨卸载尾窗例：** 盘已空闲或已服务下一袋，前次入口限制仍有效；新的合法动作域不清尾窗。
5. **不确定未来例：** 当前信息相同，未来供区/受区需求不同；限定保证与不可预测风险，不使用真实未来选动作。
6. **长线反转例：** 预测转向时已有盘在 2km/5km 连接上；不能召回在途实体，接收义务仍有效。
7. **无收益例：** 盘足、无共享瓶颈或强一轮反馈已足够；新方法可持平，额外计算必须算账。

反例采用独立小图做机制验证；完整性能仍用原图和合法业务源。不能把人工有利小图作为主要收益证据。

### 9.6 如果首选机制不成立，自动采用以下有限替代，而非降级

**分支 A：依赖普遍迅速扩到全域。** 保留测得事实。转研究边界响应/容量与源供给包络的压缩近似，以及按事件触发的滚动协调；仍由实际 owner 复验。重点比较同质量下通信/计算、近似造成的保守性与失效。不能把扩域比例藏起来，只报少数局部成功。

**分支 B：普通闭合/一轮反馈已经追平。** 若主问题是有限泊位与长在途导致的接纳阻塞，转研究服务义务保持的时间化接收/联合交接选择与滚动预平衡。完整共享该物理能力，再与常规指派/MPC/通用 LNS 比较新的选择机制。不是仅增加原子事务就算新方法。

**分支 C：低成本解析已与昂贵参考接近。** 暂停残差优越主张，检查需求变化/长线/服务约束下的质量—计算边界和预测价值；只能在有独立的求解或运输决策增量时继续写为研究贡献，不能以“解析已经够好”结束两需求。

每条分支先做明确有预算的机制实验；一次只深入一条替代，不并行堆三套复杂方法。两轮认真重构仍没有可信差异时，输出创新风险和具体选择给用户，同时继续不受影响的两需求、参考和数据工作。不得无限搜索到碰巧显著，也不得独自把项目降为工程验收。

**完成门 P5：** 新机制至少对一个预声明的真实问题维度有可靠方法差异，且强对照排除信息/权限/输入/预算混杂。工程门通过但方法门未通过时，状态必须保持 research_candidate。

## 10. P6：轻量学习有明确对象，不再训练不匹配的旧标签

### 10.1 放行条件

P1 真实 checkpoint/continuation 可用，P3 的两控制层实际运行，P4 明确候选覆盖和可学空间，P5 主机制已可独立关闭/开启。未满足时不大规模训练；允许小批诊断，不允许先生成几十万弱标签再补解释。

模型默认一个共享小模型：线性/小树作为强便宜对照，当前 32–64 隐单元量级的 MLP 作为起点。每次动作只读有权取得的局部/已送达特征。大型 GNN、MARL、多层 agent 或 API 调度不是自动下一步。

### 10.2 标签与继续策略

在真正 G31 宿主的实际待选边界保存状态，替换一次当前动作，后续继续策略、慢层相位、物理合同和外生未来一致。对照动作包含强解析选项和已验证替代；标签去重以真实干预/保留意图为准，不只按 candidate_id。

成对目标可以是 `ΔJ = J(a; 同继续策略) - J(a0; 同继续策略)`；残差再减解析差值。比较 paired-direct 与 residual 使用同输入、架构和成对损失，不能把目标设计差异误作模型容量优势。

共同未来 2/8/32 用于标签排序稳定性与预算分配；保护任务、已观察事件和当前历史不随抽样改写。以真实未来加随机抖动构造的 stress 分布应明确说是压力分布，不冒充校准后的条件预测。随机未来不是新的运营日。

模型训练不读取真实未来，但离线标签可以评估外生未来；要测试同一公开状态的标签方差和不可观测混叠，不能以更多参数强行预测缺失信息。

### 10.3 必须的学习研究

按来源组划分训练/验证/确认；同父航班、派生 2×副本、同 checkpoint 分支不能跨组泄漏。一个运营源派生的所有数据不能冒充跨机场泛化。训练期必要状态回收仅在训练源执行，最多先做两轮有记录回收；改继续策略后重新标注受影响数据。

给出相同来源嵌套样本量曲线、全部预定种子、校准/错误风险、闭环动作改变比例、候选 regret、完整服务和端到端计算。开发期至少多个初始化种子，正式实验固定不少于开发协议承诺的种子数；不能只取最好模型。

比较：强解析、线性/小树、paired-direct、residual、额外预算的公开预测 rollout。公平比较质量—计算；未来真值 oracle 只作离线诊断。模型能改变候选排序或搜索顺序，但不能越过物理/owner/服务检查。

### 10.4 无增益时的决定

- 覆盖不足：回 P4 修候选，停止无意义超参扩大。
- 排序噪声高：改条件采样/时域/标签重复数，必要时保留不确定性；不伪造稳定标签。
- 特征不充分：只增有权限、低代价的消息或特征，并给所有相同信息组的基线；新增通信成本计入。
- 解析误差存在但模型拟合不足：才扩大一个模型或调整成对目标，保留简单基线。
- 充分诊断后仍无增量：保留负结论、样本与计算结果，不宣称学习有效。P5 的非学习方法仍须满足研究质量；不能用学习失败作为删除 R1/R2 的理由。

**完成门 P6：** 得到可解释、同继续策略的学习评价；有作用则晋升一个冻结模型，无作用则明确暂停该主张。学习实验本身不自动弥补主方法创新不足。

## 11. P7：正式规模、实时性、独立确认与写作

### 11.1 实验由研究问题组织，不做无目的笛卡尔积

| 问题 | 固定因素 | 主要变化 | 需要的解释 |
|---|---|---|---|
| R1 是否真正自治且实时 | 同物理/任务/服务合同，预测关闭或固定 | 请求突发、区域数、消息延迟、局部故障、接收回压 | 更新成功率、合法候选覆盖、计算/通信及失败原因 |
| R2 是否提前缓解缺盘且保护正常分拣 | 路由策略固定，模块权限固定 | 预测误差、盘量、长线/多线、需求转向 | 哪些盘由何种已知载盘预测产生意图，何时真实供给兑现 |
| 双向反馈有什么增量 | 同输入、信息与比较预算 | 关闭/开启 C1；单向、一轮、重复反馈 | 改变的动作、释放和资源影响，而非单一总体 J |
| C2 为何值得做 | 同动作/物理/预测域 | 通用闭合、地理邻域、全量修复、新边界算法 | 触及资源/owner、漏依赖、覆盖损失和质量—计算前沿 |
| 学习价值何在 | 同主机制与候选/信息 | 解析、线性/小树、direct/residual、样本量 | 近似误差、闭环收益、计算节省及数据成本 |
| 方法何时失效 | 原始任务全分母 | 物理过载、无回路、信息不充分、严重延迟、满库 | 不可行/超预算/过保守/缺信息分开，保留无收益工况 |

主实验必须包含原图完整 1×/2×任务流；持续压力按原许可生成规则扩到 4×/8×/16×，32×可作为资源允许下的 smoke/边界，不用删任务凑全完成。若已超物理能力，报告容量和积压曲线，不要求假装每档可清空。原长/2km/5km 是连接长度因子；保留共享线和多线，不随意新增捷径。

对同一图的多个来源/合法派生场景做分层抽样和分组冻结，覆盖需求不平衡、回压、Storage、故障和预测变化。主分析不把每个查询当独立样本；总体统计单位至少按独立任务流/源组组织。只有一个运营源时明确单源外推限制，不制造“多运营日”置信度。

先完成机制小图和开发原图，再冻结确认集。某项结果反常可打开分析，但该确认集随后转为开发，新的确认须来自未参与选择的组；不能反复偷看后还叫 holdout。

### 11.2 指标与总体

主表同时给：offered/observed/loaded/completed/on-time 的全链分母；全部未完成/失败/超时/拒绝；最终仍载盘、仍在途、仍占库位和仍有租约。不能把段数当业务袋数。

服务：到达至最终卸载、源等盘、网络/工序时间、截止违约、尾部 P95/P99。未完成不填 0；使用固定观察域的积压面积/受限时间指标和删失说明。不能只比较双方完成子集的均值，除非另作为明确条件分析。

盘与资源：每盘复用次数、实际可用盘曲线、预测误差、空行时间/距离、连接利用率、接收/库位占用与保守预留、源保护拒绝、恢复成功/隔离数量。

计算：每请求全过程、算法 CPU、预处理、优化、owner 复验、序列化/日志和总进程成本；离线数据生成/训练单列。嵌套计时不重复相加，并发 wall 不相加。缓存命中允许省实际计算；公平性同时报告实际时间和逻辑工作，不能把二者混成“等预算”。

不同输入、停止时刻或物理合同的 J 不直接相减。预算删失仍在结果中，不能因为 stop_tick 不同宣称改善。性能与正确性分开计量：无额外日志/有等仪器日志配置的物理结果先做桥接，再报告开销。

### 11.3 100ms 验收的准确对象

定义：

```text
T_compute = 可见状态取得/必要转换 + 候选生成 + 特征/预测查询
            + 评分或优化 + owner 必要复验 + 提交计算
T_response = 请求排队 + T_compute + 通信等待 + 回执/结果确认
```

多 owner 计算的各端耗时、实际关键路径和累计 CPU 分别记录。不能从一条 C++ 事件的 0.x ms、平均网络推理时间或 tiny 总耗时推断完整更新达标。

在两台实际机器上分别给冷/热、不同负载、并发突发、失败/unknown 的 P50/P95/P99/max 与超时比例。原要求的“≤100ms”没有被替换为“P99≤100ms”；若存在超时，只能说哪些域/比例达标，不能写全部请求达标。

设计协作式 deadline、始终保持可用 incumbent 和安全回复；但一次超时返回 rejected 不是更新成功。没有有效旧路线或安全等待条件时，准确报失败/需要更高层处理，不能用假回退遮蔽。

### 11.4 优化顺序：先量瓶颈，再保持语义地改热路径

当前 `node_contract`/`edge_index`/`occupancy`/`can_enter` 有线性扫描，`circulation_progress` 反复扫描排序等待任务及盘，批量预检复制的 `input.jobs/legs/transfers` 会随累计业务增长。在线能力尚未由现有小例证明。[C]

优先用节点/边 ID 索引、按节点库存和等待队列、active leases/edge counts、反向依赖唤醒、持久静态数据与局部差分投射。保证盘在 parked/incoming/remote reception 的去重语义不变；不能靠漏记一个保留提高速度。

完整事件日志不进入热路径全量复制；输出采用有界内存的流式记录和版本化检查点，保留复算所需样本/关键事件。不要通过关掉安全复验、只测热缓存或删失败查询达成100ms。算法与实现加速用独立消融分开。

### 11.5 正式冻结前的内部质量门

冻结前从开发结果确定主指标、服务不可退让项与最小有意义效应，不在看到测试结果后修改。没有业务方阈值时，同时报告多种合理效应阈值敏感性和区间，不设一个任意百分比假装期刊官方标准。

至少满足以下一种方法价值，并同时保留全部硬约束：

- 同信息同计算下，主业务指标有稳定且实际有意义的改善；或
- 服务/质量保持在预声明容差内，计算/通信或可扩展运行域获得清楚优势；或
- 新的可实现决策/保证范围相对强基线扩大，且不是仅给新方法更强权限/物理能力。

实质贡献不可只靠更大样本、更快语言、代理模型更宽松或几个有利种子。各场景允许无收益；恶化尾部和失败全部报告。学习不是必须赢家，整个新方法也不能在没有证据时被标 completed_research。

### 11.6 论文材料与毕业论文章节

边研发边整理问题模型、符号、算法伪码、权限/信息集、复杂度和相关工作，但结果必须从冻结原件生成。建议形成一条章节链：

1. 既有 G31 去中心化逐跳执行与其已完成成果（旧工作，明确分界）；
2. 有限盘循环、区域请求和固定模块下的新问题；
3. 新的循环反馈/边界修复机制与适用性质；
4. 强参考和轻量学习的取舍；
5. 原图运行、质量—计算、服务与失效边界。

统一系统是载体；新章节核心应是新的决策与求解结论，不是接口文档汇编。讨论必须回答：什么时候局部信息足够、何时需要协调；提前调盘如何改善或恶化正常服务；长连接和存储合同如何改变预测价值；方法的计算优势来自何处。题名与主张在机制稳定后再定，不先起一个宏大名称倒逼结果。

## 13. 长期执行规则：减少人工往返，不意味着无限预算或无人负责

### 13.1 可自行决定并继续的事项

在不改变业务/安全/权限合同的前提下：修 bug、加必要回归、实现 session/checkpoint/观测/控制/参考；选择合适数据结构；开发集内调参数；依据诊断增加候选覆盖；选择本文给出的主机制分支；缩减无意义重复实验；推进同模型轻量学习；生成报告与论文草稿。

允许关闭某个可选加速器或旧无效模型进行消融；不能关闭正常分拣保护、屏蔽失败或把 R1/R2 变成空模块。保留足够强的确定性/解析基准，不要求“新东西每次都赢”。

### 13.2 真正必须暂停受影响操作的边界

- 需要新的付费算力/API、公开数据上传、生产设备控制、账号凭据或新增对外授权；
- 需要覆盖用户未提交修改、改历史结果、改变固定地图/原业务任务/现场模块权限；
- 发现物理/授权正确性可能被破坏，必须停止该配置的继续性能计算并修复；
- 原始必需数据或合同缺失，现有来源无法解决：标记该现场结论 blocked，但继续不依赖它的研究代理、算法和参考；
- 主机制和预定替代经充分检验仍没有创新或实际价值，需要用户选择新的研究问题；此时交付证据，不自主降低质量要求。

其他普通失败不等于项目停工。继续下一个不受阻的工作包，并在下一次实质报告集中说明。

### 13.3 资源护栏（本计划的初始运行默认，不是用户硬件事实）

先测一次 CPU 核数、空闲内存、磁盘、编译器、native 单实例峰值 RSS 和吞吐；BLAS/子进程线程避免过度嵌套。电脑保留至少两个逻辑核或25%逻辑核供交互使用（取保留较多者）；服务器按可用配置计算。不是未经允许占满两台机器。

初始并发取 CPU 可用数和 `0.65×可用内存/代表进程峰值RSS` 的较小值，至少一进程；代表实例过小则先用较难实例重测。磁盘保留至少20%空闲；达到护栏时先流式/压缩/清理明确临时文件，不删除失败、原始源或唯一结果。
