# G31：极简无预测空托盘回流基线实施规格

日期：2026-10-20。审阅基点：`1d895da00644c9486568fe74b835e057aa93f8c8`。研究分支：`codex/g31-ics-v3-circulation`。

本文件是下一阶段实施要求，**不是已经实现或已经通过原生实验的结果**。与同目录 `G31_REVIEW_1d895da0_AND_CODEX_NEXT_STAGE_20261020.md` 一起使用。原生底座的共同失唤醒诊断优先于新算法效果比较。

## 1. 决策：补一个 R0，但保留已有强对照

增加独立方法 ID：`R0_current_stock_v1`，中文名称：**当前需求优先、低库存入口回流**。

它只回答：在相同有限托盘与物理系统中，学习/预测方法是否优于一个合理、可解释、几乎没有额外计算的当前状态回流方案。

它不读取航班计划、未来行李、历史需求曲线、B1预测、载货盘未来释放估计，也不调用学习模型、滚动仿真或优化未来成本。静态路网距离、实际已到达需求、当前空盘和已发生承诺的记账属于允许信息。

**不要把已有 C00 改名为 R0，也不要删除 C00/C10/C01/C11。** 固定提交的 C00 使用 `predictive=True` 的底层匹配配置；其“无预测”是没有 B1 航班需求预测，不等于完全不估计已在系统内托盘的未来释放。新增 R0 应显式关闭这部分估计。

## 2. 文献依据与借鉴边界

### 2.1 直接针对行李系统的简单规则

Zeinaly, De Schutter & Hellendoorn (2015), *An Integrated Model Predictive Scheme for Baggage-Handling Systems: Routing, Line Balancing, and Empty-Cart Management*, IEEE TCST 23(4), 1536–1545，DOI：[10.1109/TCST.2014.2363135](https://doi.org/10.1109/TCST.2014.2363135)。[作者公开PDF](https://www.bartdeschutter.org/publications/15-019-integrated-model-predictive-scheme/15-019-integrated-model-predictive-scheme.pdf)，§IV，公开PDF第13–14页。

论文用作对照的既有规则，依据当前行李队列和运输时间分配空车：排队多、运输较快的入口获得更多空车。本规格借鉴其**当前需求驱动的回流思想**，不采用论文提出的MPC。我们的逐盘离散协议、源库存保护与接收许可不同于其流量模型，因此不能声称严格复现该论文算法。

### 2.2 较新的简单规则比较依据

Gan Zou & Houwen Liu (2025), *An adaptive dispatching approach for automated guided vehicles system*, Discover Applied Sciences 7, 1332，DOI：[10.1007/s42452-025-07893-3](https://doi.org/10.1007/s42452-025-07893-3)，§4.1–4.3。[出版社全文](https://link.springer.com/article/10.1007/s42452-025-07893-3)。

该文仍采用最近空闲车辆、等待优先等简单规则作对照，说明此类基线具有解释和比较价值。本文只借鉴这些对照的当前距离/等待原则，不引入作者提出的神经网络与重新指派机制；本项目已接受的运输承诺不可撤销。

**库存最少、固定1盘缓冲、并列顺序等，是本项目明确声明的工程选择；不是上述论文证明最优的参数。** 不因文献较旧而回避直接相关的基础规则，也不把2025年的AGV论文包装为机场ICS实证。

## 3. 为什么不直接“哪儿盘最少就往哪儿送”

最少应指**可用空盘**，不是节点内所有托盘。载货、隔离、在途、被承诺的托盘不能作为可再次派出的空盘。

基本反例：A入口0只空盘但无人排队；B入口1只空盘、已有10件行李排队。仅看空盘数量会把盘送到A，耽误已发生需求。另一个反例是A库存消息缺失：把缺失当0，会吸引多个控制器重复向A发盘。

因此顺序固定为：

1. 当前真实需求服务与共同强制清位；
2. 卸载后空盘的基本回流；
3. 无当前需求时，装载入口之间的可选补缺。

已有强制动作仍按原保护合同保留，不能被第二、三类替换。以上只是普通空盘选择的优先关系，不重排R1载货FIFO，也不撤销已接受动作。

## 4. 精确的信息合同

### 4.1 允许字段

| 字段 | 来源 | 语义 |
|---|---|---|
| 本owner实际空盘 | 当前公开观察的本地 `actual_available` 与托盘实体 | 当前本地可感知；还须排除已承诺、在边上及隔离的托盘 |
| 对端空盘 | 最新合法送达、未过期的 `planning_snapshot` 中 `actual_available` | 对端**捕获时刻**库存，不是当前全局真值 |
| 当前排队 | 已送达真实需求消息/本地真实等待队列 | 只含已进入系统且允许观察的业务；保留FIFO |
| 本方未决请求 | `client_transfer_ledger` 与已送达ACK | 防重复发盘/重复承诺；不是全系统的incoming总量 |
| 角色与距离 | 冻结静态loader目录、正容量可行路网的静态旅行代价 | 用于合法目的地与并列顺序；不拟合动态旅行预测 |
| 接收约束 | 现有receiver资格、容量/reserve、owner/generation合同 | 执行时仍由原生层原子核验 |

禁止通过 `final_result`、offline diagnostics、未来job tape、全局私有session、未送达消息补全R0输入。禁止把远端缺失字段当零。

- `cpp/ics_core/runtime/circulation_planning_snapshot_impl.hpp:127–135`：已有源端实际捕获的库存、occupancy与未表示占用。

- `foundation_airport_protocol_v2.py` / `protocol_control.py` 当前机场路径没有启用这条库存发布/读取，必须显式接线。

第一版优先复用原 `planning_snapshot` v1 的command→源端capture→消息送达→ACK链，不建设新的中央信息服务。保留 `as_of/captured_at/valid_until/source/target/coverage/digest`。

### 4.3 不虚构完整在途库存

当前接口不能一般性给出所有owner已经向某接收点承诺的空盘总数。`occupancy-actual_available` 可能包含载货、隔离、hold或远端预约，不等于incoming空盘。

R0 v1按实际观察库存排序，本方outstanding单独用于防重复分配；字段名称用 `known_own_assignment_coverage`，不要命名为全量 `incoming`。pending不能冒充accepted，已经接收并包含在库存里的同一只盘不能再加一次。

可选回流时，若本方已有未决回流覆盖同一目标，保持重复发送抑制。pending、dispatching、departed等非终态ACK，以及仍未包含在途盘的更新库存快照，都不能解除该抑制。只有原请求到达可公开确认的终态并完成覆盖去重，才重新判断可选补盘。pending虽不是accepted供给，仍必须阻止本方重复承诺。新增真实需求由原匹配扣除已知覆盖后处理；mandatory清位继续走原保护。

若实测重复发送确实构成瓶颈，再扩一个窄版本：由接收owner捕获 `accepted_empty_incoming`，按自身已授予的空接收承诺去重，保持明确的schema与as-of。没有证据前不为R0建设复杂全局库存估计。

## 5. 可直接实现的 v1 规则

### 5.1 先生成实际需求基线

复用 `analytic_control.transfer_candidates`，显式设置：

```python
predictive = False
respect_service_forecasts = False
terminal_clearing = True
```

其实际空盘供给、当前排队覆盖、源FIFO/min-stock、已有承诺去重和基本匹配可以保留。静态路径代价只用于当前可行动作。不要开启未来release候选，再在末端过滤一次后声称整个R0不依赖未来估计。

R0同时关闭基于已发布条件性服务预测的发车错峰。这类soft service window不是原生硬许可；因此各组仍保持相同的源FIFO、接收容量、租约和不可撤承诺，R0则明确使用更少的预测信息。不能把R0与C组之差单独归因于学习。

共同mandatory动作、已经选定用于真实业务需求的分配和R1载货决策原样保留。R0第一版仅给**没有被这些动作分配的实际空盘**增加回流动作。它不是将已承诺的盘改派到另一个入口。

### 5.2 基本卸载回流

对本owner位于非loader、已空闲且无承诺的托盘：

1. 从固定静态角色目录中枚举合法loader；排除自身、不可达、禁止接收及已知不具资格的目的地。
2. 检查该剩余空盘是否还有当前协议允许且可服务的真实需求分配；有则交给实际需求规则，不以库存均衡抢占。没有这类可行动作时，可以普通回流，即使其他节点仍有该盘当前无法服务的等待业务；不得要求全网排队清零。
3. 对未被优先动作分配、且当前没有可服务真实需求的剩余空盘，选择有有效库存观察的目的地，按 `(reported_actual_empty, static_travel_cost, node_id)` 从小到大排序。
4. 若所有远端库存均未知，回退到有合法本地库存的loader；仍无可用库存信息时，使用同一静态合法目录中的最近可达入口完成必要回流，并记 `fallback_reason=inventory_unknown`。这时不得声称选择了全局最低库存。
5. 发出普通真实空盘transfer，`control_reason=ordinary_return_to_loader`。不创建future job，不伪造行李需求，不改真实业务ID集合。

基本卸载回流不要求源端至少2盘：**卸载点1盘→装载口0盘应当允许**，只要满足原生的源/接收合同。否则所谓防抖会让基本循环中断。

### 5.3 无需求时的loader间可选补缺

这是一项小的固定规则，不能干扰上两类动作：

- 目标loader有有效库存观察且空盘数为0；
- 源loader没有未覆盖的当前需求，托盘是原保护认可的实际剩余；
- 扣除已承诺盘、本次其他分配及本地FIFO保留后，发送该盘仍至少保留1只未承诺的实际可用空盘，并继续满足原 `export_min_stock`；
- 本方没有未决动作已经覆盖该目标；
- 目的地并列使用静态距离、node ID；源并列使用源ID、tray ID。

这个固定1盘缓冲仅用于**可选loader间补缺**，不修改native min-stock，不限制真实需求服务或卸载回流。不做1→0的无需求互换；在两个loader只有一只盘时，这可避免简单的往返振荡。

它不能保证异步多owner下不存在所有振荡或重复发送；仍须依靠消息语义、未决抑制和接收原子准入，并如实报告重复拒绝/空走里程。不要编造全局最优或稳定性证明。

### 5.4 选择和执行粒度

必须分两阶段执行。先按原提交循环执行实际需求与mandatory动作，每次submit后刷新current。随后重新生成实际供给基线；只有该fresh基线没有可执行优先intent时，才进入独立的普通回流/可选补缺阶段，并对这个新基线使用单盘 `add_optional`。

固定源码的 `foundation_airport_batch_patch.py:120–121` 会把 `add_optional` 插到批次首位，`foundation_airport_protocol_v2.py:154–163` 每次只提交首项再重算。不能仅声称“其他intent还在列表”就认为优先级已保留，也不能只append到批次尾部而任其在残余重算时丢失。必须实现上述后置阶段；原提交循环因错误中止时不得绕过错误继续发回流。

每个 `(owner, next_tick)` 最多新增一次回流，在残余重算间保留这个计数，不能每次重算都重新获得一次额度。在线候选沿用共同上限K；P只约束离线成对原生续行预算，不作为实时submit次数门禁。

此一次额度针对新增的库存回流阶段，不削减原实际业务匹配的提交数。新比较若给C组也开放该新增回流阶段，须提供相同额度；各方法已有业务调配/替换动作的边界另行明列。R0优先服务当前需求是它的策略定义，不能据其与C11的差异单独归因RL。

每次submit后使用新current重新核对剩余动作。原request身份、owner、generation、departure lease、receiver reserve、ACK、唯一实体首边与恢复全部沿用。库存快照只决定偏好，不能授权实际不存在的盘或预占未接受的容量。

触发使用当前已冻结的R2节拍及已有事件路径；不按每个底层路由事件调用预测。新规则默认复用现有60秒控制tick，属于当前工程配置，不是文献推荐周期。后续若改为事件触发，所有对比组使用相同新合同并重新冻结。

## 7. 必须通过的语义门禁

| 反例 | 预期结果 |
|---|---|
| 卸载点1空盘，loader0盘，无未来业务 | 能走普通回流，不受可选均衡阈值阻挡 |
| loader A1/B0，无需求 | 不无限进行1↔0互换 |
| 同样A1/B0，但B已有真实公开需求 | 按原当前需求规则服务，不被可选均衡阈值阻挡 |
| A0但无需求，B1且10件排队 | 真实需求优先，不能仅按最少库存把额外供给全部送A |
| 对端库存缺失/过期，新revision过期而旧revision曾有效 | unknown，不能置0，也不能复活旧库存 |
| 对端库存变化，但消息尚未送达 | actor结果不能提前体现新库存；执行时receiver可以拒绝过期方案 |
| 同一盘经历pending→accepted→received | 不能重复当成库存或可再次派出的供给 |
| 同一请求重试、两个owner竞争同一接收余量 | 保持幂等、原子准入与唯一实体链；不撤旧承诺 |
| 修改未来航班/私有未来job，当前合法视图完全相同 | R0动作字节一致，证明不依赖未来输入 |
| 当前源有FIFO业务或盘已在途/隔离 | 不能借“库存均衡”导出保护外的盘 |
| 同一回调有mandatory、真实需求分配与剩余空盘 | 优先动作先提交；fresh residual全过程至多新增一次回流，错误中止不能绕过 |

纯函数反例用定向测试。涉及送达、过期、并发、ACK和实体的少数反例用native门禁，不为简单排序增加大量镜像测试。

## 8. 比较矩阵与解释

| 方法 | 空盘/当前业务 | 航班需求预测B1 | 学习排序 | 回答的问题 |
|---|---|---|---|---|
| R0 | 实际空盘、已送达当前状态；无未来release估计 | 无 | 无 | 复杂方法是否超过朴素但合理的回流 |
| C00 | 现有规则信息，包括已声明的内部释放估计 | 无 | 无 | 现有规则底座表现 |
| C10 | 与C11相同允许信息和冻结B1 | 有 | 无 | 同信息强规则表现 |
| C01 | 与C11同候选/保护，移除航班预测后独立训练 | 无 | 有 | 不用航班计划的学习表现 |
| C11 | 同域、同预算、同冻结B1 | 有 | 有 | 航班条件学习表现 |

R0是额外低信息基线；C11−R0不能单独归因为RL，因为两者同时改变信息与控制规则。学习增量看C11−C10与C01−C00；航班增量看C11−C01和C10−C00，并同时报告交互项。

所有新比较采用同一共同底座修复、恢复机制、图、业务、盘数、初始布局、公开消息时延、在线候选上限K、控制节拍和窗口；需要成对评估时采用同一预登记P预算。新库存消息向所有组提供相同合法接入，不给R0偷偷开一个全局传感器。改变信息合同后重新冻结，旧34支结果保留原定义。

报告至少包括：全人口积压积分J、完成/准时/到期未完成、精确与右删失延误方向、最长无实体进展区间、隔离盘秒、空走距离、动作/拒绝/重试、完整回调时延。不要仅报已完成件平均等待。

**规则在行李到达前把空盘放回入口，也是一种提前放置。** 所以“发生了提前移动”不能作为预测或RL独有收益；新方法必须超过这样的普通回流才有说服力。

本基线的目的，是确定更高级方法究竟解决了什么问题；不要刻意削弱它，也不要为了让学习胜出而挑选盘数或只发布有利父场景。
