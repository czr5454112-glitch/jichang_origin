# G31 × ICS V3 创新证据账：首版与后续更新模板

日期：2026-10-11。用途是持续判断方法是否仍有可辨认增量，不用作投稿承诺，也不以增加文档数量代替研究。

## 1. 当前判断

**当前没有足够证据把拟议 G31-V3 联合方法标为“创新已成立”。** 已有 G31 成果保留；V3 原型提供了可复用的物理、权限、参考与学习诊断。接下来必须形成同一执行系统上的新决策/求解机制并取得强同信息对照证据。

“已有邻近工作”不等于不能继续做；它排除的是宽泛首创表述，并要求差异更具体。不因初期收益不明显降低两需求或TRE/CIE目标，也不把尚未证明的差异包装成已证创新。

## 3. 门禁更新规则

在首次统一闭环、主算法变更、大规模训练前、W4冻结前各更新一次；出现强新近邻或失败反例时立即重审相关claim。无需每个小重构都写长综述。

每个claim用以下格式更新：

```text
claim_id:
一句话机制（不是形容词）:
本次实际新增控制变量/信息/求解步骤:
原G31已有内容:
最近邻论文及读取版本/章节:
原文中已覆盖哪些点:
尚未确认的全文/假设:
代码位置与运行配置:
正例、无收益例、失败例:
同输入同权限同预算的强基线:
动作变化/覆盖损失/排序损失/周期服务与计算结果:
是否因改变任务/模型/保护/信息权限而获益:
可证伪差异:
当前状态: engineering_only | hypothesis | supported_in_declared_domain | contradicted
下一阶段: go | refine_mechanism | stop_this_claim
停止本claim后如何保持两需求与研究质量:
```

“supported_in_declared_domain”只表示限定域中有支持，不等于世界首次或期刊会接收。发现近邻覆盖某机制时，要调整具体方法/主张，不把该近邻故意设成弱基线；基础物理/权限要公平，拟议核心算法仅在增强消融时共享。

## 5. 第一轮最有价值的反证测试

**常数修正反例。** 相同bag终点的所有候选加相同区域价值不能改变排序；若学习收益只存在于训练指标而没有实际动作变化，暂停该对象。

**非闭合依赖反例。** 局部路径改动导致下游满缓冲、某盘释放延迟，再影响另一owner源保护；只按地理邻域修复会漏掉传播。必须扩大时间化依赖或明确unknown。

**单向信息已足够反例。** 强解析/一轮反馈在同输入下追平完整新方法；不能靠增加无效层次宣称创新。分析是否还有可测计算节省、边界更清楚的修复机制，否则重选主机制。

**源需求不可区分反例。** 当前公开信息相同，未来分别在供区/受区突发需求，导出最后一盘不可能同时对两种未来零代价。由此约束保证的假设，不允许事后删保护任务。

**充分盘量/无共享瓶颈反例。** 应允许新协调没有收益；若仍报告显著“普遍提升”，优先查计量、不同输入与额外权限。

这些是待在新G31宿主实施的研究反例，不能与本轮已运行的N1–N3错误地合计成“全部验证通过”。
