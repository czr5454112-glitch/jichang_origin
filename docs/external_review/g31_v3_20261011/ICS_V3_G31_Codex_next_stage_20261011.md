## 3. 立即完成的三项定点修复

### A. 旧整数参考拒绝或正确建模 Storage

`routing_reference.py`中的`FullGraphReferenceGenerator`接受Storage，却用不含阶段的`(node,tick)`标签，并给错误最早标志。本轮反例：

```text
S-A=1, S-W=1, A-X=1, W-X=1, X-G=1, W-G=4
W必须经过，release=0；单盘；H=6、K=1、work=200000、无wall截止。
返回S-W-G到达5，earliest_arrival_certified=True；
S-W-X-G到达3、卸载4的手工见证通过同一validator。
```

最小正确修复：对旧参考显式拒绝不支持的Storage，保证消费者不会继承错误证书。后续真正支持时用阶段积状态，头距接入后纳入自身尾窗；不是加K修复。保留现有独立Storage测试oracle，它已经有passed状态，不要误删。

### B. 普通screen默认K对齐

`TerminalScreenGenerator.generate`默认4，原Regional默认3；Storage subclass已是3。修普通wrapper，比较完整有序候选，不只首选；显式K、ordinary/storage/empty、冷/热、耗尽/无证书回退都保留。

### C. 普通screen factory检查点隔离

普通factory持可变accounting；`Simulation.checkpoint`复制generator但共用factory，检查点保存后原factory调用会把其账本从(0,0)改成(0,1)。优先纯factory＋显式本次账本汇集；或正确复制完整对象图。测试必须走真实Simulation.checkpoint/fork，不只deepcopy两个对象的tuple。

执行外部`reproduce_audit_probes.py`，默认exit0仅表示探针运行；修复验收用`--require-fixed`，并人工检查拒绝原因属于正确能力边界。原1519保持，新增反例归入针对性回归；不覆盖旧失败目录。

## 4. 首个实质交付：G31-host 有限盘闭环，不是接口空壳

首选成熟G31 native事件内核作为唯一物理宿主。明确`legacy_g31`与`circulation`两个模式，保护原实验同时定义新物理。不要同时让Python Simulation与C++各自推进不同的队列/托盘日历。

实现以下最小垂直切片：

1. 持久`tray_id`与`business_bag_id/transport_leg_id/traversal_id`分离；source装袋必须使用真实可用盘，完成袋不删除盘。
2. 迁入真实Storage阶段、卸载/hold、终点库存与合法离开。早包原多段身份保留，第二段不从预定时刻凭空生成。off-carrier是另一明确合同，不作为默认快捷修补。
3. G31真实逐跳动作驱动这套生命周期；不是从另一个仿真器结果搬运一份最终时间。返回empty任务仍是同一盘运动，不是新增无限盘。
4. 固定区内模块port，允许查询/导出/接收/拒绝，不打开模块内部动作权给中央算法。
5. 一只盘实际服务第一袋→卸载和hold→真实跨区返回→服务第二袋；另有接收满拒绝、无收益和失败变体。
6. 同图小域独立参考或可行见证，提供每件袋、每只盘、每个实际入边与服务事件账。未做精确求解则明确未知，不能凭运行结束称可行最优。

`legacy_g31`模式先在小例及既有代表任务入口保持原动作/服务语义；`circulation`新增资源约束可合法改变行为，必须对所有新比较方法一致，不能把模型变化算算法提升。

第一包允许关闭screen与learning，以避免无关耦合；不允许把no-op slow callback当真实预平衡。此包是实质接入起点，不是全研究完成；随后必须进入区域与预测两个需求。

## 5. 统一资源、区域权限与按需接口

- 一个ClockSpec：不把G31的毫秒服务变成V3一秒整数tick，也不为精度把完整天仿真改成逐毫秒循环。
- 区分边在途容量、入口间隔、junction服务、接收缓冲与库位；G31旧local_queue_capacity=0不证明现场无限容量。
- entry按traversal区分；已离边/卸载不清除未过期头距；重复/迟到消息不复活过期承诺，不把同盘重入合并漏冲突。
- `RouteIntent`是意图，`ReleaseForecast`是条件预测，`OwnerGrant`才是硬资源权利，`ExecutionReceipt`确认真实发生。禁止全路硬锁后让G31自行改向。
- planner只接本地＋已送达远端摘要；实时时钟在通信期间继续推进。旧全局arbiter可以作为明确物理参考，但不能把其全局搜索能力传给局部策略。
- protected新后缀权限是扩展合同，旧禁止保留；保持deadline/存储/不可撤前缀及别的任务权利。旧路已因故障失效不得计作有效回退。
- A*编解码要处理原路线/后缀/事件版本，不能只返回一串节点。必须支持按需请求，不把快层更新强制等慢层周期。
- checkpoint一起保存native事件/仲裁代际、身份、尾窗、消息、owner、慢层相位、cache和cursor；外生未来保留在环境侧，不进入policy。

## 6. 主方法：循环释放反馈与受影响依赖修复

在共同物理稳定后，实现一个实际可检验的求解增量，而不是继续堆模块。

以当前合法下一跳导致的`Δ可用盘释放时间轮廓`、`Δ共享资源占用`、`Δ正常服务后果`作为循环影响表示。快速层在S4原成本上增加动作相关的循环边际价值；慢层在同一有限实体账上滚动跨区调拨。载盘路线改变供盘预测，调拨占用又反馈给路由，形成双向闭环。

不能给同一最终区域的每条路径加相同常数价值——那会全部抵消，根本不改变动作。不要把未来预期盘当当前可导出的空盘。

从改变的时间化资源和供应义务构建受影响依赖子问题，含回压、存储、接收、源保护与盘复用。依赖未闭合则扩展范围/unknown，不按任意地理半径宣称局部完整；最坏全局必须报告。与全量同域修复、当前强解析、一轮反馈、同信息滚动约束优化比较。松弛对偶/受限master界须说明适用域。

优先研究这条修复机制的可行域与计算—质量边界。若方法仅剩现成MPC拼接，应重构主机制，不能靠测试规模、哈希或“机场场景”声称创新。
