## 1. 不可降低的研究目标

### 1.1 两项需求分别成立，然后验证真正的双向联合

**R1：区域按需自主路由。** 不依靠跨区调盘也能工作；在合法局部观测和实际收到的消息下，对未承诺的合法后缀提出快速更新，处理拥堵与故障，保留系统 A* 路线／版本编解码和处理结果上报。G31 继续执行逐跳 S4、资源仲裁与原有安全保底。论文须说明实际决策主体是节点／区域 owner，以及消息范围；单进程模拟多个 owner 不等于完成了物理分布式部署。

**R2：载盘驱动的有限空盘预测与预平衡。** 从当前载盘路线、目的地、装卸／Storage 阶段和已送达信息推断未来可用空盘，决定跨区源、目的区、连接线、数量及出发窗口。区内模块和接收／导出权限保持，已进入长连接的实体不能撤回或瞬移。

**联合目标。** 必须出现并验证“R1 改变卸载／空盘释放 → R2 改变真实跨区占用和未来供给 → R1 再响应”的双向关系。两个开关同时为 true、两套模块依次调用或 event_joint 命名，不是联合求解的证据。

## 3. 首批必须处理的三个接入点

### 3.1 C1：合法 owner 观测与 P5 有限域的接口不能直接混用

当前 `observe_protocol_impl` 主动去掉 `version`，原因是旧值包含未收到 ACK 的处理痕迹，可能泄露不允许的状态。`p5_handoff.build_domain` 却用 `observation['version']` 构造请求及 read-set。本轮纯 Python 探针中，原 P5 测试投影能构造域，删除该字段后会出现 `KeyError('version')`。[A1]

这是**旧有限域接口到新协议控制器的接入缺口**，不是证明已声明的旧有限域实验造假，也不是 native 物理崩溃。不得通过恢复全局／真值版本或改用 offline observation 来“修好”。

实现 `LocalContextToken` 或等价明确类型：静态合同哈希、owner 本地可观察 stage／tray generation／traversal、该客户端收到的 ACK／公告序号及必要局部读集。区分“请求身份”“决策依据身份”“接收端当前可执行性”；后者必须在实际送达时由有权限的 owner 复验。新 token 不得因远区未送达事件变化。测试隐藏远区状态变化时本地投影／token 不变，真实合法通知后才变化。

更新 P5 请求构造与协议适配层，保留旧实验的只读兼容入口和版本，不偷偷改历史原件。新候选缺少真实跨区服务合同则返回 unknown 并请求必要消息；不补齐远端私有字段。

### 3.2 C2：补齐公告／撤销／租约／重试的事件生命周期

同 stage 的成功预测当前不会仅因时间推进而再次发布；`_retry_time` 仅索引非终态 outbox。本轮 mock-client 探针确认：首次发布 1 条，保持同 stage、时间推到 1000 后新增 0 条；仅包含终态拒绝、`next_retry=5` 的 outbox 返回无限定时点。该探针说明索引范围，不说明所有 native 场景必然死锁。[A1]

建立按 owner 的合法公开定时队列：首次发布、有效期／估计变化触发的刷新、到期撤销、撤销失败后重试、终态拒绝 cooldown、路线 lease 及路由变更。重试周期、有效期和 cooldown 的语义分别定义，不复用同一数字遮蔽问题。定时只能来自本地已知合同／真实送达信息，不读取未来物理事件堆。

避免每个细小时间步群发。采用明确最大有效期＋有意义变化阈值＋合并 pending 意图；消息噪声／丢失下测流量和有效性。checkpoint 保存定时堆、去重 generation、未结束 owner 轮次、通知游标；恢复后不得重复执行已承诺动作。同一真实时间戳完全排空再决策，保留严格 double 顺序，不重新引入 epsilon 排序。

### 3.3 C3：计时与活跃索引并行推进，但不取代方法研究

`observe_protocol_impl` 仍遍历历史请求／命令，部分取消查询遍历命令；客户端反复扫描 outbox 和预测历史。这是源码可见的增长风险，不等于已证明 199ms 尾部全由这些操作造成。先做真实请求剖析，再优化同 activation 内只读观察复用、活动 outbox／取消状态／有效预测索引及等价增量序列化。

完整历史仍可审计和恢复，不能删除 ACK 或老请求来制造速度优势。每次优化需证明投影内容、顺序、字典隔离、pending／timeout／duplicate／restore 行为等价；当 owner 的合法状态改变时缓存必须失效。

## 5. W1：两需求可真正在线运行的最低合同

### 5.1 不再让 R1 只靠配置开关存在

为原图建立单独版本化的 `research_r1_authorized` 合同档。它依据原 R1 需求，明确允许相应任务在合法接口更新**未承诺后缀**；不改目的地、已执行前缀、Storage 必需工序、实体所在位置或容量。冻结的 original24 老档完全保留。所有同组方法拥有相同基本权限。

明确 `request → observe → proposal → source/receiver validation → commit/reject → delivered ACK` 的链，验证新路线确实改变某个后续真实逐跳动作，而不只是生成了一段不同字符串。分别保留新路线成功、合法旧路线继续、无替代路、搜索预算耗尽、证实不可行、故障通知未到、通信失败、到达后失效、提交失败、unknown。已被故障破坏的旧路线不是有效回退。

若原图某 OD 只有唯一合法后缀，这一任务记“无路由选择”，而非算法失败或移除任务。为机制研究按静态拓扑和预先规则选择真正有替代路的 OD／时段，并同时报告选择比例；正式全流仍保留所有任务。

### 5.2 服务预测采用可执行的条件，而非一对永远有效的时间点

至少区分：当前合法观测、条件估计、已接收但未授权的请求、已承诺资源占用、已进入长连接的不可撤销在途。预测消息不能直接授予出口权限或预定不存在的盘。

跨 owner 新消息只传需求所必需的摘要：任务／服务身份、适用路线或条件、可能释放区／时间信息、所依赖消息序号、有效期／撤销方式、接收条件和源保留限制。私有内部队列可以由该 owner 本地计算摘要；其他 owner 不得直接读它。若声明区间代表“任一点均可行”，必须有证明；否则标为范围估计／离散候选，不能把点集凸包当可执行时间窗。

预测验收不仅看 MAE。统计在真正调度决策期限前到达的比例、相对实际释放的提前量、信息年龄、过期误用、撤销延迟、拒绝率和每个有用动作的消息量。入边后仍可能对下游有效，必须用消息消融验证。

### 5.3 完成标志

原图至少形成一个真实 R1 改路见证和一个 R2 提前预平衡见证；另有跨 owner 场景中两者互相影响的真实事件链。它们仅是接入门，不是统计收益或创新门。新增定时、token 和消息协议的延迟／丢失／重复／重放／恢复回归通过后，直接进入 W2/W3，不等待人工“继续”。

## 6. W2/W3：先找到真实耦合，而非继续在饱和小域上训练

### 6.1 按因果条件设计，不按正收益筛选

第一批预声明 8—12 类机制情形，再从原图事前筛出 32—64 个开发上下文作为初始研发规模。数字是可调整计算预算，不是样本量充分性证明，也不强迫构造不存在的场景。每个上下文记录来源任务族／时段、筛选依据和全部排除原因。

需要覆盖：载盘存在至少两条合法后缀并改变释放时机；两个以上调盘方案争用真实节点／边／headway／接收位；Storage 释放门会吸收或放大到达差异；源保留量使部分出口不可用；长连接多线占用反馈；同盘连续复用两次以上；消息延迟／预测反转／接收回压。盘充足、没有共享瓶颈、无替代路径、强基线已饱和等无收益场景同样保留。

正常主实验使用未修改的真实拓扑；获许可的连接线长度敏感性单列原值、2km、5km，不改方向／连通性。若原图无法提供某种机制，仅在明确标为合成的单元组中展示其原理，不冒充原图证据。

### 6.2 必须同时排查六类“没有收益”

分别诊断物理／权限不可行、候选域不足、信息没有提前或不合法、继续策略不一致、目标／保护口径错误、强基线确实饱和。不能把这六类统一解释成“learning 不适合”。保留 unknown：超时、没有兑现全部请求、候选域只跑了前缀，不等于无可行解或零 headroom。

可以在同一 frozen native checkpoint、相同合法信息、相同外生事件和明确相同继续策略下测二阶交互：

`κ(i,j) = J(ai,aj) − J(ai,a0j) − J(a0i,aj) + J(a0i,a0j)`。

只有四个分支都达到相同完成／删失合同，且动作可执行时，数值才可比较。非零 κ 说明简单可分加和不够，**不证明新算法有创新**。两两检测也不足以排除多方容量耦合；另测至少一个多候选同时超容量的高阶例子。

### 6.3 强基线阶梯，公平分清三类比较

| 参考 | 用途和最低要求 |
|---|---|
| B0 同 G31 反应式跨区调盘 | 保持现有区内模块、盘数、权限和全任务；不是用原始无限盘结果做唯一对手 |
| B1 载盘预测＋强服务完成费用匹配 | 保留必要 WAIT／合法窗口／源保留，不只按空盘 ETA 排序 |
| B2 强匹配＋持续滚动反馈 | 同样拿到合法通知、刷新／取消和反馈时点，防止把多轮控制当独有优势 |
| B3 同模型联合滚动 MPC 适配 | 参考联合路由／空盘管理思想，候选落到真实 native 资源和业务约束；说明时间离散和模型差异，不冒称逐行忠实复现 |
| B4 通用资源感知 LNS／闭合／重定时 | 给足相同基础候选、公共资源合同和预算；不拿没有跨候选资源检查的弱版本充数 |
| B5 小域枚举／精确参考与必要界 | 同 native fork、真实继续策略和保护合同，明确有限域／全局／预算 unknown；用于候选覆盖和上限分析 |

区分 **同信息同预算的算法比较**、**更多信息／更长预算的参考上限**、**端到端系统比较**。特有求解核心不要求免费复制给基线，但合法基本动作、物理权限、已公开输入和基础约束检查必须公平。离线真值参考不能作为在线模型可调用接口。

B3/B4 不必在第一周完成全面工程优化；先实现最小正确、可执行版本并列出适配差异，再扩大。不要花数周追求精确复刻不兼容场景而完全暂停主方法。

### 6.4 原始物理合同与全流阻塞

建立 `PHYSICAL_SEMANTICS_LEDGER`：零容量边、EBS 是否载盘存储、装卸／hold 时长、实体接收位、同区模块行为、盘初始位置和源保留量分别标注原始字段／明确需求／研究代理／未确认。不得把原需求的“约 3000 件/小时”等举例值直接变成地图校准真值。

现有 `0/57012` 保守代理历史结果保留。判断是源流超过能力、闭边造成不可达、盘循环断裂、FIFO／存储回压还是程序问题，输出可复核的阻塞链／必要界。未知物理语义不能自动设 0→1、增盘或改成离盘存储；可以在独立版本的研究代理中做敏感性分析，但不覆盖主档或宣称现场已确认。

确实依赖合作方答复的合同项集中写一次问题清单。只把相关“现场物理结论”置为 blocked_external；可合法执行的接口、候选、解析方法、强基线和研究代理实验继续，不无限等待。

## 7. W4：主方法研究——动作条件化的有限盘复用链与局部联合求解

### 7.1 明确研究对象，不先给一个漂亮新名字

推荐主线：**在有限盘连续复用和跨 owner 资源权限下，对“载盘后缀—空盘释放—跨区连接占用—下一次装载”形成的短复用链做动作条件化建模，再在可验证边界内联合调整路线与调盘。** 这是一项待验证研究假设，不是本轮已证明的创新。

不是把已经选好的载盘路线算出一个固定 ETA，再给空盘做独立匹配。一个候选至少包含合法载盘后缀选择、该选择导致的可释放条件、跨区空盘服务对象／路径／出发窗口，以及对共享资源和下一次用盘的影响。就地 WAIT／维持已验证 incumbent 必须存在；不可撤销实体只作为固定约束。

在线初始规模建议每个关键请求 2—4 条合法后缀、一个小规模关联任务邻域、有限复用深度；具体上限由 CPU 剖析决定，并报告候选截断的损失。**限制求解邻域可以，删除系统业务不能。** 不要求一开始实现大 GNN、端到端多智能体 RL 或全网超大 MILP。

### 7.2 数据结构和执行链

先统一四类内部对象，命名可以调整但语义必须写清：

1. `LegalContext`：只含 owner 合法可见信息及 C1 token，不含全局真值版本。
2. `ReuseChainCandidate`：关联载盘动作、释放条件、空盘调拨、下一服务及资源足迹；记录假设／未知。
3. `BoundaryContract`：不可修改的已承诺在途、外部任务衔接、源保留、接收义务、消息依据及有效期。
4. `JointProposal`：关联的 route／transfer／cancel 意图、依赖顺序、过期后回退及源／接收复验结果。

候选生成 → 便宜可行性／必要界筛选 → 条件资源冲突检测 → 有预算的联合选择／修复 → native 权限复验与提交。多个 owner 的异步动作不能假装瞬时全局原子提交；采用明确的条件请求／准备／承诺／撤销语义，真实承诺前可取消，承诺后按物理执行。每个外部通知都经过原通信链。

### 7.3 真正需要攻克的机制，而非重复 LNS 术语

已有方法已包含服务费用匹配、重指派、低余量种子、后继闭合、外部冻结和重定时。[L2][L3] 只实现这些不自动构成新贡献。

本项目要具体检验：能否用有限盘复用链的**动作条件化释放／接收边界**识别哪些下游必须联动、哪些外部承诺可以保持，从而避免“全网重算”或“局部修复破坏后续用盘”二选一。资源耦合不只沿静态任务先后传播，还会通过空盘身份复用、Storage 门、接收位和长连接产生新的依赖。

优先开发一种主求解器，不同时堆很多启发式。可以用受限候选组合／冲突驱动修复做第一版；复杂联合优化器用于小域参考。基于某次消息上下文产生的不可行组合／冲突约束只能在该上下文适用，不能缓存成永远有效的全局禁忌。

### 7.4 理论／结构工作单独验收

先正式写出“保持外部承诺的局部替换”命题及全部前提：同盘先后衔接、装卸与 Storage 约束、节点／边／headway 容量、边界状态、已承诺外部服务、真实 owner 授权和延迟变化。证明局部替换与冻结外部组合后可执行；随后寻找让命题失败的最小反例，如接收位提前占用、第三条复用链、长线不可逆在途、过期公告。

**仅有上述组合可行性命题仍主要是基础保障。** 研究性目标是进一步给出可计算的边界选择／扩张判据、保守程度分析，或相对某个明确定义的强参考的质量—计算界／结构条件，并用同 native 反例验证。若得不到一般性界，明确收缩定理适用条件，不能凭试验无冲突声称全局完备／最优／无死锁。

公开条件估计不得当成硬预留。只有经过证明的保守服务保证或已承诺资源可进入硬可行性结论。对未出现的任意未来需求，不能凭有限窗口证明所有业务永远不退化；理论前提需要明确，**正式实证仍统计全体 offered，不能借此缩小正常业务保护分母**。

### 7.5 连续推进中的两条替代路线

若新真耦合域仍被强匹配解释，先核查是否仅改变了单候选费用；补充共享容量／多次盘复用／合法跨 owner 相互制约，不重复搜索同八域。若拓扑与权限决定根本没有相关选择，记录适用范围，转向其他事前合法上下文，不改图造收益。

若依赖闭合频繁扩展到全网，研究条件边界摘要／分区协调，比较质量、搜索量和通信量；不能无证明截断后继续声称全体保护。若强 MPC/LNS 在质量上打平，允许以**新的求解机制实现稳定的预算内质量／计算优势**作为候选贡献，但普通缓存优化本身不能替代核心方法创新。

最多连续两轮没有支持的机制改造后，必须提交结构性负结果、最近邻差异和下一假设；暂停该假设的盲目扫参，不暂停整个 R1/R2 任务，不自动降低期刊目标。研究结论可以否定某机制，不能伪造成功。

## 8. W5：轻量学习，学习对象是难以快速计算的动作后果

### 8.1 放行规则避免两种极端

不能直接复用不匹配新合同／继续策略的 V3 标签；也不要求“解析版先击败所有无预算精确参考”才允许学习，否则无法研究学习加速。小规模 pilot 的前提是：合法输入与 token 已闭合；候选能真实执行；同 native 标签一致；存在可改进的候选选择、误差或昂贵强参考可蒸馏的计算余量。主方法至少已形成可检验、可消融的具体算法假设。

大规模训练另需：pilot 有有效覆盖、拆分无泄露、标签质量／unknown 处理过关。门没有通过就继续前置任务，不用扩大数据量掩盖原因。

### 8.2 第一版只比较小模型和明确残差

优先预测解析模型难以包含的局部排队／相互干扰／复用链终端代价，或在相同预算内排序联合候选。解析＋残差是一个可检验设计，不是默认优于直接回归。至少比较：纯解析、线性／小树、同输入的小网络直接预测、解析＋残差；模型容量、调参预算和输入域公平。

只有一台 RTX 4070 电脑与一台 RTX 5080 服务器这一保守资源预算；先读取实际 CPU、内存、GPU 型号与可用状态，不假定它们都可远程使用。大部分 native 标签生成是 CPU 工作，优先减少重复 fork／昂贵继续，而非追求百万级训练行。运行时不调用外部模型 API。

### 8.3 标签、切分和选择指标

每个标签绑定源任务族、拓扑／合同档、合法观测、候选、native SHA、控制器继续策略、全部外生事件、预算及业务分母。不能把真实将来的到达／私有全局状态放入特征。native fork 只用于离线教师或明确预算内的在线搜索，不能把离线全部未来视为合法在线输入。

同母任务的倍流副本、相邻 checkpoint、同一原生日的切片和同一因果 rollout 属于同组，不能随机拆行造成泄露。训练／开发／确认按源族与运行组隔离；只有一个 legacy 模拟日时明确只有一个源日，不能制造独立运营日数量。

保留失败、未兑现、超时和删失，标签状态要显式化。不拿未完成任务的截断时间伪装完成成本；不用删除失败候选提高分类准确率。

验收看真实选择后相对解析及强参考的业务结果、保护、耗时与风险；不以 MSE／top-1 单独放行。学习关闭时系统仍正确运行。若学习无独立价值，保留真实消融和失败分析，继续研究机制／计算对象，不默认换更大网络。

## 9. W6：完整 100ms、真实继续和长期实验运行

### 9.1 定义计时口径，禁止暗中摊薄

以业务 `request_id` 和因果父链建立 span。至少记录：请求读取／合法观察、特征与预测、候选生成、求解、源端及接收端实际复验、提交、ACK 处理的计算时间；另列排队、消息传输／等待和端到端完成。区分物理仿真推进开销与控制器计算，但不能把实际必须执行的权限复验藏进“仿真”后删去。

嵌套 span 用 exclusive 时间避免重复计费。批处理共享开销明确分配或采取保守归属；不得把一次慢 activation 除以许多任务后宣称全部小于 100ms。分别报告请求总计算与最大连续服务段，公开失败／重复／超时请求分母。

≤100ms 是声明规模、负载、硬件和实现域内的完整计算要求，不是 P99、平均值或神经网络前向。为提交／复验预留预算，提前返回仍合法的 incumbent；任何实际超限仍算超限。普通操作系统测得有限样本全部通过不等于所有未来情况下的硬实时证明。

### 9.2 性能工作有止损边界

先按调用栈定位观察、索引、序列化、候选、求解的比例；优先优化活跃工作集而非历史总长度。增量 API 必须能重建与旧全量相同的合法投影，历史归档与活动态分离，恢复／sibling fork／可变 dict 隔离继续验证。没有源变化不重复跑同一已通过测试；有协议／物理变化则跑受影响回归及冻结里程碑全集。

性能报告区分同机受控对照与跨运行描述值。保留作者 015 并发编译导致旧速度比较混杂的事实；不把它变成确定加速倍数。

### 9.3 持续运行与跨进程恢复

现有能力是 native 进程内 checkpoint 加控制器 JSON 的配对继续。先让 runner 在独立会话／进程退出时有明确心跳、run manifest、子进程硬超时、原始输出原子落盘与退出码，保证重启后知道哪些 shard 完成、哪些是截断。

若要声称跨进程恢复，必须实现并验证 native 物理状态的序列化／校验／版本守卫，以及与控制器、随机流、定时队列的原子配对；新进程加载后与连续运行比较全部业务和事件。不能只存 Python JSON 或新开一份物理世界继续。

跨进程持久化未完成时可采用已知完整 checkpoint 起点的独立短 shard 和可重复重建，明确重算损失。它不阻止小域方法研究，但不能用于宣称全天中断任意恢复。

### 9.4 两台机器的负载矩阵

在确实可用的 4070 电脑、5080 服务器上记录 CPU／内存／操作系统／编译器／电源模式和并发负载，分别跑冷启动、热缓存、批量到达、故障触发密集更新、长历史运行。未取得机器访问或某档未跑就明确缺失，不租新机器、不虚构双机结果，也不默认继续使用早期 4090／5090 资源。

## 10. W7：全流确认、失败分母和论文证据

### 10.1 数据规模不能偷换

原图、原投影业务完整 1× 28,506 件和 2× 57,012 件是必须面对的主档；24 件选择只是机制组。原始 legacy 流为一个模拟日，投影到南宁拓扑不等于获得了真实机场运营日。倍流和仿真随机种子不是新的实测日。

完成主档后按预声明规则扩 4×／8×／16×压力，32×仅 smoke 可明确标注。超载可得“超过该合同能力”的结论，不要求所有任意高流量都全部完成；必须保留积压和未完成，不能删工作后声称可扩展。盘量／容量的敏感性单列且所有方法同档，不把增盘当算法修复。

### 10.2 核心实验矩阵

先做无学习的 R1-only、R2-only、并行单向耦合、强滚动反馈、联合主方法；然后加入学习版及同预算对照。设置预测关闭／过期／打乱、仅更快事件激活、固定载盘路线、去除释放反馈、去除复用链边界、替换通用 LNS 等消融。每项消融只动对应机制，基础权限和安全底座不变。

包含无故障、局部故障、消息延迟／丢失／重复、预测反转、满接收、长线在途、盘充足负对照。集中式更多信息参考可以单列；不能因为它有全局真值而误判去中心化算法实现错误，或把自己偷偷拿到全局信息的结果叫去中心化。

### 10.3 指标与统计

事前冻结主终点、保护规则、效应解释和确认集。所有 offered 任务都在分母，报告完成率／准时率、未完成与失败、积压面积／等待、缺盘等待、尾部延迟、空盘运输代价、盘复用、正常业务逐件变化、节点／边冲突和资源／权限违例；计算与消息指标独立列出。

对有限 H，可以报告 `Σ[min(Cj,H)−arrival_j]` 等限制时间指标，但必须单列未完成和约束，不允许用它掩盖堵死。H 以后才 offered 的任务不能混入该窗口，已 offered 但未入网的任务不能删。达到 H 不等于所有请求兑现或所有在途义务清空。

全体正常服务保护的原合同保持。对比基线的相同业务 ID／到达／截止／随机事件，任何回归逐件列出；总均值提升不能冲销不被合同允许的退化。没有用户明确许可，不自行加非劣界或把 0 改成允许小退化。

统计单位按外生运行／源业务组，不把数万个相关任务当独立样本。采用配对外生随机带；运行分支改变随机调用顺序时按事件身份生成或对齐共同扰动。开发与确认隔离，置信区间按独立运行或源组聚合；单源日结果注明推广限制。实际有多个独立源日才作跨日推广。

### 10.4 论文交付必须与方法同步

在 W3 完成问题定义和最近邻差异表，W4 形成伪代码／性质／反例，W5 完成学习目标及拆分，W7 完成实验与失败边界。未完成结果用明确占位，不先写虚假的提升数字。

贡献至少分别回答：相比已有联合路由空盘 MPC，多出的可执行信息／权限与求解机制是什么；相比强服务匹配，多解决的非可分耦合是什么；相比通用 LNS，边界／复用链方法有什么结构或计算优势。不能把“用了机场”“用了 G31”“分层＋小网络”作为充分创新论证。

## 11. 科研失败时的自动分流，不逐项等人工审批

| 观察结果 | Codex 自动执行的下一步 | 禁止的替代动作 |
|---|---|---|
| 没有 R1 候选或所有授权关闭 | 检查原图路径选择、建立合法单独权限档、统计无选择任务 | 静默改历史输入或增边 |
| 预测准确但未在相关决策前到达 | 分解 source 复验／通信／期限，做时机与消息消融 | 降为零延迟冒充原协议 |
| 强基线解释全部有限域收益 | 诊断可分性与高阶资源耦合；换预声明真耦合域 | 在旧八域重复大训练 |
| 候选存在优势但方法没找到 | 检查筛选误杀、边界模型与搜索策略；允许小模型 pilot | 只调随机种子或弱化基线 |
| 标签好、真实继续差 | 对齐控制器、行动执行、继续策略和最终业务分母 | 换成容易打分的替代模拟器 |
| 求解邻域扩大到全网 | 研究可验证边界／协调方案，公开 unknown 和计算曲线 | 无证明截断再声称全局保护 |
| 完整计算超 100ms | 剖析热点、活跃索引、预算内 incumbent、减少重复搜索 | 删除历史／请求或摊薄耗时 |
| 全流受未确认物理语义阻塞 | 输出必要界和合同问题单，继续其余研究代理／方法线 | 擅自扩容、增盘、改 FIFO |
| 学习无独立增益 | 诊断预测对象与可蒸馏计算价值，保留失败消融 | 扩大模型并把“含网络”当创新 |
| 新物理／身份／泄露缺陷 | 停止受影响标签和性能结论，修复后重放依赖项 | 用旧结果继续写正式主张 |

资料缺失通常只阻断局部任务。只有数据／源码损坏、新安全或身份失败使所有后续实验失去意义、超出授权、必须由用户决定的业务语义，以及资源不足无法继续任何有效任务，才停止整轮并一次性说明。

## 12. 首个 7—14 天连续执行块：必须留下实质结果

**块 A：起点和真实控制。** 复用本轮身份与原始证据；检查实际增量；完成 C1 token 适配和 C2 定时生命周期，接入完整请求 span。新增窄范围回归与 native 真实场景证明，不花整天重打已相同的 ZIP。

**块 B：真联合的最低闭环。** 从原图合法可选路线开始，为两项需求分别建见证，形成一个两个 owner、至少两个相互制约候选、能改变后续盘复用的在线场景。保证变更能传到真实 G31 动作、不是仅改变论文图或策略名。冻结 original24 作为“不能证明联合”的负对照。

**块 C：强参考和第一版主算法。** 在事前定义的机制域运行 B1/B2/B5，建立非可分交互诊断；完成 B3/B4 的最小正确适配；在有意义域实现 W4 的第一版复用链候选与联合选择。每完成一个域就记录强参考饱和／unknown／剩余改进来源，不等所有大实验才开始分析。

**块 D：同时向正式规模靠近。** 固定全业务输入档，记录零容量与回压阻塞；做真实请求剖析和至少一个长历史计时档。若 W5 门达到，只启动规模受控的残差／排序 pilot；未达到继续 W2—W4，不以未授权训练“凑工作量”。

首块结尾至少包含可执行代码、实际运行回执、一个清楚的机制成立／被反证结论、下一最优任务和准确续跑命令。若任务条件确实阻塞，给出原始错误／合同／必要界及已转入的替代任务，不把未完成写成全完成。

## 13. 自动化工作方式、资源与状态文件

在既有 `RESEARCH_STATE.json`、`RESULT_INDEX`、`NOVELTY_LEDGER` 上增量维护，不再建立相互矛盾的多套成功状态。新增一个 LT2 任务清单可以，但必须引用共同状态。

每个任务记录：`task_id, depends_on, status, source_identity, input_contract, evidence_paths, actual_result, next_action`。状态限定为 ready／running／complete／negative／blocked_external／invalidated；negative 是科研结果，不是偷偷改成 complete_success。一个任务阻塞，只暂停其依赖后继。

示意执行逻辑：

```text
while 本次会话与授权资源允许:
    从任务依赖图中选择最高优先级、可执行的研究任务
    若发现新身份/物理/信息泄露缺陷:
        隔离受影响证据，修复并重跑最小必要范围
    否则:
        在新输出目录运行有预算的实现或实验
        保存输入、源码、构建、stdout/stderr、退出码和完成状态
        根据本文件的自动分流表选择下一任务
    原子更新共同状态与唯一推荐续跑动作
```

先登记实际 CPU、内存、磁盘、已有进程；资源不明时默认最多 2 个 native worker，试跑后再增加。新 worker 不抢占用户已有实验。每个 shard 独立子进程、有 wall timeout 和真实退出码；磁盘不足预留安全空间，不删除原始失败证据。没有明确预算时先用短 profiling shard 确定成本，再扩展，不启动不可控的全组合搜参。

每次会话结束留下 `NEXT_ACTION.md` 与一条经过验证的实际续跑命令。路径／参数必须根据当前实现生成，不能抄旧 binary011 命令假装适用于新版本。命令带新输出目录、实际 binary 身份和必要合同；恢复是否跨进程需写明。

以里程碑汇报为主：控制闭合、真耦合／强参考、主方法、学习、正式确认。正常实现和可逆研究参数无需逐个询问“是否继续”。本计划不是向外部服务创建了自动任务；是否持续运行取决于当前 Codex 会话、主机和已启动进程。

## 14. 不可越过的收口门

| 门 | 通过标准 | 当前状态 |
|---|---|---|
| G-control | 合法 token、真实 owner 消息和完整定时、可执行 R1/R2、正确继续 | 待补齐 |
| G-coupling | 原图／明确研究域存在真实双向作用，候选和强参考口径正确 | 未闭合 |
| G-method | 对最近邻有具体差异，机制或质量—计算优势有因果证据，性质与边界明确 | research_candidate |
| G-learning | 同宿主合法标签、无泄露、有真实增益／预算优势或完整负结果 | 大训练不放行；满足前提可做 pilot |
| G-business | 原流全分母、正常保护、有限盘循环和异常结果完整 | 未闭合 |
| G-realtime | 明确域内完整单任务计算 ≤100ms，包含失败与两机必要档 | 未通过，保留已见超时 |
| G-paper | 方法、理论／结构、强对照、消融、规模、失败、资料限制均可复核 | 不可提前宣称达到 |

正常保护／安全失败不能由平均收益抵消；正式创新失败不能由工程测试数抵消；原始物理语义未确认不能由研究代理自称现场实现。**保留目标，允许否定具体假设；不能为了尽快交差把工作降成工程验收。**
