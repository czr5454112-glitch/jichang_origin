# G4IRSF26 New Ideas

These follow-ups come directly from the paper-protocol experiments. They keep the S4/J2/E2 framework small and local.

1. **Preserve release as part of the experiment protocol.** The legacy Java release sequence changes with conveyor speed because each source admits at most one segment per epoch. A speed comparison must therefore feed S4 the exact release trace produced by the matching HCA speed run, not reuse the 2.5 m/s trace.
2. **Use `outputstarttime.txt` for legacy retry timing.** A task that fails its first HCA planning attempt may later succeed without appearing in `routes.csv`. The raw successful-planning stream is the authoritative processed-attempt source; route predictions remain diagnostic only.
3. **Keep S4 as the no-fault baseline.** Its mean raw-bag time is lower at all four tested standard speeds. The 2.5 m/s maximum remains worse than fresh HCA, so the next routing change should target extreme waiting rather than the already-strong median.
4. **Try one bounded local speed estimator.** S4 wins all four 10% physical-slowdown cells but loses the 20% and 30% cells against the thesis's archived dynamic method. The smallest useful response is an EWMA of recently observed traversal time per directed edge, used only to correct the existing one-step travel term. Do not add a route predictor or another policy hierarchy.
5. **Compute a topology upper bound before severe fault simulation.** After removing the seed edges, directed reachability gives a necessary upper bound on completable raw bags. If a run reaches that bound with structural safety intact, the primary completion rate is proven even when the event stream is censored. Timing and deadline metrics must remain unmeasured in that case.
6. **Separate mapping evidence from algorithm performance.** Interruption lines 2, 3, 4, 5, and 8 have direct workbook support. Lines 1, 6, and 7 are supported by the archived workbook and map figure but remain a 69-edge project projection of a thesis that describes 72 lines. Results involving those IDs must keep the reconstruction label.
7. **Keep the inconsistent 5+7 source row archived-only.** The workbook labels this row `33→44 + 46→36`, while the other rows require line 5 to be `14→46`. A fresh HCA run using the worksheet label still produced `8013/28506`, not the archived `13939/28506`; there is no defensible fresh S4-versus-HCA verdict for this row without the missing original protocol.
8. **Do not convert predictable business failure into a safety failure.** A permanent disconnection can legitimately leave bags unfinished. The safety gate should continue to cover forbidden A*, global reservation scans, physical entry into faulted edges, conflicts, and runtime contract violations; completion rate is the experiment outcome.
9. **Add one fault-triggered local reachability potential, not another route planner.** The interruption matrix shows that the static S4 potential remains strong in normal flow but can keep preferring a basin whose best exit has failed. The smallest fault response is a versioned distance-to-goal scalar propagated between adjacent node owners after a fault or repair. S4 would reject a next hop whose propagated value is unreachable and otherwise reuse the existing one-step score. This keeps each bag path-free and the reservation logic local. Test it first on `single_4` and `pair_2_4`, require exact no-fault equivalence, and stop if it does not materially recover completion rate.

The next implementation candidates are therefore deliberately narrow: one local travel-time correction for the 20% slowdown cells, and one fault-triggered reachability scalar for the interruption cells. They should remain separate experiments so a fault-routing gain is not confused with learning or with the already-strong no-fault S4 baseline.
