## Data Claim Levels

High-flow data must be labeled with one of:

- `original_project_generated`: produced directly by the original ICS project generator or simulator.
- `original_rule_replay`: generated by a reimplementation after auditing original project rules.

- `diagnostic_synthetic_only`: artificial stress data for debugging only; not allowed for main performance claims.

## THT Denominator and Source Release Semantics Rule

Any experiment that changes task release time, pass_time, source queue order, source queue gating, or reservation semantics must explicitly declare the THT denominator.

For paper-protocol comparisons, Codex must distinguish:

- `original_entry_time_tth` (G4IRSF12 raw-entry semantics): THT measured
  from the raw task's `original_entry_time`, including scheduled dwell before
  later split segments become eligible.
- `legacy_segment_pass_time_tth`: THT measured from each processed segment's
  `pass_time`; this is the actual denominator behind the legacy G4IRSF8 field
  that was labelled `original_entry_time_tth`.
- `java_release_time_tth`: THT measured from Java epoch release time / cur_time when the task actually enters path planning.
- `processed_segment_attempt_time_tth`: THT measured from processed JSONL segment attempt_time.
- `diagnostic_runtime_tth`: any engineering timing used only for diagnostics.

A candidate may not be promoted as paper-protocol superior if it improves THT by changing the denominator unless the original thesis/project evidence proves the denominator is the same.

All release semantics variants must preserve:

- original task_id mapping,
- original bag count,
- original source/goal distribution,
- storage-in/out grouping,
- no runtime full A*,
- no teacher path/future schedule leakage,
- no node-window conflicts.

If denominator equivalence is unresolved, the result must be labeled:
`engineering_candidate_pending_denominator_audit`.

The parsed historical IoT-DRPA/HCA* value `3.967122711` minutes is the
`processed_segment_attempt_time_tth` value reconstructed from the original
project output start time.  It is not an `original_entry_time_tth` value and
must never be used as an original-entry target.  The same historical output
recomputes to approximately `5.197225146` minutes under Java-release time and
`5.764936746` minutes under the legacy pass-time-anchored field that was
labelled original-entry.  Neither value uses the G4IRSF12 raw-task
original-entry denominator.  These recomputations remain historical parsed
evidence, not a fresh Java/HCA* rerun.  A comparison must show all relevant
denominators side by side and may claim a win only within a matched
denominator.

The append-only G4IRSF12 denominator reconciliation discovered that the legacy
G4IRSF8 field labelled `original_entry_time_tth` was actually anchored at each
segment's `inputdata.jsonl:pass_time`.  It was not anchored at the later
G4IRSF12 raw-task `original_entry_time`.  Legacy v2-safe/HCA values must
therefore be translated by the protected-input scheduled pre-release offset
before comparison with the G4IRSF12 raw-entry metric.  The authoritative
correction is
`outputs/reports/g4irsf12_denominator_reconciliation.md`; it supersedes only
the old performance targets, gates, and derived blockers.  Sealed runtime
timings, completion/safety counters, repeat hashes, and execution provenance
remain immutable.

## Original-Scale-First Rule

Every new event-runtime architecture must first pass the complete original
1x workload on the frozen map and task source.  Passing requires all 28,506
raw bags and all 43,603 segments to complete, zero failed segments, zero
node/resource conflicts, zero runtime full CIE/A* calls, zero global
reservation scans, zero unresolved deadlocks, no event/time-limit termination,
and a drained backlog.  Survivor-only latency statistics cannot satisfy this
rule.

Until that gate passes, full 2x, 4x, 8x, 16x, and 32x experiments are
prohibited.  A smoke or bounded diagnostic cannot substitute for the full 1x
run.  Any later expansion also requires a committed demand-calibration report
and an auditable task-generation level.

## Real-Demand Scaling Rule

Repository 4x, 8x, and 16x workloads are stress levels and must not be called
real airport demand.  A real-demand multiplier must be computed from the
number of departing and transfer checked bags actually handled by the airport,
terminal, and BHS subsystem represented by the frozen map, divided by 28,506.
The calculation must document the airport/terminal and system boundary,
design-day factor, departure share, checked-bag rate, transfer-bag rate,
subsystem allocation, early-bag share, flight-bank profile, and parallel-system
diversion.

Missing inputs must be represented as an uncertainty range.  Without those
inputs a workload may be labeled only `provisional_envelope` or `stress_only`;
it may not be promoted as calibrated real demand.

## Framework Variable Isolation Rule

Framework/event-loop semantics, resource semantics, scorer, PIBT coordination,
pressure control, and admission control are separate experimental variables.
A causal A/B must change exactly one of them while holding the frozen map,
source ordering, denominator, and all other modes fixed.  If several variables
change together, the result may be reported as a combined candidate but not as
evidence that any one component caused the observed delta.  Every ladder must
retain negative rows and the complete control-to-candidate deltas, not only the
final winner.

## No-A* Candidate Tiering Rule

When a no-A* candidate includes multiple semantic changes, Codex must separate proven and unproven parts.

A candidate whose release semantics and THT denominator are supported by original Java/project evidence, but whose reservation semantics are still engineering-only, must be split into:

- a conservative candidate that uses only proven semantics;
- an enhanced candidate that includes the engineering-only improvement.

The conservative candidate may be used for stronger paper-protocol discussion.
The enhanced candidate must remain an engineering candidate until the missing semantic proof is supplied.

Do not merge these layers into one claim.

## Legacy Rule

Do not modify legacy Java or original ICS source code for CZR005 experiments unless a separate explicit integration stage is opened.
