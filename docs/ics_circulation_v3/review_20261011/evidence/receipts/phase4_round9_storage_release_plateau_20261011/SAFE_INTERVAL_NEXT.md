# 存储/接收时窗导致的剩余搜索瓶颈：下一实现合同

## 已有证据

只改变同 f 排序已解决无库位冲突的 release 平原，但 `synthetic_comparison_001` 的 busy-storage 合法晚到 witness 仍在原 500 展开预算下找不到。完整原图的其他已预约路线还会使边/库位/接收资源的真实可行到达晚于静态下界；不能把“同 f 问题已修复”推广成所有资源平原都已消失。当前原件保留这一负结果，不通过删除回路或加大 K/预算抹掉它。

## 文献支持与不能直接借用的保证

SIPP 用“配置与安全时间区间”表示搜索状态，减少逐时间点展开；它的保证依赖论文的具体状态、等待和碰撞假设。本项目可以研究这一表示，但不能直接沿用其最优/完整性结论。[Phillips & Likhachev, ICRA 2011，作者原文](https://www.cs.cmu.edu/~maxim/files/sipp_icra11.pdf)

后续 SIPP 研究专门讨论了附加运动约束；这提醒我们，当前 ICS 的不可等待节点、边上的不可撤回占用及状态支配规则都需要重新核验。[Safe Interval Path Planning with Kinodynamic Constraints, AAAI 2023](https://ojs.aaai.org/index.php/AAAI/article/view/26453)

以下是针对当前源码的设计推导，不是上述论文已经证明的 ICS 性质。

## 实现顺序与证明义务

1. 从当前公开 `effective_reservations` 构造“再容纳这一只真实托盘”的可用区间。排除候选自己的旧资源前必须遵守现有 replacement owner 权限；其他真实盘、旧在途和已承诺路线不能丢。节点/边可以容量大于1，必须按叠加占用是否达到容量划分，不能把每条预约都当容量1阻塞。
2. 保持半开语义。边预约覆盖整段 travel；目标节点、最终接收资源、卸载和 hold 分开验证。预留足够信息重建完整 witness，再交共同 validator；区间摘要不能代替真实承诺。
3. 可等待节点的候选状态可研究 `(node, interval, storage_stage)`，标签保存实际 arrival。只有同阶段且早到标签确能在同可用区间等待到晚到时刻、并不改变任何义务时，才有资格讨论支配。不可等待节点保留 exact-time，或向前一个可等待点投射整个 no-wait 链；禁止用早到标签无条件删除晚到标签。
4. 固定 release 仍必须由公开合同给出。在 storage 节点，合法出发必须不早于真实入库和 release，并且整段驻留可用。不能用“release 时刻已过”替代真正访问 waypoint；也不能为边/接收容量等待凭空生成库内空盘信用。
5. 最终节点候选必须覆盖 reception/unload/hold 和长期盘驻留；较早到达终点却接收失败不能阻止搜索后续可行区间。保护截止仍作用于最终卸载完成。
6. K=1 最早可行 witness 与 K>1 不同物理路径/预约候选的覆盖要求分开证明。即使最早到达标签足以证明单目标最早到达，也不因此证明可以删除学习/控制所需的候选路径族。保留候选覆盖 diagnostics，不把较少候选说成全域最优。
7. 日历构建、区间扫描、转移及完整校验全部纳入原请求工作预算。不得靠未计持久缓存或读取私有未来任务提高结果。若以后缓存区间，必须扩展私有 checkpoint/cache 绑定及公平冷/热计量。

## 固定验证顺序

- 先对保存的 busy-storage 反例和真实原图失败 query 做同一 snapshot/合同/K/预算对照，保存原候选/合法晚到 witness，失败继续保留。
- 小整数图用现有逐 tick 精确搜索交叉比较：多容量、禁等链、跨区旧在途、同 tick release/acquire、接收拥塞、迟到入库、保护截止边界。只在其有限声明域内谈穷尽或最早性。
- 检查点恢复、后缀冻结、新/旧提交、条件/确定供盘及普通袋桥必须一致。新搜索不能扩大 owner 权限或改物理事件。
- 再重放同一完整44袋窗口；仍保留16件原最终OD不可达任务，不能借搜索改目的地。版本化目的域投射是单独的场景构造分支，需要保持原源及整航班代理组，不和搜索收益混在一起。
- 固定时刻逐袋服务/未观察/未完成并列；资源截止早于完整窗口时不能比较 J 或完成率后宣称吞吐收益。
