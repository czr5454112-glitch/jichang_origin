# Round8: terminal screen, identical-instrumentation on/off performance

Before any original-network physical run, fixed design: 27 original Round6 scene × tape inputs, two blocks, both on/off arms = **108 episodes**. The fixed pilot is three nominal inputs × two blocks × both arms = **12 episodes**. Formal repeats these identities independently; pilot work is never reused. These are 27 business cases with timing repeats, not 54 independent business samples.

Within each sorted case list, block 0 alternates off→on / on→off by case index; block 1 reverses each pair. Every arm runs in a fresh Python subprocess. A pair runs its two arms sequentially; at most three pairs are concurrent. All block 0 pairs finish before block 1 starts. Together with the main stability line's six workers, global concurrency is at most nine. No warmup or outcome-based sampling. All paired differences, including regressions and zeros, are retained.

New opt-in `PerformanceGenerator` uses the frozen Round7 certificate only in the on arm. Both arms perform identical full pre-query public Snapshot SHA, actual private-cache SHA/count, diagnostic/pool copies, fixed-schema rows, complete physical tick/event observations and serialization. Both use the frozen Round7 `InstantPhysicalCursorSimulation` to detach each actual tick observation; the legacy live-map representation is retained only for compatibility against old artifacts. Paired acceptance independently compares the new detached observations. Snapshot hashes include only the actual public query state. Each child exports and asserts an initially empty private replay cache before the first query; factories remain pure and create fresh caches. Skipped searches may change later cache histories, which are reported separately, never forced equal.

Algorithm timing starts before destination lookup, validity checks, dispatch and optional certificate/delegate. It excludes common Snapshot/cache hashing and diagnostic/pool copies. Screen and search timings are nested subintervals. Whole `run_cycle` includes the shared observer and full controller. Child invocation includes setup, input verification, simulation and raw serialization; earliest module-entry cumulative CPU and the heavy-import interval are explicit. On Windows the parent reads final `GetProcessTimes` after child exit while the process handle is still valid, covering process startup/import/receipt/teardown CPU. Parent launch→exit wall is separate. Worker peak working set/commit is per-process lifetime, not simultaneous aggregate RAM. No production latency or hard-real-time claim is made; concurrent elapsed times include contention and timer-resolution zeros are kept.

The paired acceptance contract checks every query's actual Snapshot SHA, identity, K and complete ordered raw candidate pool, plus full physical tick trace, task ledger, protected results, actual actions, slow proposals and final drain. Both arms also compare against all 27 frozen Round7 screen raw artifacts, including the requested nominal compatibility check. Query call count is retained, search and screen work remain separate. The prior unmatched collector CPU values are used only for rough planning (about 4–5k CPU seconds, 25–35 minutes at three workers), never as a speedup denominator. Pilot cost will refine the resource estimate without changing the 108-case plan.

Every failed invocation, completed first arm, partial query work, persistence failure and repeated attempt is retained. Source/test/input/C++ bindings use the frozen Round7 closure plus only these new performance files and dedicated tests, excluding other agents' developing Round8 modules. Original default policies, old sources, old artifacts and C++ are unchanged; no commit/push.

Measured algorithm time is the performance primary; whole simulation/process invocation show the practical cost of this instrumentation. Shared observer overhead may still vary naturally with on/off private-cache contents and result/status data size, so it is measured separately. Extra screen computation is never free. Validation and analysis costs are separately recorded in the new Round8 ledger.
