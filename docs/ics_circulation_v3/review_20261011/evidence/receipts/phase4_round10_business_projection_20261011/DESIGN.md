# Versioned whole-flight destination projection — Round10

This is an explicit, result-independent research input version. It does not change original workloads, graph edges, runtime experiments, protection, or deadlines. It does not certify capacity feasibility or a real airport assignment.

The archived 2026-10-09 review W2 requires provenance-preserving task projection, complete denominators and a directed loaded/unloaded return path. Round8 BUSINESS_INPUT_DESIGN requires immutable business identity, complete early/direct lifecycle, finite real trays and private future tape. The original Temp review path is no longer present; its repository archive is used. The failed path read and subsequent file discovery are unmetered auxiliary work, not zero CPU.

The new pure module returns a distinct frozen BusinessProjection containing full original BusinessTask records and an explicit original/new-final decision. It is deliberately not a BusinessWorkload; passing it to the unchanged runtime adapter must fail closed. A future explicit adapter will require a separate contract and review.

The caller declares the source workload fingerprint, source graph SHA, proxy status, whole-parent-flight-family grouping, salt, canonical ordering, role-limited candidates, both-mode positive original directed edges, unchanged protected deadline rule and final-unload seconds. Missing or unsupported fields fail closed. Empty necessary domains fail without dropping any bag.

Each group includes every bag with the same parent timetable SHA and exact original `(STD, end, Unloader)` flight surrogate, including all synthetic copies. The 2× source has 360 parent groups and 720 flight instances; it is not an independent second observed day. Ranking uses the parent key and fixed salt, not the scale/raw artifact SHA, so corresponding 1× and 2× families retain the same decision when their domains agree.

Candidates are original legal unloaders. Every original origin must reach that final using its original direct or storage lifecycle. Early tasks must reach their unchanged storage waypoint and leave no earlier than the unchanged release. Every final must reach at least one original legal loader using positive original directed edges. Return to the same origin is not required. Final node equal to a required storage waypoint is excluded.

Exact rational travel seconds and sums of per-edge ceil-to-tick travel are computed independently. Earliest final completion includes declared unload service; protected final deadlines remain the original exact seconds and conservatively floored tick. Necessary seconds and tick slack are reported per candidate for the whole group. Static necessity does not include simultaneous capacity, inventory availability, ownership, permissions beyond the explicitly declared proxy, or time-dependent congestion.

An already-legal original final is retained. An illegal original final is replaced by the candidate with smallest SHA256 score over a canonical JSON encoding of `[schema, fixed salt, canonical parent-flight key, candidate]`, with explicitly declared lexical Unicode node order for ties. This is deterministic salted hash ranking, not a load-balancing policy or a claim of balanced results. No runtime result is read to select the salt, ranking or domain.

Validation checks the source seal and complete denominator, recomputes every group/domain/decision from bound source inputs, and compares the entire immutable result. Resealing a mutated projected task, group assignment, deadline, origin, raw identity, release or decision cannot bypass the source comparison. SHA256 seals are integrity checks, not signatures against a caller replacing the entire declared source and contract.

Evidence will include all 28,506 original and 57,012 densified input records, full group decisions, unchanged-field/source SHA checks, original-versus-projected counts, no physics, CPU/wall scopes, all failed attempts, source/test snapshots and manifests. The old six original-endpoint windows and their negative results remain valid and separate.
