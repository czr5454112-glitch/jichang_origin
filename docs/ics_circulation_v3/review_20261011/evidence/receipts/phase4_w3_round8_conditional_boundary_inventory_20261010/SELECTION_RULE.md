This is a separate, outcome-blind structural inventory. It does not change the frozen Round8 17-state / 64-draw stability experiment, its 4,352 logical requests, or its controller. No physics, routing search, branch evaluation, or cost/regret inspection is authorized by this inventory.

1. Start with all 180 genuine Round7 same-zone loaded attempts, including all six zero-candidate attempts. Bind the existing attempt inventory to its preparation manifest and every checkpoint/metadata file to the original Round7 collection manifest before loading trusted local pickle files.
2. Partition into the six fixed scene × role cells: cross_cycle, counterflow, near_full × origin, continuation. Within a cell sort by public `(time, decision_index)`. A selectable attempt must have K > 0, an actual loaded routing cursor, and at least one original pending **soft** task whose arrival minus checkpoint time is 1 or 2. Keep the complete per-attempt inventory, zero-candidate rows, and missing cells.
3. Select the first eligible attempt per cell. Within that state select the boundary task by `(arrival, bag_id)`. Do not use candidate costs, selected-action performance, labels, regret, or future branch outcomes. Pending arrival metadata is engine-only structural evidence; it is never an online controller feature.
4. For only that selected task, the base masses are cancellation 3/24 and jitters −2, 0, +2 each 7/24. Conditioning on being unobserved at this actual post-arrivals loaded cursor removes −2 because arrival−2 ≤ now. The remaining support is cancellation 3/17, jitter 0 with 7/17, and jitter +2 with 7/17. Cancellation removes the identity; +2 shifts arrival and deadline together, preserving OD, identity, and slack. Every other pending task stays exactly on its original tape, including all protected tasks. Existing state, candidate pool, cursor, forecasts/publications, cache, and continuation are not changed.
5. Materialize and validate these three finite tapes without applying them to an engine. Record their hashes, target identities, original pending metadata, exact rational masses, original K and candidate keys, checkpoint/metadata SHA, and checks that all non-target and protected tasks remain exact. No RNG is used. This is a one-task conditional slice with other tasks fixed, not the main joint future law or a newly calibrated future distribution.
6. Report a prospective full candidate × three-support grid of `sum(3*K)` physical continuations if separately authorized later.
