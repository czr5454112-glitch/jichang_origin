## Lossless storage version

`foundation_airport_observations_v2.py` keeps the original planner input object and returned decision object. It stores exact JSON content in SHA256-addressed blobs, chunks lists into 64 items, and records references in a second gzip stream. A reference row is flushed only after its complete blob members are flushed. No actor field is deleted or added; unknown values, exact public waiting-group counts, numeric types, ordering and residual callbacks remain available.

The native policy view deliberately aliases its two ledger fields. The recorder shares their descriptor only when the objects are actually identical (`is`); it does not use loose Python equality to identify distinct `1`, `True` and `1.0` values. Cache comparisons use exact JSON bytes, and immutable encoded blobs capture observations before the planner can mutate them.

The public iterator is:

```python
from scripts.experiments.g31_ics_circulation.foundation_airport_observations_v2 import read_records

for row in read_records(path, blobs_path=None, allow_partial=False):
    # Full original callback fields, reconstructed without private augmentation.
    ...
```

`blobs_path` defaults to the matching `.blobs.jsonl.gz` sibling. The decoder validates complete gzip CRCs, blob hashes, record sequence and referenced lengths. It indexes compressed offsets and retains at most 256 decoded blobs in its cache, rather than retaining the complete expanded recording. `allow_partial=True` permits a killed final gzip member to be discarded; it never turns a missing reference or altered blob into a valid record. Returned values are isolated from the cache so consumer mutations cannot alter later rows.

The reconstructed record changes only `schema` from `g31.foundation.airport_policy_observation.v1` to `.v2`. In particular, `scope` still equals `actual owner policy callback arguments and returned decision, including residual calls`, as verified against the old run's frozen source and actual original rows. Other contract-level storage metadata is explicitly new.

`C_observation_v2_benchmark_001/report.json` records a pure replay of the first 24 actual callback rows: 2.51549 seconds for old capture and 0.60571 seconds for the new capture, or 4.15 times faster for this small fixed sample. Compressed storage fell from 3,662,661 to 642,517 bytes. This is a recording microbenchmark, not a whole-native speedup claim. `decoder_freeze_validation.json` directly compares the original failed-run rows against the final decoder's encoded JSON, changing only the schema field; all 24 records pass with no ignored scope or content fields.

The callback archive still contains only actual callback input/options and returned decision. It does not contain the subsequently assigned request ID. Closed segment `control_records` and immutable `client_calls` provide the submission/attempt binding; raw transfer receipts can supply offline outcome labels only after a valid join. An unclosed segment's absent bindings must remain missing. One trajectory alone does not establish independent train/dev/test data.
