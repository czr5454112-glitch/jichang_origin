# Optional regional path pool: pure evidence and finite replay proposal

This change is an opt-in, process-local experiment in new modules. It does not edit the frozen controllers, native runtime, public-travel pool, or sealed business experiments. The actual finite pair below preserved exact behavior but was slower. It is not recommended for adoption and does not establish complete-business-request latency below 100 ms. The preparation sections retain their historical scope.

## Why this computation

The saved `late_reconstructed_profile_003/controller.prof` measured 17,872 `_ObservationRouting.path` calls and 3.260 s within 2,000 owner activations (42.589 s owner work; 57.521 s controller run). Each `_publish_services` invocation starts a new observation-scoped graph/heuristic cache. Reusing an identical occupancy-dependent path across invocations could remove repeated graph construction and search. This is distinct from the existing static `PublicTravelPool` and native026 delivered-message index.

The earlier actual 125.423 ms outer activation at logical time 11980.019600 had only 2.656 ms of measured native calls; another 123.005 ms activation at 12131.212850 had 2.839 ms. Neither had a contemporaneous GC trace that proves the cause. The path profile is evidence of recurring work, **not evidence that this cache removes those spikes**. All owner activation timings remain proxy scopes rather than the original per-business request contract.

## Exact reuse boundary

Implementation: [regional_path_pool.py](../../scripts/experiments/g31_ics_circulation/regional_path_pool.py). The context replaces only the process-local `protocol_control._ObservationRouting` factory and restores it on exit. Each publication gets a new handle retaining the original observation identity/time guard. Key construction happens only at the first path request; unused handles preserve the old lazy validation behavior.

An eligible key contains the owner and the original ordered node IDs/occupancy-presence/occupancy values, node service records, directed edge lengths and speeds, all edge-capacity records, and all known-fault endpoints/active values. Integer versus float types and every finite float's binary representation, including signed zero, are preserved. Neither paths nor weights are rounded; misses use the unchanged solver. Now, jobs, forecasts, ACKs and other fields the solver never reads are absent from the key. Each new handle rebuilds the key even at the same logical timestamp, so a native boundary cannot reuse a stale occupancy key.

The supported domain is ordinary native dictionaries/lists/tuples with unique nonnegative integer node IDs, matching node-record membership, finite numeric values and positive edge speeds. Unsupported values, duplicate IDs, malformed membership or exceptional inputs fall back to the old solver. A custom observation mapping is delegated before any additional mapping access. Original path exceptions are never cached. Read-only observation lifetime is the same explicit contract already imposed by `_ObservationRouting`; in-handle mutation is unsupported by both implementations.

The pool retains at most four immutable fact keys and 256 immutable path tuples per key. Each handle resolves its full graph key once, then looks up source/goal pairs in the resulting bucket. A live old handle can finish using a bucket evicted from the shared pool; it cannot reinsert the obsolete observation or make it available to a new handle. Jobs, observations, ACKs, service decisions and graph/heap objects are not retained by the pool. A fresh context is required for each restored/forked experimental arm. No cache state enters a checkpoint or native seal.

## Pure results, including negative results

[52 pure checks](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_pure_004.xml) passed. They compare unchanged-solver paths on 20 seeded graphs across all source/goal pairs, changed occupancies, closure/fault changes, exact numeric/order distinctions, unsupported inputs and exceptions, same-timestamp new handles, LRU eviction with a still-live handle, absence of retained job payloads, and full service-publication calls/state/serialized route outputs for accepted and rejected submissions.

The [microbenchmark](../../scripts/experiments/g31_ics_circulation/benchmark_regional_path_pool.py) uses the actual saved public owner projections in `native026_acceptance_001/late/entry_views.json.gz` (151 nodes, 227 edges). It declares repeated, alternating and always-changing occupancy scenarios. Nine source/goal pairs per owner use visible carried-job stages, padded with public edge endpoints. **Those repetitions and padded pairs are diagnostic scenarios, not the actual original-flow activation tape or a measured cache hit rate.** All lazy-key creation, lookup, solver misses, maintenance and result accumulation are timed; GC remains enabled. Identical observation preparation is outside both timed arms and separately reported. Concurrent project work means these are not isolated performance measurements.

The first micro attempt copied irrelevant message histories during scenario preparation. Its verified task-owned Python process was stopped; [micro001](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_micro_001/interruption.json) preserves the incomplete attempt. The second attempt completed but exposed a real negative result: repeatedly hashing/comparing the entire graph key for each pair made the pool 1.51–1.73 times slower even with high reuse. [micro002](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_micro_002/receipt.json) and its exact source archive remain unchanged.

The current implementation resolves the full key once per handle. [micro003](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_micro_003/receipt.json) retained exact paths in all 18 cases with no source changes. ## Bounded original-flow proposal, unexecuted

[prepare001](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_prepare_001/plan.json) has status `prepared_not_executable`. Its 50-source package includes the actual imported repository closure of the candidate and proposed replay components plus tests/microbenchmark; 67 native026 compiled-source archive hashes and the accepted binary are pinned. The future worker and independent verifier must enter a new complete source freeze before execution. The proposal itself does not constitute runtime acceptance.

Use the unchanged 28,506-job original input, native026 SHA `c7eab9d81e3e930a3e7f2f3a320b4c92b1c1c2e5a0c07db9c4050b536d821943`. Reconstruct the first ten authentic native024 shards, then require the actual cut-0009 seal `e245cd4e5345a6838ac0914e512bf550558210131237b3d3d6d83d1a8829f8ef` at H11775.277650 before obtaining a native checkpoint. This cut is selected to include the earlier spike neighbourhood, not after observing cache performance.

Run one serial original/candidate pair from that same verified checkpoint and exact controller state, with a fresh candidate pool. Each arm continues the exact next two 500-owner shards (1,000 activations), the original requested horizon H14400 and original event budget. The original saved exits are H12020.572400 and H12285.281484, with their contemporaneous native seals already pinned. Preserve each pending owner round and mandatory native drain across the same shard boundary. Cap the parent at 600 s and one native worker; no automatic expansion to 2,500 activations.

Require every ordered public API return, immutable request/retry payload, delivered ACK, notification batch, control decision, checkpoint policy state and both original exit seals to agree, except a closed allowlist of actual measured clock fields. The API wrapper must explicitly expose the recent-policy endpoint so it cannot silently select another native projection. Preserve complete raw records synchronously in bounded shards; any tracing/encoding and GC cost remains charged. Capture GC window envelopes and owner context without disabling, forcing or subtracting collection.

Retain whole initialization, reconstruction, checkpoint/restore, controller, output and process costs, plus per-activation outer/inner times and pool hit/miss counters. Shared/setup work is not divided by request count, physical simulation work is not subtracted, and a future independent update is not silently folded into an old request. The comparison tests this one implementation's exact semantics and local cost; it cannot replace the missing production business-admission contract or prove the original 100 ms requirement. Timeout, mismatch, missing evidence or net slowdown must remain explicit outcomes.

## Executable preparation, still no native execution

The subsequent [native001 ready package](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_native_001/ready.json) freezes the new [driver](../../scripts/experiments/g31_ics_circulation/run_regional_path_pool.py), [independent verifier](../../scripts/experiments/g31_ics_circulation/verify_regional_path_pool.py), all 27 actually imported repository sources and two test files. Its 67 compiled native026 source hashes remain bound to the accepted artifact. [74 pure checks](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_pair_pure_002.xml) passed, including API omissions/order/identity/argument/clock tampering, GC-envelope rejection, narrow clock normalization, proxy capability and cleanup, and exclusive artifact writes.

The executable design strengthens the earlier proposal: each arm uses its own Python process and independent native session and reconstructs the ten-shard prefix itself. No native checkpoint or mutable process cache is shared between arms. The parent uses one 600-second budget for both workers and its independent verification child, starting before its plan/pin/claim work; metadata/export overhead is recorded, and an observed overrun cannot be marked verified. Parent interpreter startup/import time is outside that internal timer and is explicitly labeled; each worker's subprocess elapsed time includes its startup/imports and all setup.

Both main sessions stop at the exact original 0011 budget-cut seal. Full-population result rendering occurs only on a separate diagnostic fork at the same logical time, with its actual advance and pre/post seals retained. The main-session seal is checked again after the fork. Any same-timestamp drain in that diagnostic result is explicitly separate from the main budget cut, and both arms must match.

[The clock inventory](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_native_001/timing_field_inventory.json) checks both real saved shards: their controller states contain no measured-clock fields; all measured clocks are exactly at the declared top-level, owner-record, native-batch and client-call locations. The archived native026 notification endpoint returns no measured wall-clock field. Thus its returned API values are compared completely; only the recorder's own start/end timestamps are excluded from API equality. The package was held for parent review and native-slot allocation at preparation time.

## Actual finite pair: exact behavior, negative performance result

The parent executed the frozen package. [Receipt](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_native_001/receipt.json) SHA256 `e6596f638947e78a36ed3dfcf118678a213ec34be8317ec2f195646b039b0676` records exit 0 and 64.0224655 s for the complete pair and verifier. [Independent verification](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_native_001/independent_verification.json) passed: each arm had 24,571 ordered API rows and 1,000 owner activations, matching the original two shards and all 28,506 offered identities. Both final native seals were `bdf3f42bf7ebea6c540fc68983a731bfc6b273894db8c669d6991ff2421baf34`.

| Measured scope | Original | Pooled |
| --- | ---: | ---: |
| Controller window, ms | 10,633.849 | 11,539.014 |
| Complete worker process, ms | 21,249.561 | 22,135.279 |
| Largest outer owner activation, ms | 28.641 | 32.200 |
| GC inside captured windows, ms | 222.285 | 234.986 |

Controller time increased **8.51%**. The pool recorded 1,000 key builds, 4,579 in-handle hits, 2,574 cross-activation hits and only 5 misses across 2 resident graph keys. High hit rate did not imply net benefit. Unlike the nine-pair micro scenarios, this real stream requested only five distinct paths. Key construction and lookup are plausible excess work; the existing totals alone do not isolate causation. GC remains included and is not established as the cause of the difference. The comparison ran alongside other work and is not an isolated speed certificate.

This negative pair remains authoritative for this implementation/domain; no adoption or 100 ms claim follows from the low activation maxima. Whole-business admission, setup and causal completion are different scopes. Any further candidate must retain this result, account for key/maintenance cost, and use a separately declared comparison. The pool's resident-entry counters also describe its own retained entries, not total process memory or observations held by live activation handles.

## Pure replay of the actual API: why high reuse lost

The separate [saved-API analysis script](../../profile_saved_regional_paths.py) instantiated no native session. It consumed all 24,571 saved original-arm API calls in exact order, checking every endpoint and argument, replayed both complete controller outputs/state with the closed clock normalization, and rejected unused API tails. It did not recompute a native seal. Only the routing dependency fields and actual source/goal/path calls were extracted for a second, pure kernel comparison. All source hashes before/after matched. [Pure receipt](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_actual_pure_001/receipt.json), [extracted calls](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_pool_actual_pure_001/actual_routing_calls.json.gz).

The true 1,000 handles made 7,158 path calls. Domestic handles had three distinct pairs, 112→53, 137→53 and 150→53; international handles had two, 29→53 and 28→53. All 579 domestic and 421 international activations respectively shared one exact graph key. There were no padded pairs, skipped handles or unsupported-projection fallbacks.

Three alternating-order repetitions, with GC enabled and every returned path checked, measured median kernel time 415.389 ms for the original and 1,019.639 ms for the pool: **2.455 times slower**. This is a routing-only diagnostic, excluding native calls and the rest of controller work, not an alternative full-request measurement.

Separate cProfile runs isolate the mechanism: the pooled kernel took 4.227 s under profiling; `public_routing_key` consumed 3.909 s cumulatively (92.5%), including 983,000 `_number` and 1,210,000 `_node` calls. `_graph` lookup consumed another 0.214 s; the unchanged solver ran just five times for 0.00318 s. Profile instrumentation inflates these times, especially small Python calls, so they must not be subtracted from actual native wall time. The unprofiled negative kernel measurements and actual negative pair independently agree on the direction. Revalidating and allocating the full strict key costs more than the small amount of repeated search in this trace.

A lazy profitability gate can preserve exact paths by continuing to use the original solver until enough distinct work has accumulated, and constructing a fresh full key before every eventual cross-activation reuse. It must never reuse an old key merely because the preceding activation was similar. Historical runtime counters could select only the computation path, not permissions, routing preferences or clocks. However, such a gate would mainly disable this cache on the present two/three-pair domain; it cannot recover the original solver's own cost and is not a new demonstrated speedup. Choosing a threshold after seeing this window would be a new hypothesis requiring a separate declared domain and both negative and positive cases.

The concrete decision is to keep the current pool disabled. A useful future implementation would first have to show cheaper exact input validation or amortize it over demonstrably more distinct searches; simply increasing hit rate cannot solve this case. The saved 125 ms spikes remain unattributed by this kernel experiment, which also uses a later native026 projection and does not establish that routing caused those earlier spikes. No original-business 100 ms gate changes.

## Batch bytes-key candidate: another retained negative result

The separate [bytes-key candidate](../../scripts/experiments/g31_ics_circulation/regional_path_bytes.py) validates the same exact built-in primitive/finite-number/ID/order domain and serializes only the selected ordered primitive tuple using `pickle.dumps(protocol=5)`. It never unpickles anything and rejects custom types before serialization, so no custom reducer participates. Integer versus float and signed zero remain distinct. Its context temporarily changes the old pool's key function and factory only inside the experiment, restoring both on exit; frozen source files remain unchanged.

[74 pure checks](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_bytes_pure_001.xml) passed: the original 52 differential cases were run unchanged against the new key, plus exact numeric encodings, unsupported domains, custom-reducer exclusion and context cleanup. A separate read-only [source review](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_bytes_independent_source_review_001.json) found no concrete blocker; it did not rerun tests or native.

The [three-arm saved-call comparison](../../benchmark_saved_path_bytes.py) retained all 1,000 real handles and 7,158 actual calls, three rotating arm orders, every path check and GC enabled. [Receipt](../../outputs/experiments/g31_ics_lt2_sustained_20261014/regional_path_bytes_actual_pure_001/receipt.json) SHA256 `16582fb439df5bfc90ac33a79aaae904f35bcf585af40887c558679743428057` reports no source changes or native executions. Median whole kernel milliseconds were original **351.791**, tuple-key pool **896.834**, bytes-key pool **592.127**. The bytes version improved the old pool by 34.0%, but still lost to the original by 68.3%; it lost in every repetition. All counts remained 5 misses, 2,574 cross-activation hits and 4,579 in-handle hits. No higher-query scenario replaced this denominator.

The bytes candidate reduces hashing/comparison and per-numeric helper overhead, but full validation/tuple creation still dominates: under cProfile its key consumed 2.009 s of the 2.084 s kernel. The instrumented times are diagnostic only. This candidate will not receive a native performance run or be enabled. The prior actual negative result remains untouched.

## Remaining cost evidence and next narrow hypothesis

Summing the original actual001 saved API envelopes gives 2,420.076 ms of 10,633.849 ms controller time: 1,230 recent-policy observations cost 2,032.323 ms; 1,000 demand signatures 172.295 ms; 1,876 native advances 100.336 ms; 4,189 request queries plus 824 command queries 52.788 ms. The owner outer intervals sum to 10,242.332 ms, including 2,302.479 ms of nested API envelopes. Their remaining 7,939.853 ms is **unseparated controller, synchronous tape JSON encoding/writing, GC and other Python work**. API timers stop before tape encoding; the difference is not a production-policy cost estimate.

The existing [late003 profile](../../outputs/experiments/g31_ics_lt2_sustained_20261014/late_reconstructed_profile_003/controller.prof) clarifies an apparently larger copy hotspot. Of 13.699 s cumulative `deepcopy`, callers from `run_event_protocol_control` account for 8.669 s and `ProtocolClient.__init__` 3.574 s, chiefly whole-state copies. Current measured streaming paths already pass `_consume_state=True`; these old costs cannot be claimed as a new optimization opportunity. `refresh` accounts for 1.363 s and `_send` 0.058 s. The earlier GC attribution limitations remain as documented in [the streaming report](LT2_NATIVE_TIMING_STREAMING_20261014.md); no old pause is assigned to this later window.

A smaller, testable next hypothesis is a closed shallow-tree copier for the two independent query-view copies in `ProtocolClient.refresh`. All 5,013 actual001 query responses contain immutable scalar top-level fields and, optionally, one `last_delivered_ack` dictionary of immutable scalars. Two independent `dict.copy` results plus independent ACK copies could preserve the current mutation-isolation contract while avoiding generic `deepcopy` per-leaf dispatch and memo allocation. Complex planning payloads, custom types or unsupported structure must fall back to unchanged `deepcopy`; source/state/caller aliases must remain isolated. A separate process-local copy facade could scope this without changing standard-library `copy`, frozen controllers, polling, retries or notifications. This is a proposal, not implemented or measured here, and its potential is substantially smaller than the misleading 13.699 s total. Test it first against the complete real response cohort, without a native worker or a complete-request latency claim.
