# Restricted v3 later projection: conditional data only

The new `public_preexisting_v3_model.py` and
`preexisting_v3_data_adapter.py` extend the existing three-tray, five-job
fixture with an observed moving E tray on either 1→3 or 3→4. They do not
collect native messages, mint a delivery token, certify a current state, or
establish physical protection. The frozen v2 delivery study and its inputs
are unchanged. All supplied-data acceptance and prediction results remain
conditional; missing data stays in the unknown denominator.

The adapter checks the nested unchanged v2 capture and its terminal/action
coverage, the v3 digest and observed-entry identity, source ownership,
generation and public traversal version, causal delivery/ACK times, and the
unchanged 0.05-second age limit. Each deciding owner checks only its own
current view. A peer dictionary is not treated as a native-authenticated
message. A future native collector must bind the accepted version and exact
selected peer message, source self-copy, collection start, and observed
endpoint calls before any online-delivery claim is possible.

Source captures may have different physical epochs; their timestamps are
preserved. The projection requires an explicit conditional policy-quiescence
contract covering the earliest capture through the decision. All five jobs
must already belong to the retained finite population, all completed-prefix
receipts must precede that earliest capture, and source action/fault coverage
must be resolved. An observed moving entry must precede every capture and its
derived exit must be strictly later than the decision. Other tray lifecycle
transitions must be outside the whole capture interval. Native action
coverage cannot certify unsubmitted Python plans or exclude undeclared future
external actions. Equal capture timestamps alone do not establish an atomic
event cut; these checks establish only conditional consistency and stability
of the supplied facts.

The draft2 consumer additionally retains the complete submitted physical
action sets and requires every terminal delivered ACK to be strictly before
the earliest capture. Resolving an action only by a later source's capture
is insufficient: a route update may change preference without changing the
captured lifecycle or prefix. Same-epoch/late ACKs and missing action rows or
times remain unknown; no execution epoch is inferred from the ACK. The saved
`preexisting_v3_action_union_correction_001` is a pure interface counterexample,
not evidence that the fixed native runner reached that sequence.

The predictor reserves the moving tray's target node using the same identity
and physical occupancy accounting, seeds its observed edge headway, and adds
the target service interval when the target is not its destination. It checks
all declared node occupancy and stock, including unrepresented incoming
occupancy, against the full tray set. It preserves the old fixed topology,
protocol, permission, service, scorer, completed-prefix and population guards.
Only an actually moving E can replace the old stationary-only receiver
predicates. Unsupported stationary E lifecycles remain unknown.

Inferring a lifecycle start from its stored finish requires a conservative
floating-point inverse. A simple subtraction can round to the capture epoch
even when a representably later start produces the same stored finish. The
new inverse rounds outward and may reject a boundary-equal valid case; it
does not add a tolerance to the strict per-job protection test. The saved
`preexisting_v3_guard_correction_001` preserves the earlier source and pure
counterexamples before this correction.

Strict coordinate search, plateau coordinate search, pair repair and finite
enumeration receive the same conditional bundle, incumbent, four later
actions, deterministic order and maximum evaluation budget. The later actions
are route 3/8 and return delay 0/0.5. Every method retains unexecuted/unknown
rows and uses all five jobs with exact `candidate <= incumbent` comparisons.
Model-protected predictions are not native protection, and no strategy
superiority follows from this implementation. The earlier 192-row study,
where all strong methods matched and later route 8 was not necessary for any
protected gain, remains unchanged.

The initial guard version passed 60 pure tests in
`preexisting_v3_model_pure_tests_003.xml`. They include asynchronous source
epochs, both supported moving edges and later phases, ownership and identity
mismatch, reservation without observed entry, missing coverage, unresolved
actions, changed own current state, receiving occupancy, unsupported
stationary E with recomputed valid coverage, and exact lifecycle/exit and
floating-point boundaries. The fixtures are supplied native-shaped data, not
recorded v3 deliveries. No native branch or business comparison has been run
with this model. Required next gates are accepted native027 message semantics,
an independently bound actual collector, and a preregistered native prediction
and five-job protection comparison retaining every negative and unknown.

The draft2 consumer and separate collector/runner now pass 107 pure tests in
`native_preexisting_v3_integration_pure_003.xml`, including prior terminal
actions, ACKs inside or equal to the capture-union boundary, missing times,
missing action/coverage rows and retained exact peer action data. This adds
no native execution or physical protection evidence.
