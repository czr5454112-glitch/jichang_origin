# Third-tray native gate, prepared without execution

This is a separately declared synthetic domain with three physical trays and
five protected jobs. The 192 saved pure projections are unchanged. Ordinary
strict coordinate, plateau coordinate, pair repair and enumeration tied in
all six cases. Later route 8 improved the best modeled vector in two cases;
route 3 still allowed protected improvement against the finite fixed-initial
reference. Neither optimizer superiority nor later-route necessity is claimed.

`research_native_preexisting_occupancy.py` prepares a two-stage native025 gate.
The first stage has six normal delivery branches and three missing, expired or
lost-ACK branches. It issues publications only and reports no business gains.
Business execution requires independent verification of all nine saved raw
endpoint records, unchanged source closure, binary identity and configuration
hashes. A successful summary or receipt alone cannot admit it. The second stage has all
six cases and ten arms per case: frozen continuation, all four fixed-initial
E windows, strict coordinate, plateau coordinate, pair repair, enumeration,
and enumeration with the later route fixed to 3. There is no outcome screening.

The native input preparation rebuilds the ten-by-ten service-aware potential
after adding node 9. The earlier pure input retained a nine-row potential,
which its projection did not use. Each corrected native input is saved and
hashed; every loaded project Python source is archived by repository-relative
path, including the absolute preprocessing import and its loaded dependencies.
The worker invalidates changed or newly imported project sources. This is
not an assertion that standard-library and third-party packages are archived.

The revised prepare002 retains each owner's actual local view, queried own
command/ACK and delivered recipient inbox at .11, including negative cases.
Every gzip and saved input has a byte SHA. Before admitting business execution,
the gate reads all nine gzip files, checks their input and archived source
hashes, recomputes capture digests and source coverage, validates exact
publication/ACK/delivery times, and requires the planned negative's exact
failure reasons. Missing peer delivery, expired capture and lost self-ACK
cannot be replaced by a malformed unrelated snapshot. It then compares the
recomputed results with the ledger and receipt. Old prepare001 remains intact.

The 91 pure tests in `preexisting_online_pure_tests_006.xml` passed, including
raw deletion/modification, input alteration, forged ledger flags, wrong fault
substitution, rehashed but invalid raw evidence, and archived source drift.
These tests use declared fabricated data fixtures; they do not authenticate

Each owner independently uses its own observation, delivered peer capture,
and delivered self-ACK. The case parameters are derived from the five actual
captured contracts. A always submits the selected initial route 1 or 2 using
the actual local generation and traversal. Explicit route 1 matters because
the default queue-aware native choice can respond to P's occupancy. B submits
the selected E transfer. An observed mismatch between the two independent
initial decisions is retained as unknown; no centralized rescue or atomic

At the first L return and first loaded reuse, the policies collect new v2
captures with the existing 0.05-second maximum age. The retained initial ledger
provides the complete job contract population; completed jobs require actual
destination-owned terminal receipts. P must be completed and parked at node
9. Unresolved physical actions, moving E, unexplained receiving occupancy,
expired messages and unsupported lifecycle transitions retain unknown input
status. The common explicit local fallback remains return delay 0 / route 3.
Model-selected actions and fallback executions are separately recorded.

All methods receive the same public facts, candidate domains and a maximum
32 model evaluations per decision. All four E windows are separately executed
for the fixed-initial family. Its future actions are freshly recomputed with
the same delivered information and finite model enumeration; this is not a
continuous timing optimum or a commitment to all planned future actions.
Every comparison requires all five physical completions at common H40,
three-tray audit, required delivered ACKs and matching executed edges. One
unfinished job or unexecuted branch leaves protection unknown. The permitted
per-job regression is exactly zero. Prediction error is reported for every
executed branch; the model has no calibrated physical error bound.

## In-flight information audit

Native source inspection establishes the following existing contract:

* `circulation_planning_snapshot_impl.hpp` includes a moving tray while its
  retained `node` belongs to the publishing source. The capture binds tray ID,
  carried job, edge endpoints, generation, public traversal version and the
  committed prefix. Node changes only on physical edge exit.
* `CirculationState::reserve_enter` commits `edge_to` at edge admission.
  `occupancy` counts that destination berth once. A loaded journey has no
  separate empty-transfer request ID for this reservation. The peer's
  `unrepresented_occupancy` is a count, not a new identified lease.
* Source-local `observe_protocol` exposes `edge_exit_at` computed from an
  observed matching EDGE_ENTER receipt plus public edge duration. The v1 body
  nested in v2 does not carry this field or the observed entry time.
* A delivered empty-transfer ACK does not identify a later loaded edge.
  The protocol ACK exposes observed/delivered/received times, not a general
  loaded-edge departure timestamp. Service forecasts are pre-entry estimates;
  publishing one is rejected once the tray is in flight.

`planning_inflight_bounds.py` is a pure diagnostic. An earlier generic claim
that `capture + travel` bounds arrival above is withdrawn: committed `edge_to`
can precede actual EDGE_ENTER, so the capture does not establish an entry-time
upper bound. The old audit001 is retained; correction002 archives its source
and a pure counterexample. Without a matching observed entry, the public-only
diagnostic now returns unknown. It does not infer completion from absence.

An exact source-local current `edge_exit_at` can close that source's own
diagnostic only after matching the current tray/job/edge/generation/traversal/
prefix and checking public minimum journey duration. It cannot silently enter
the other owner's knowledge. The corrected audit002 keeps all twelve saved
branches and twenty-four decisions: the four moving public-only cases are
unknown, while their same-source actual current views still give 7.801 and
match the offline actual exit. All 67 audit checks and 20 corrected pure tests
pass. The old four policy fallbacks remain unchanged. This is not a new online
input adapter and never certifies delivery, future service ordering or strict
protection.

The smallest exact-information extension would capture the already
source-observable matching EDGE_ENTER time (or its derived edge-exit time)
inside a new immutable message version, bound to the same tray/job/edge and
public traversal identity. It would require new native digest/checkpoint/
delivery/self-ACK tests and explicit ABI acceptance. Existing v2, its digests
and all saved evidence should remain unchanged. This extension is proposed,
not implemented or authorized by this document.

No native execution, physical gain, full business-request latency or original
map benefit is established by this prepared gate.
