# Query-copy experiment and remaining complete-request timing gates

The new [query-copy module](../../scripts/experiments/g31_ics_circulation/protocol_query_copy.py) is a pure, opt-in experiment. No native worker was started, no frozen policy or runtime file changed, and the optimization is not enabled by default. It does not certify any original business request below 100 ms.

The closed fast path accepts the four existing native query shapes: `request_id`, `status`, `attempt`, either `kind` or `physical_resolution`, and optionally `last_delivered_ack`. Root fields must be exact immutable built-in scalars and the ACK must be an exact dictionary of scalar values with string keys. Each call creates a fresh root and ACK dictionary. Two calls therefore preserve the existing separation between `row.client_view` and the returned/logged view. Nested captures, custom types, unknown root structure, mutable aliases/cycles and an explicit memo use unchanged `copy.deepcopy`. Only `protocol_control.copy` is temporarily replaced by a private facade; the standard-library module and other controllers remain untouched and restoration runs in `finally`.

[23 pure tests](../../outputs/experiments/g31_ics_lt2_sustained_20261014/protocol_query_copy_pure_001.xml) passed for value/order/identity, two-result mutation isolation, unsupported deep trees, aliases/cycles, custom objects, memo and context cleanup. The [saved-API benchmark](../../benchmark_saved_query_copy.py) then used all 5,013 actual001 query responses: 4,189 transfer requests and 824 commands. Every response was copied twice, with exact ordered values and independent mutable roots/ACKs checked. Under the facade, all 24,571 API calls and both complete controller outputs/state still replayed exactly, excluding the existing closed stopwatch fields. No native seal was recomputed by this pure replay.

[Receipt](../../outputs/experiments/g31_ics_lt2_sustained_20261014/protocol_query_copy_actual_pure_001/receipt.json), SHA256 `a47c123de0200e61bea80e15d09ef3fbad0fa3393b6f0fa12f3a9949e5b1434f`, records unchanged source hashes, GC enabled and zero native executions. The median reduction is 59.568 ms for the entire 1,000-activation query cohort. The last candidate repetition is a real negative tail and remains in the report. Its CPU time was 281.25 ms; this kernel did not capture GC intervals, so its cause is unknown. Do not subtract that repetition, infer isolated hard-realtime behavior, or translate the median kernel ratio into controller/request speed. The absolute saving is too small to justify a new native campaign on its own; the candidate remains optional and unadopted.

The previous larger copy total is not available for a fresh improvement claim. In saved late003, `deepcopy` had 13.699 s cumulative cost, but 8.669 s came through `run_event_protocol_control` and 3.574 s through `ProtocolClient.__init__`, chiefly whole-state copies already avoided by current `_consume_state=True` streaming. Only 1.363 s came through `refresh`, and 0.058 s through `_send`. These instrumented totals are not additive with their parents and do not represent the current native026 window. | --- | --- | --- |
| Actual business admission and causal completion | Owner activations, installed-operation roots and notification/job bundles are explicitly experimental scopes.
