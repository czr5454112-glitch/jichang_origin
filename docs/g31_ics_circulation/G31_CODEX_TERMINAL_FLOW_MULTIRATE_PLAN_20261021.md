## 0. 先执行这些判断，不要重新从零设计

### 0.1 对用户构想的结论

**本轮明确的职责边界：**

- 学习预测层：输出各装载站未来需求的时间分布与不确定性，不输出来源站、订单或真实 tray_id。
- 图优化层：读取预测、当前库存、合法释放、运输时间与承诺，决定来源、目的地、数量和预计时序。
- 订单适配层：形成一批空盘运输订单，统一处理普通回流与提前预置，校验权限并进入现有 ICS 接口。
- ICS/G31：接受合格订单，在真实网络上执行运输，反馈出发、到达、拒绝和失败。

用户把第一层称为 RL。当前 B1 实际是 Gamma-Poisson/CDF 需求预测，并非已有 RL 预测器；第 10 节规定如何保留这个分工、如实命名并检验后续学习方案。此术语差异不阻塞先做图分配与订单闭环。


用户提出的“边表示站点间可达性和距离，在小图上分配空盘”可行，值得推进。

准确名称建议使用：

**有向站点抽象图上的滚动空托盘运输分配。**

该图的边仍连接两个站点，不因跨过多条物理边就成为数学意义上的超边。首版不实现新的 LaCAM 搜索，也不引入超图神经网络。

最短路提供可达性、运输时间和费用；运输优化决定来源与数量；原生控制协议和 G31 完成真实移动。三个职责分开。

### 0.2 当前最值得检验的收益

1. 多个装载站同时缺盘时，协调有限供给，避免先处理一个站就耗尽其他站的唯一及时来源。
2. 同时考虑调出站的后续需求，避免“离得近就拿走”。
3. 把接受中的补给、到盘时间和接收空间计入分配，减少重复补给。
4. 允许不调拨，减少没有服务价值的空驶。
5. 固定图优化与执行层，单独检验更好的需求预测能否改善服务；避免把改调度算法的收益混写成预测学习收益。

151 节点的物理图并不大。不要预设收益主要来自图缩小后的算力节省；真正的机会是决策表示与供需协调。

### 0.3 不提前下结论的事项

- 不宣称 60 秒必然过细。
- 不宣称 300 秒一定提高预测准确率或服务表现。
- 不宣称普通最小费用流精确解决带共享拥堵、FIFO、迟到与随机释放的完整 ICS 问题。
- 不宣称 RL 已经预测出缺盘并取得学习收益。
- 不把“抽象图＋RL＋最小费用流”作为新的通用算法组合；GRAND 已有非常接近的结构，见第 12 节。
- 若同一时刻仅一只合法盘、一个有效目标，运输分配可能退化为已有单动作选择；应报告这种退化比例。

## 3. 两张图各自负责什么

### 3.1 物理图

物理图 G=(V,E) 是实际 ICS：有向输送边、节点服务、容量、FIFO、故障和当前占用仍由原生系统处理。

不替换 G31，不把抽象边当成能瞬移的物理边，不由上层固定整条无冲突轨迹。

### 3.2 站点抽象图

令 Z 为当前物理/业务合同中有调拨意义的站点，包括：

- 行李装载处；
- 卸载后可以释放空盘的位置；
- 合法空盘缓冲和存放处；
- 当前 owner 可以处分空盘、且符合运输接口的其他实际来源。

首版保留真实站点身份，不急于把多个装载处压成一个大区域。两个站点有不同服务、FIFO、方向和库存时，不能只按距离近就合并。

抽象有向弧 (i,j) 表示 i 到 j 在当前公开条件下存在物理路径。每条弧至少提供：

~~~text
source_terminal, destination_terminal
reachable
static_transport_seconds, static_service_seconds
physical_path_reference
topology_version, notified_closure_version
estimate_asof, observation_scope
receiver_type, receiver_space_coverage
~~~

静态时间优先使用现有 PublicTravel 的语义。注意 path 与 complete 是否已经包含源端和目标服务，避免加两次。动态修正只能来自当前可见排队、已实现历史残差或合法消息，不能加入未通知故障。

同一图上 i→j 可达不代表 j→i 可达。不可达弧不进入求解；不能给它一个很大有限值后仍当成可执行。

### 3.3 缓存及物理瓶颈

PublicTravel 当前对象的缓存只属于一个观察/候选调用。新增跨调用缓存必须显式绑定拓扑、服务参数与公开关闭版本；故障、参数变化时失效。

保留 witness path 或路径摘要，用于识别多个宏观 OD 经过同一物理瓶颈。它是估计与诊断依据，不是强制 G31 走该路径的命令。

两条宏观弧共享物理通道时，不能各自获得一整份独立通道容量。首版继续依靠原生准入，并记录可见拥堵费用与执行残差。不得声称只凭站点图就已处理所有冲突。

## 4. 先把“从哪里来”算对

### 4.1 当前没有 B1 预测时，空盘已经怎样回流

已核验的真实链条如下。[C4–C5、C10、C13–C15]

1. **卸载完成后**，托盘经过必要 hold，变成 empty，留在实际卸载节点；代码没有让它自动返回原始装载口。
2. **本地真实行李先用盘**：原生先按到达 FIFO 为已等待行李分配本地可用盘，再考虑可选调出。
3. **跨位置的实际需求补盘**：当前可见的真实排队需求，由上层匹配合法空盘来源并生成 transfer；不需要 B1 才能工作。
4. **必要腾位**：当已知载货任务将到达而卸载端需要腾空间，terminal clearing 生成反应式空盘转出；这是现有普通运行能力。
5. **普通回流**：优先需求处理后，stock_return 开启时，非 loader 来源的空盘回到合法装载处。旧 R0 优先选择已知库存少的目标，再比较静态耗时；完全没有有效目标库存信息时，普通回流可退到最近合法可达 loader。
6. **装载口之间的当前平衡**：在源端保留条件满足时，旧 R0/C00 可以向已知零库存装载处补给。当前 C00 也保留 ordinary return，不会因没有 B1 就把空盘全停住。

最新 C10 已可利用预测改善普通回流的目的地选择。因此新工作不是首次发明空盘回流或 transfer，而是增加多个来源/目标的数量协调、订单时间语义和时间尺度验证。

不同开关不要混淆：

| 设置 | 含义 |
| --- | --- |
| 使用不读 B1 的 C00/R0 | 保留实际需求补盘、必要腾位和普通回流 |
| controller 的 forecasts=False | 主要关闭服务预测发布，不自动关闭 C10 单独调用的 B1 |
| stock_return=False | 关闭优先任务后的库存回流/预调入口，实际需求补盘仍可存在 |
| prebalance=False 或停止上层控制 | 对应上层 transfer 决策不再生成；原生本地装载和已承诺运输仍是不同机制 |

主实验的“无预测”基线应保留正常回流。禁止关闭正常回流后让新方法与一个人为瘫痪的基线比较。

### 4.2 四类来源

| 来源 | 是否可立即作为供给 | 处理方式 |
| --- | --- | --- |
| 卸载点已空闲的盘 | 通过当前资格检查后可以 | 优先纳入完整合法来源集合，不强制优先选择 |
| 装载点的富余空盘 | 满足硬保留、优先业务与 FIFO 后可以 | 计入调出地自己的后续需求损失 |
| 缓冲/其他合法位置的空盘 | 取决于 owner、接口、权限与可达性 | 复用现有共同菜单 |
| 当前载货、预计稍后卸载的盘 | 不可以立即派出 | 作为未来条件释放信息；真正释放后才能绑定原子动作 |

“从哪里来”的答案不是固定选某类站点，也不是总选最近站。应联合比较可调数量、到达时刻、来源机会成本与所有接收站的需求。

### 4.3 三个账本与唯一物理身份

1. **当前事实**：实际可见空盘和当前等待。
2. **已接受义务**：已获协议接受、尚未到达的调拨，带 tray_id 和 ETA。
3. **条件信息**：当前合法载货任务导出的下一次卸载释放，以及新增行李预测。

一个 physical_tray_id 只沿一条状态链出现：

~~~text
当前空闲 → 已接受调拨 → 在途 → 接收后空闲 → 装载忙碌 → 卸载释放
~~~

已接收盘一旦进入当前快照，就从未来到盘表移除。pending 仅作请求去重/占用状态，不等于已接收库存；当前已经承诺的盘不能再当自由盘。

### 4.4 可调上限与当前菜单

用于解释的来源上限为：

\[
S_i=\min\{N_i^{\mathrm{actual,uncommitted,eligible}},(I_i-r_i)_+\}.
\]

这里 r_i 是现有硬保留量。实现时必须调用已有资格逻辑，不能只靠这条计数公式代替 FIFO、优先任务和租约检查。

分别记录：

- 当前这一决策机会真正合法的 tray_id 集合；
- 公开 FIFO 队列中可能在后续机会变为可调的盘；
- 未来条件释放的盘。

后两者只能提供带时间的建议供给，不能混入当前原子菜单。若合法观察不能证明某站未来可调 3 只，就不要输出确定可执行的“该站发 3 只”。

当前 Python 候选并不是每个源只保留一只队首空盘：它在保护本地 FIFO 行李所需盘和最低库存后，会列出全部真实未承诺余盘。物理 FIFO 与每 owner/tick 一次提交是另两种限制。不可为了数量分配而放宽这些限制。

### 4.5 预测优先改变尚未承诺的回流去向，再考虑额外搬动

例如卸载点 U 刚释放 2 只盘，普通规则准备回 A，而预测表明 B 将缺盘。图优化可以直接产生 U→B 的回流订单，不应先 U→A、再 A→B。

实现要把两类作用分开统计：

- **预测引导普通回流**：该盘本来就会回流，只改变尚未承诺的目的地/数量分配；
- **额外提前预置**：把已经位于某个装载站或缓冲点的富余盘重新分配。

这两类订单共用供给，不是两套可以各下一个订单的任务源。若旧普通回流已被原生接受，新的预测只能把它算成既有承诺，不能取消后重新计为自由盘。

保留原有必要腾位与普通回流优先语义作为第一版合同。含 HOLD 的优化作用于可选部分；不能因为短时预测没有正收益就静默取消原来需要完成的普通回流。若未来要把“普通回流是否发生”本身也优化，另立桥接版本，与原合同公平重比。

## 5. 从未来行李需求转为补盘价值

### 5.1 不直接令“补盘数＝未来行李件数”

未来 10 分钟预测 20 件行李，不意味着现在要补 20 只盘。需要同时考虑现有库存、接受中的到盘、装载服务速度、需求先后、卸载释放以及盘的周转。

保留当前短时单次使用代理作为第一版基线：每只盘被一次预测装载消耗后进入忙碌状态；没有合法未来 OD 和释放模型时，不自动几分钟后返回原装载处。

这不是完整循环模型。长期真实循环影响在原生续行中验证。预测模型可利用合法历史到达与释放信息改进估计，但本轮不通过学习动作 Q 绕开图优化器。

### 5.2 短时代理接口

优先扩展现有 foundation_airport_inventory_projection.py：

~~~python
build_station_projection(public_state, forecast, supply_mode, horizon_seconds)
evaluate_station_loss(projection, added_supply_events, removed_supply_events)
~~~

第一版仍固定：

~~~text
forecast_horizon_seconds = 1800
projection_horizon_seconds = 600
supply_mode = committed_only
~~~

条件下一次释放先做独立版本/消融，且所有被比较方法共享该信息。不要一边加预测释放、一边改分箱再把全部收益归因于图优化。

一个简化的时间守恒关系：

\[
I_j(t')=I_j(t)
 +A_j^{accepted}(t,t')
 +A_j^{plan}(t,t')
 +R_j^{conditional}(t,t')
 -Y_j^{load}(t,t')
 -X_j^{depart}(t,t').
\]

其中条件项是否启用由合同决定；装载量受可用库存和服务限制，不允许负物理库存。R 的同一盘只能在真正进入下一可用阶段时计算一次。

### 5.3 缺口与边际价值

以现有全人口等待/积压目标的局部短时代理 L_j 为基底，计算：

- 给目标增加第 k 只盘的预计短时损失下降；
- 从来源移走第 k 只盘的预计短时损失上升；
- 到达太晚、装载服务已饱和或已有充分在途补给时，边际收益降低。

需求保持期望质量或校准情景。不能对每个小箱的 0.2 件各自向上取整成 1 件；否则箱越细，虚构出的需求越多。

未知库存、等待或接收空间应输出 coverage/missing。未覆盖站点不能因被填零而获得虚假的“最紧缺”排名。

## 6. 第一版：可选整数运输分配

### 6.1 直观运输模型

令 x_ij 为本轮建议从 i 向 j 调的整数盘数，S_i 为可调上限，d_j 为通过同一短时代理得到的目标补给量，u_j 为无法满足的缺口：

\[
\min_{x,u}\sum_{ij}c_{ij}x_{ij}+\sum_j p_j u_j,
\]

\[
\sum_j x_{ij}\le S_i,\qquad
\sum_i x_{ij}+u_j=d_j,\qquad
x_{ij},u_j\in\mathbb Z_{\ge0}.
\]

这只是帮助解释的固定缺口版本。d_j 不是未来行李总量，p_j 不是为了强迫搬运而设无限大；若收益不足，可保留空盘与缺口。

同时对所有有合法信息的目标分配。不要先锁定“最紧缺的一个目标”，再把全部供给都给它。

### 6.2 推荐实现：边际价值形式

本节网络仅作用于第 6.3 节扣除受保护回流/真实需求后剩余的可选资源；因此“全部 HOLD”只表示本轮可选预置为零，不表示关闭普通回流。

对补给收益 U_j(n)、来源损失 O_i(n) 与运输费用 c_ij 求：

\[
\max_x
\sum_jU_j\!\left(\sum_i x_{ij}\right)
-\sum_iO_i\!\left(\sum_jx_{ij}\right)
-\sum_{ij}c_{ij}x_{ij},
\]

满足来源上限、目标可接收上限、可达性、合法范围和整数约束，并始终允许 x=0。

若 U_j 是离散递增凹函数、O_i 是离散递增凸函数，可以展开：

\[
u_{j,k}=U_j(k)-U_j(k-1),\qquad
o_{i,k}=O_i(k)-O_i(k-1).
\]

使用如下网络：

1. 超级源点向来源 i 提供 S_i 单位流；
2. 来源 i 有直接通向汇点的 HOLD 弧，费用 0；
3. 来源 i 经容量为 1、费用 o_i,k 的单位弧进入调出端；
4. 调出端经有向站点弧进入接收站 j，费用 c_ij；
5. 接收站 j 经容量为 1、费用 -u_j,k 的单位弧流向汇点。

总流量设为所有 S_i 的和；留在原地的流经过 HOLD，不发运输命令。只有经过站点调拨弧的流生成 x_ij。

来源损失递增、接收收益递减时，单位弧自然遵循正确边际顺序。收益不支持调拨时，全部流可走 HOLD。显式检查负费用与残差逆弧的求解正确性。

如果原始代理曲线不满足这些性质：

- 记录违反幅度；
- 可以用明确版本的单调凹/凸近似生成分配建议；
- 输出近似误差，逐步用原代理复核；
- 不能声称近似后的最小费用流精确优化了原非线性目标。

22 盘下优先复用现有网络流原语或已有依赖；只有确有需要再增加依赖。不要为此引入大型商业求解器作为必需组件。

**逐盘资格不能被来源计数丢掉。** 同一站点的盘若具有不同 owner、承诺依赖、合法目的地集合或可用时刻，不能全部压成一个可互换的 S_i。首版可在调出端后加入容量为 1 的真实 tray 节点，只连接该盘合法的目的地；每只盘只能出现一次，并保留站点总调出上限。也可按完全相同的资格集合分组，但必须在生成订单前证明存在合法逐盘整数匹配；匹配失败则回到分配器重算，不能先发再补资格。

### 6.3 接收上限与同站流

B_j 必须与实际接收空间、接受中的义务及信息覆盖一致。当前接收容量和未来可能腾出的空间分开。

HOLD 表示本轮不新增运输；若网络使用 i→i 自流表示保留，也不得把它提交成一条真实调拨。

真实需求补盘、必要腾位与普通回流的资格/优先类别，先按当前合同确定；其供给和已接受义务从可选余量中扣除。同一物理盘不能同时属于两层。

实现可分两步：先为当前受保护的回流类别选择合法图边与目的地，再对剩余可选资源求含 HOLD 的运输分配。若采用这种分层分配，应如实称分层代理解；不要宣称它等于不带优先类别的全局运输最优解。

在当前 post-priority 入口只允许一单时，若原合同要求优先 ordinary return，第一条子订单必须来自该类别；后续数量是带未来提交槽位的建议。无 ordinary return 时，剩余可选部分才可以全部 HOLD。

### 6.4 单时点模型的时间限制

单时点 U_j(n) 不能精确表达“同样一只盘，2 分钟到与 8 分钟到”的不同服务价值。

第一版必须登记共同参考可用时刻、费用中的延迟近似，以及逐动作的精确 ETA。对选中的首动作使用现有精确事件库存代理复核，检查到达前不能增库存、源端先扣除与近期价值。

此复核是公开状态下的代理检查，不是真实未来的服务保证。若候选未通过，记录拒选原因，按冻结规则回退，保留同一次提交额度。

晚于首次缺盘不等于永远无价值；它可能减少后续等待。若某条弧赶不上一个时段，可转入后续时段评价，不应统一永久删除。

### 6.5 时序诊断触发后，升级少量时间层

出现以下任一情况时，在相同信息与接口上实现时间展开版：

- 来源 ETA 差异持续改变首动作；
- 运输时间与需求箱宽相当或更长，单时点排名不稳定；
- 多盘计划的首批到达时间被系统性低估；
- 条件释放和接收空间的时间变化决定动作是否有价值。

时间层节点为 (站点, 时刻)。加入等待弧、带旅行延迟的调拨弧、当时才能进入的供给事件。只在真实预计可用之后计入目的地。

首轮保留 600 秒主代理，不直接扩展为全天时空网络。若更长运输/循环确有必要，再在开发集登记 900/1800 秒视野对照，独立于箱宽实验。

在一般代理模型中加入任意跨 OD 共享物理瓶颈约束，可能破坏普通网络流结构和整数性。若改用整数规划或近似协调，应明确命名与求解误差，不能继续称纯 MCF 精确解。

## 7. 多盘配额如何落实为原子动作

### 7.1 分配结果是建议，不是运输事实

建议数据结构：

~~~text
plan_id, version, owner_scope, information_asof, plan_valid_until
forecast_id, mapping_id, travel_version, projection_version
source_terminal, destination_terminal, suggested_quantity
earliest_departure_profile, estimated_arrival_profile
marginal_gain_profile, assumption_flags
already_accepted_quantity, pending_request_ids
execution_status, rejection_reasons
~~~

每条计划分别记录 proposed、submitted、accepted、departed、received。各阶段数量不能互换。

### 7.2 一个 owner 的 3 只盘不会同时发出

当前每 owner、每 60 秒 tick 最多一次新可选提交。若当前 tick 可以发第一只，第 r 只的计划提交时刻至少受到：

\[
t^{submit}_{o,r}\ge t^{next\ eligible\ tick}_o+(r-1)\Delta_{control}.
\]

随后还要加命令延迟、FIFO 可释放时刻和运输时间。真实优先业务、拒绝和恢复可能进一步推迟，因此这是乐观下界，不是保证。

若采用未来多盘建议，输出数量必须附带这样的派出序列。禁止把 x_ij=3 解释成 3 只都在 t+2 秒发出。

不同 owner 可以各用自己的合法额度；不能把跨 owner 的并行能力转借给同一个 owner。

### 7.3 控制流程

1. 按现有合同处理真实 priority 和恢复。
2. 刷新当前 owner 公开观察。
3. 构建原有完整合法单动作菜单。
4. 从有效计划或本轮重新求解的计划提取下一条建议。
5. 绑定一个当前实际合法 tray_id；重新校验源保留、FIFO、目标空间和消息时效。
6. 选择一条或 no-op，提交前消费当前 tick 配额。
7. 接受后进入真实承诺账本；未接受则记录真实拒绝，不能立即另取一只重新提交。
8. 后续机会根据状态更新剩余计划，过期且尚未提交的建议可以本地撤销；已提交但未收到 ACK 的请求继续确认，只有权威拒绝/取消回执才能释放占用；已接受义务按原生状态机履行。
9. 计划、预算、去重、承诺与必要策略状态进入现有恢复机制。

多盘组合的收益不一定等于独立单盘收益之和。图优化器生成明确代理下的数量计划，订单适配器按现有准入逐条提交；同时记录计划与实际执行差异。本轮不存在另一个 RL 动作选择器覆盖图优化结果。

### 7.3.1 首条订单选择和回退必须可复现

把以下规则实现为图调拨策略/订单适配器的一部分，不新增学习动作选择器：

1. 保留当前合同规定的优先类别；有受保护 ordinary return 时，首条候选限定该类别。
2. 只检查当前 flow plan 中数量仍为正、且当前真实单动作菜单存在的条目，绑定合法 tray_id。
3. 使用精确预计派出/到达事件计算当前一条订单的公开短时边际收益，按净收益降序，再按目标剩余裕量、预计到达、source、destination、tray_id 的稳定序排序。缺失收益单列，不当作极高收益。
4. 额外可选预置只有净收益超过冻结非负阈值才提交，否则 HOLD。
5. 若计划条目全部失效且当前合同仍有 ordinary return，应重新求解该优先类别；求解失败/超时才使用已登记 C00 的当前库存/耗时回流规则，并标记 fallback。没有受保护回流时 HOLD。
6. 选择/精确代理检查尚未占用真实提交额度；一旦 submit 被调用，拒绝或异常后不得同 tick 另发新请求。

该规则的选择与回退次数均报告。不能在看到事后真实收益后更换首条订单。

### 7.4 防止多个来源重复满足同一缺口

已有物理接收容量检查不必然等于“预测需求已被别的 owner 覆盖”。在复用现有 ACK/receiver reserve 的基础上，补足逻辑分配去重：

- 接收方对一个有效预测版本发布可补给量或需求槽位；
- 槽位带 destination、epoch、allocation_valid_until 和唯一身份；该有效期不同于原生出发租约；
- 源方保留唯一 tray 身份，接收方确认同一槽位的唯一承诺；
- 接受中的补给扣减目标剩余缺口；
- 请求失败、出发租约过期和接收完成依据原生权威回执更新状态；上层计划过期只释放尚未提交建议，不释放 pending/accepted 实体承诺；
- 重试沿用请求身份，不新增逻辑配额。

优先复用已有协议字段；仅新增必要的分配语义，不另写完整共识系统。

### 7.5 空盘订单已存在：复用原生 CirculationTransfer

当前原生已经区分业务行李 CirculationJob 和空盘调拨 CirculationTransfer。后者无业务 deadline，进入底层时形成 kind=empty_return、job_index=-1 的运输段，底层请求 deadline=-1。[C14–C15]

因此不用向 28,506 件业务 jobs 中插入虚构行李。直接复用：

~~~text
图优化的来源/目标/数量
→ 空盘父计划
→ 逐只 CirculationTransfer
→ empty_return 运输段
→ 现有 G31 物理执行
→ EMPTY_RECEIVED / 失败与恢复回执
~~~

底层共用移动宿主，并不等于空盘运输变成了业务行李。行李完成数与空盘运输完成数必须继续分开。

统一订单元数据建议为：

~~~text
order_type = EMPTY_TRAY_TRANSFER
reason = REAL_DEMAND_SUPPLY / NECESSARY_CLEARING /
         ORDINARY_RETURN / FORECAST_REPOSITION
~~~

同一订单可附 forecast_guided=true 表示普通回流的目的地由预测决定；不能因此再创建第二个订单。reason 解释目的，physical_tray_id 和 request_id 才约束实体与协议身份。

新增 plan_id、target_by 等字段先保存在上层计划/元数据中，通过原生已经支持的字段适配，不未经登记向底层强塞未知 schema 字段。

### 7.6 无业务截止时间，但有软到达目标和独立租约

**推荐：空盘运输继续没有行李式硬 deadline；上层增加需求驱动的软到达目标，保留原生出发租约。**

| 字段 | 用途 | 到时如何处理 |
| --- | --- | --- |
| target_by | 预计应在何时到位，避免目标开始缺盘；属于软服务目标 | 晚到重新估值，仍可能有益，不直接删除实体订单 |
| useful_until | 本次预测窗口内已知需求价值的参考末端 | 未提交部分重新计算；不据此撤销已承诺运输 |
| latest_issue_estimate | 按派发排队、命令和运输时间推算，为赶上 target_by 最迟何时应提交 | 诊断可能赶不上；不是一过时就硬禁所有晚到补给 |
| plan_valid_until | 尚未提交建议可保留的最长时间，受预测、库存、消息和规划周期约束 | 只让未提交建议失效/重算 |
| native expiry | 现有出发租约，限制过时请求迟迟不进入物理运输 | 按现有原生状态机处理，不作为业务到达期限 |

估计：

\[
latest\_issue\_estimate
=target\_by-\widehat{T}_{queue+command+travel+ready}.
\]

必须避免重复计算：若 static_travel 已包含某站服务时间，不在 ready 项再加一次。

target_by 可取预计缺盘开始时刻，或每个新增补盘单位的需求槽位时间；同一批 3 只盘可以有不同的软到达目标。它来自当前可用预测，不是事后真实行李到达时间。

当前 Python joint 候选用“预计命令生效时间＋静态运输时间＋60 秒 slack”构造 expiry，但其原生含义仍是**出发租约**。第一版保留原生算法与语义，不能把它改成 target_by，更不能设无穷大绕过租约检查。[C4、C14–C17]

在途订单可超过 target_by 或原出发租约的时刻后到达；是否继续有收益由评价反映，物理承诺不会凭预测消失。

### 7.7 订单生命周期与预测更新

沿用原生实际状态，允许上层建立下面的语义映射：

~~~text
PLANNED → SUBMITTED → ACCEPTED / DISPATCHING → DEPARTED → RECEIVED
~~~

不要用此示意重命名或覆盖原生状态。具体规则：

1. 未提交 PLANNED 可以因预测更新而 SUPERSEDED/EXPIRED；释放的是建议配额，不是已存在的原生承诺。
2. SUBMITTED/PENDING_ACK 不能因 plan_valid_until 到期就本地释放盘。对端可能已接受但 ACK 未到，必须复用 request_id 查询/重试或取得明确取消/拒绝回执。
3. 原生当前仅允许在 undelivered/pending 等未承诺阶段显式取消；已经承诺会返回 already_committed。首版不新增接受后的自动改派。
4. ACCEPTED/DISPATCHING 尚未真正进首条物理边时，可能因原生 departure lease 过期而失败；必须消费真实失败回执和恢复流程，不能继续把它算作准时到盘。
5. DEPARTED 不因出发租约或预测到期而被上层静默撤销；接收空间义务保持到实际接收，除非原生明确发生别的失败并进入其处理流程。
6. RECEIVED 才把盘变成目的地当前实际空盘；同时移除同一盘的未来到盘项。
7. 失败盘可能 quarantined，不能自动回到自由库存。现有 recover_failed_empty 仅在其规定的失败类型和物理身份检查通过后恢复。

接受中的普通回流、真实需求补盘和预测预置都计入同一个目标供给账本。预测版本改变不重置真实订单。

### 7.8 订单优先级：区分发单和物理执行

发单阶段沿用现有顺序：

- 安全、恢复、必要腾位与真实需求优先；
- 普通回流保留其当前合同；
- 额外预测预置使用剩余合法机会。

图优化决定可调资源如何分配，不越过正在服务的真实行李和已接受承诺。

物理执行阶段保持现有 G31/FIFO/准入机制，不设置“所有空盘永远低于所有载货盘”的新绝对规则。真实行李缺盘时，空盘运输本身就是其服务前提；该规则会形成长期饥饿。

target_by 首版只在上层分配、顺序和过时计划判断中使用，不写进 native 的业务 deadline。若将来需要修改底层优先级，必须单独比较其收益和损害，不能混入本轮图优化收益。

### 7.9 时间语义示例（说明用，不是机场实测）

现在 10:00，预测装载处 D 在 10:08 开始缺盘。图分配建议 A→D 1 只、B→D 2 只。

- A、B 是不同 owner 时，可以各使用当前一次合法提交机会。
- B 的第二只至少等到下一控制 tick；当前 60 秒控制周期下，不能与第一只同时按 10:00 出发计算。
- 三只盘的 target_by 可以先设 10:08，也可按各自预计需求时间设置不同目标。
- 未提交的第二只如果在 10:01 新预测中已不需要，可以从父计划移除。
- 已接受/在途的 A 那只继续履约，不能因预测变更瞬间恢复成 A 的自由盘。
- 某只预计 10:09 才到，但 10:09 后仍有需求，可按剩余收益继续发；迟于 target_by 不等于永久无价值。

因此“无业务 deadline”不会变成“过时订单可以无限生成和占用资源”。

## 8. 分布式边界与 R1 衔接

### 8.1 第一版的权限范围

每个 owner 的立即可执行供给只来自自身权限内的盘。可见远端库存并不等于有权直接派出远端托盘。

若先实现一个汇总公开消息的协调器，准确称为“上层协调、区域确认、底层去中心化执行”。不要称整个系统已完全去中心化。

默认生产路线优先做区域有权限范围内的滚动流分配和接收方去重；集中全局解可作同信息诊断基线。隐藏全局状态只可在离线上界实验使用，并单独标为 oracle。

### 8.2 保留 R1，先隔离再组合

## 9. 时间粒度：把四类参数拆开

### 9.1 当前总时长不能决定合适箱宽

当前运行 16.5 小时；即便将来跑完整 24 小时，60 秒也不自动太细。应看站间 ETA、源端耗尽时间、需求脉冲持续时间、单站需求密度与不确定性。

当前 1800 秒预测视野在 60 秒下只有 30 个箱，600 秒库存代理只有 10 个箱。不要把它误认为每次优化整个 16.5 小时的 990 个箱。

### 9.2 参数必须分别登记

| 参数 | 当前/首轮处理 | 后续候选 |
| --- | --- | --- |
| 物理事件时间 | 保留原生精度 | 不随本任务粗化 |
| 控制与协议 tick | 首轮仍 60 秒 | 若要变更另立合同 |
| B1 预测视野 | 1800 秒 | 本轮箱宽实验固定 |
| 库存代理视野 | 600 秒 | 有证据再独立比较更长视野 |
| 未来需求箱宽 | 60 秒历史参照 | **300 秒重点候选**；600 秒仅作粗化敏感性 |
| 预测刷新 | 现在按合法 policy 回调计算 | 独立研究缓存与有效期 |
| 分配重算周期 | 首轮跟随原机会，先隔离算法差异 | 后续 60/300 秒加同合同事件失效 |

第一轮只改变箱宽，不改变控制 tick、派出配额、信息送达或物理时间。第二轮固定箱宽，再改变上层重算周期。

### 9.3 先复用同一预测，再考虑重新拟合

B1 当前由航班条件计数模型和到达 CDF 得到质量，prepared adapter 硬编码了 60 秒。

先实现统一接口：

~~~python
forecast_at(..., bin_edges_seconds=edges, horizon_seconds=1800)
expected_arrivals(interval_start, interval_end, owner, station)
~~~

以同一冻结 B1、同一航班信息、同一 loader mapping 生成 60/300/600 秒表示，或将连续五个 60 秒箱求和为 300 秒箱。

必须满足：

- 总需求质量守恒；
- 第一个/最后一个不完整箱的处理明确；
- 300/900/1800 秒累计特征的算法与语义登记；
- CDF 区间查询与箱内均匀化近似分开，不能粗箱组偷偷保留更细的额外未来信息却称纯粗粒度；
- 供给 ETA、请求时刻与真实到达不取整到箱首；
- 共享潜在强度导致箱间相关时，不直接相加区间上下界或假定方差独立；使用模型的累计区间不确定性或明确近似。

先比较“表示/近似变化”，再考虑新的拟合方式。仅改变输出分箱未必需要重新训练整个模型。

### 9.4 必要时使用近细远粗

若 300 秒均匀箱造成近端断供判断变差，测试：

- 0–5 分钟：60 秒箱；
- 5–30 分钟：300 秒箱。

该方案总共 10 个需求箱，保留近端响应，减少远端分辨率。仍属于待验证设计，不预设最好。

另一种简化是按当前候选 ETA 与少量固定未来窗口查询 CDF 累计需求，不在 actor 中维持不必要的密集输出。它与“整箱均匀化”是不同近似，应单独登记。

### 9.5 分配缓存与事件失效

将上层重算周期候选设为 300 秒时，原控制循环与真实需求响应保持原精度。库存耗尽、实际到盘、重大新需求、已通知故障、接收容量变化、计划/消息过期等事件使相关计划失效。

失效可以只对受影响 owner/站点重算。必须给出防抖或每 tick 合并规则，避免所有观察变化都触发全图重算。

对缓存报告计算耗时、数据年龄、计划年龄、失效次数、命中率和回退，不只报告单次神经网络推理耗时。

### 9.6 选择标准

先从已完成 TRAIN 原生轨迹统计：

- 真实/预计空盘转运时间的 P50/P90/P95；
- 调拨排队至提交和提交至到达的分解；
- 装载站首次短缺提前量与持续时间；
- 源端有盘到耗尽的时间；
- 每站 60/300/600 秒计数分布与零质量比例；
- 预测生成、特征、分配求解、提交各阶段耗时。

再在固定开发父场景比较：

- 相同 5/15/30 分钟窗口的预测误差；
- 缺盘开始时刻/提前补给是否被判断错；
- 完整物理窗的等待/积压、准时与完成服务；
- 空驶、重复补给、源耗尽和尾部损害；
- 算力与信息陈旧度。

不同箱宽的原始单箱 MAE 不能直接横比，粗箱误差数值更小/更大都不能单独证明模型更好。

优先选择满足原服务合同、真实指标有益且计算更稳的粒度。若证据无显著差别，应报告不确定，并按预登记的简单性/耗时原则选取，不能包装为算法收益。

## 10. 预测学习的位置：遵守用户的新分工

### 10.1 预测接口与调度权限

预测层固定只输出：

~~~text
forecast_id, owner_scope, issued_at, valid_until
time_edges, destination_station_or_region
expected_arrivals, uncertainty_or_quantiles
mapping_id, available_at, information_coverage
~~~

预测层不输出 physical_tray_id、source、transfer_request、调拨矩阵或真实运输命令。库存是否短缺由图优化前的库存投影结合供给推导；需求旺盛与托盘缺乏不是同一个量。

图优化器是新方案唯一的来源—目标—数量决策者。若输出多盘订单，后续的安全/协议校验可以拒绝不合法订单，但不能再由一个未登记的 action-Q 策略把它换成另一运输计划。

### 10.2 如实处理“RL 预测需求”的技术含义

当前 B1 是统计需求预测模型，旧 C01/C11 是动作价值学习；它们都不能直接改名为已实现的“RL 需求预测”。

本轮先用已存在 B1 打通新架构，并保留用户希望研究的学习预测环节。预测模型的首要验收是到达量/时间分布的误差、校准和下游服务价值。

后续若采用真正 RL 训练预测层，必须先给出可运行、可解释的合同：

1. 状态只能含当前合法航班计划、已到达历史和已完成预测误差等；
2. 动作只能修改未来需求分布/校正参数，不产生来源、调盘数量或运输订单；
3. 标签在对应未来窗口实际结束后成熟，不能提前回填当前观察；
4. 奖励明确区分预测误差/校准与通过固定优化器产生的服务反馈；
5. 状态转移、延迟奖励、更新方式与终止定义真实存在，并与监督预测强基线比较；
6. 冻结图优化器、订单时间规则及执行权限后，才能将收益归给预测学习。

若奖励只是外生行李到达的预测误差，而预测动作并不改变后续信息或可观测过程，该学习通常更接近监督预测/上下文决策，不能为名称硬造多步 RL。

若把系统等待直接当奖励，模型可能通过夸大某站“预测需求”来暗中操纵分配。必须同时保留预测校准检验；若输出实际变成调度偏好或风险调节值，应另名为决策风险信号，不能继续解释成真实期望需求，也不能绕过用户规定的优化层职责。

不要让上述算法命名讨论阻塞 P1–P3 的实质实施。也不要为了保留“RL”称呼复用旧 action-Q 直接选盘。

### 10.3 新比较组

旧 C 组保留原含义。R0-legacy 只作额外历史桥接，不能与 C00 混名。新阶段以固定优化/执行层做以下比较：

| 配置 | 未来需求输入 | 站点图配给 | 目的 |
| --- | --- | --- | --- |
| R-current | 固定为现有 C00 当前信息规则 | 原实现 | 保留正常回流的有效基线 |
| R-B1 | 固定为现有 C10，B1/映射与 TF-B1 相同 | 原单动作规则 | 隔离增加图配给结构的收益 |
| TF-current | 无新增未来需求预测；保留当前需求与正常回流 | 有 | 分配结构增量 |
| TF-B1-60 | 同一冻结 B1，60 秒箱 | 有 | 预测信息增量 |

另可做离线 oracle 需求诊断上界，但未来真值不能进入上述可部署组。

所有组共享合法来源、权限、源端保留、普通回流、请求额度、物理底座和评价窗口。无预测组不通过预测剪枝/排序后的菜单获得未来信息。

### 10.4 预测学习的最低证据

- 输入合法可用，预测训练/校准仅用 TRAIN；
- 标签是实际到达量与时序，不是自己生成的调拨指令；
- 预测质量以相同窗口、相同站点和相同人口比较；
- 冻结分配器后，预测差异确实导致了不同的数量/时序订单；
- 订单被实际接受并执行，完整轨迹的服务变化可复算；
- DEV 选择与 TEST 比较按父谱系隔离；
- 如称 RL，另外给出其状态—预测动作—成熟奖励—更新链及监督学习对照。

预测更准却服务不变，可能是没有可调盘、运输赶不上、服务瓶颈或订单被既有任务占满。先诊断这些情况，不把预测接口偷偷改成调拨动作接口。

| 场景 | 必须验证 |
| --- | --- |
| 没有必要/普通回流，且可选补给收益低于运输成本 | 可选部分全部 HOLD；不因最大流目标强迫搬盘 |
| 两源一目标，近源自身将短缺 | 来源机会成本可改变选择 |
| 两目标竞争一个及时来源 | 联合分配不重复使用该盘 |
| 一站建议发 3 只、每 tick 只能发 1 只 | 派出时间按序延后，执行配额未增加 |
| A→B 可达、B→A 不可达 | 保留方向，不输出反向调拨 |
| 两个宏观 OD 共用瓶颈 | 不虚构独立容量；执行冲突与 ETA 残差可追踪 |
| 已接受的盘到达并进入快照 | 当前库存与未来义务不重复计算 |
| 载货盘 4 分钟后才释放 | 当前菜单不能选择它 |
| 接收消息过期或库存未知 | 标记缺失，不能把未知按零创建高收益 |
| 60 秒质量聚合成 300 秒 | 总质量相等，不逐箱向上取整 |
| 同一预测总量但箱内尖峰不同 | 记录粗化误差，不能默认所有盘先于需求到达 |
| source/receiver 拒绝或 runner 恢复 | 不重复请求、不新增额度、不丢承诺 |

### 11.2 指标

主指标沿用登记的全人口积压积分、完成、准时与逾期未完成；输出每父场景配对差值，不只给整体百分比。

新增机制指标：

- 可选机会数、可调来源数、多目标竞争比例；
- 多盘计划中真正完成接收的数量与比例；
- 计划数量/提交/接受/到达分母；
- 来源耗尽、重复补给、反向空驶；
- 派出序列与实际提交延迟；
- ETA 偏差、共享瓶颈压力、载盘服务损害；
- 规划、特征、预测、准入及恢复耗时；
- 消息与计划年龄，缓存失效和回退原因。

原生行李/任务统计与内部 segment 计数分开；未完成业务继续按原有限窗合同计费。墙钟超时不是正常物理终止。

### 11.3 资源与持续推进

不重新开启一份 160 支/48 小时预算。先计算旧账本剩余，按完整比较块安排新阶段。使用旧任务允许的预算修订时，先登记原因、未启动额度的去向和保留测试规模，不修改已完成记录，也不热改活动 runtime。

建议的第一个原生块是：在同一开发父场景比较原规则与 TF-current/TF-B1-60；逐父扩展到现有四个开发 parents。旧结果不能等价复用时，基线重跑也计入预算。粒度先用两个候选，避免无效笛卡尔积。

代码实现、已保存观察的离线分配、时间统计和小规模机制验证可以先持续完成。新的长运行在资源满足时自动进入依赖已满足阶段；预算耗尽则保存可恢复状态、未满足依赖与精确继续命令，不伪造已验证收益。

只在预算/访问/无法恢复工程问题或必须改变核心合同的边界收尾。不因第一次无收益就把研究目标降为工程验收；先按第 13 节诊断。

## 12. 文献对照与创新定位

以下均应按原文引用，不凭方法名推断。这里列出借鉴边界，不要求复现所有论文网络。

### L1. LaCAM：不能把联合配置搜索误认成站点聚合

Keisuke Okumura. LaCAM: Search-Based Algorithm for Quick Multi-Agent Pathfinding. AAAI 2023.

原文的高层节点描述全体智能体位置的联合配置；与把装卸站之间的物理路段压成运输边不同。暂未确认用户先前所指的具体变种，不武断认定为 db-LaCAM 或 HMAGAT。

- [论文](https://ojs.aaai.org/index.php/AAAI/article/view/26377)
- [作者项目页](https://kei18.github.io/lacam/)

本任务借鉴抽象与分层的思路，不继承 LaCAM 的完备性、最优性或联合碰撞搜索结论。

### L2. GRAND：本轮必须正面对照的直接相邻工作

Johannes Gaber, Meshal Alharbi, Daniele Gammelli, Gioele Zardini. GRAND: Guidance, Rebalancing, and Assignment for Networked Dispatch in Multi-Agent Path Finding. arXiv v3, 2026-03-04；页面关联 DOI 10.1109/LRA.2026.3673902。

其框架由 RL 产生聚合区域的空闲智能体目标分布，经最小费用流得到区域调拨量，再做局部匹配。与用户构想高度相关；不能声称首次组合这三部分。

- [全文，重点 V–VI 节](https://arxiv.org/html/2512.03194v3)
- [版本与 DOI](https://arxiv.org/abs/2512.03194)

借鉴分工，针对 ICS 的航班外生需求、装卸释放、少量循环托盘和单向共享输送通道做适配。若声称相对 GRAND 有方法增量，需要适配对照与消融，不能只改场景名。

### L3. Iglesias 等：时间展开与多时间尺度的直接先例

Ramon Iglesias, Federico Rossi, Kevin Wang, David Hallac, Jure Leskovec, Marco Pavone. Data-Driven Model Predictive Control of Autonomous Mobility-on-Demand Systems. ICRA 2018.

研究用预测与时间展开网络计算预调；其仿真步长为 6 秒，上层 MPC 每 5 分钟运行，说明物理精度与控制重算可分离。这不证明本项目应固定 5 分钟，且其拥堵近似不能直接替代 ICS 的共享容量处理。

- [作者托管全文](https://cs.stanford.edu/people/jure/pubs/driving-icra18.pdf)
- [arXiv](https://arxiv.org/abs/1709.07032)

### L4. Gammelli 等：学习指导运输优化

Daniele Gammelli, Kaidi Yang, James Harrison, Filipe Rodrigues, Francisco C. Pereira, Marco Pavone. Graph Neural Network Reinforcement Learning for Autonomous Mobility-on-Demand Systems. 2021.

可借鉴学习与组合优化分工，但该文的学习输出是调度指导，不等同于本轮指定的需求预测输出。不能照搬后又称其仅做预测；本项目不为引用该文强制换 GNN。

- [论文](https://arxiv.org/abs/2104.11434)
- [作者代码](https://github.com/DanieleGammelli/gnn-rl-for-amod)

### 12.1 更合理的研究贡献假设

待检验的研究问题为：

**在真实有向 ICS 中，利用学习得到的航班需求和合法供盘时刻预测，经站点图联合决定普通回流与提前预置的来源、数量和软到达目标，并通过已有去中心化宿主执行，能否减少断供与等待，同时控制空盘对载盘的通道挤压？**

这是贡献假设，不是已证明创新。

为了达到 TRE/CIE 级别的实质工作量，需要完整的问题建模、强预测优化基线、预测学习与校准、订单时间语义、机制消融、持续闭环和严谨局限。不能靠“加一个超图”命名来代替这些证据，也不为回避相邻工作无目的地增加网络复杂度。

## 13. 无收益时按原因继续，不直接降级目标

| 观察 | 首先检查 | 下一步 |
| --- | --- | --- |
| 没有可调空盘 | priority、硬保留、FIFO、owner 权限、真实资源短缺 | 报告机会分母；分析合法条件释放和调拨提前量，不放宽物理条件制造机会 |
| 分配与现有规则几乎相同 | 单盘单目标退化、多目标竞争是否存在、费用是否只有距离 | 查真实竞争场景与来源机会成本，不能增加网络规模代替动作差异 |
| 计划数量多、执行少 | 每 tick 配额、未来派出假设、拒绝和接收空间 | 校准 departure profile，缩短有效计划并滚动重算 |
| 目标改善但来源变差 | 来源短期损失/后续业务被忽略 | 增强机会成本和下一次释放信息，保留原服务损害记录 |
| 粗箱预测指标好但服务差 | 箱内尖峰被平滑，补盘到得太晚 | 比较近细远粗或 ETA 累计查询 |
| 空驶增多、总服务无改善 | 强制最大流、缺口重复计数、边际收益不递减 | 修 HOLD、承诺去重和价值单位，避免只调权重 |
| 平均等待降、尾部严重受损 | 目标加权、末端效应、共享瓶颈 | 按原门槛判未晋级，做机制修复，不静默放宽 |
| 图分配有益、预测升级无益 | 预测误差是否改变可执行订单、是否已知供给不足、校准与空间映射 | 在固定优化器下诊断和改进预测；不把调度结构收益写成 RL 预测收益 |
| 微观安全但动态效率差 | 宏观路径价没反映空载与载载竞争 | 加可见拥堵反馈与 R1 组合消融，必要时小时间展开 |
| 仅某模板有效 | 整航班时移与真实独立日不足 | 限定结论范围，登记后续独立数据需求，不把窗口当新机场日 |

## 14. 完成交付标准

Codex 最后必须提供：

1. **能运行的代码与真实命令**：新选择器、流网络、分箱参数化、恢复和评估入口。
2. **可审阅的计划案例**：每个来源有多少、为什么能调、目标何时缺、建议数量、预计派出/到达、实际接受/到达；明确示例和真实机场案例。
3. **统一对照结果**：保留普通回流的当前规则、无未来需求的图分配、同 B1 的图分配、分箱候选、预测升级组；完整正负结果与失败分母。
4. **机制与时间尺度报告**：是否真有多源多目标竞争，60/300 秒如何影响决策，计算瓶颈究竟在哪。
5. **预测学习证据**：合法特征—到达标签成熟—训练—校准—固定图优化器生成不同订单—真实执行—留出比较；若称 RL，额外提交真实状态/预测动作/奖励/更新证据。
6. **研究结论与局限**：站点抽象、预测、数量分配、学习、R1 组合分别评价；不保证一定正结果。
7. **可恢复交接**：当前预算、活动状态、剩余依赖、失败原因、精确继续命令。按当前已有仓库授权保存，不合并主分支。

验收拒绝项：

- 只提交文档、图或离线 solver 输出，就宣称调拨系统完成；
- 把所有 x_ij 当作立即发出的盘；
- 未来释放、在途和当前库存重复计数；
- 借上层协调绕过 source owner 权限；
- 无预测组间接读到预测菜单或目标分布；
- 默认关闭/零容量边可通行，或改变盘数来追求效果；
- 将新政策写回活动 runtime、重置预算或覆盖失败证据；
- 将一个历史模板的派生父场景当作独立真实机场日；
- 把粗粒度平均误差下降当成完整服务收益；
- 让旧 action-Q 模型继续选盘或目标，却声称其只负责预测需求；
- 未做同信息强基线比较就宣布 RL 增量；
- 用计划有效期替代原生出发租约，或让在途订单随预测刷新直接消失；
- ACK 未到时把盘当作自由盘重新下单；
- 关闭普通回流构造“无预测”基线；
- 把空盘运输作为虚构行李计入业务完成量；
- 把 R2 routes=False 的实验当作 R1/R2 已联合验证。
