## 航班究竟进入了什么

航班静态计划已经进入实际训练的需求预测器。训练父组 STD ≤ 43,200；开发组 43,200 < STD ≤ 57,600；测试组 STD > 57,600。训练集 153 组/12,549 件，开发集 75 组/5,658 件，测试集 132 组/10,299 件。训练标签关闭时间为 43,200，不能把训练后的模型提前放回该时刻之前。

测试集 60/300/900/1800 秒窗口 MAE 为 1.632/5.059/12.304/23.458，对照为 1.810/6.026/15.493/30.836。
1800 秒点估计改善约 23.93%，但三个 bootstrap 种子的 90% 区间均跨零；名义 90% 覆盖率仅 71.43%，部分区域变差。三个 bootstrap 种子不是三次神经网络训练。

现有小域 FQI 的原生结果不消费机场航班特征。新机场模型将冻结的航班预测、六账户、未知掩码和动作交互送入88维输入及64×64非线性网络，已实际完成81条执行标签上的三个种子（17/29/43）各100 epoch训练。三个最终权重全部保留，没有用开发或测试结果挑选。当前缺失的接收方完整在途证据保持未知，不能用发送方私有账本或假零补齐。

`B2_behavior_training_001` 内层126.453秒、外层128.438秒，最晚标签窗口关闭于53,880，模型首次允许使用时刻为57,600。监督目标是实际行为之后固定300秒的完整人口负积压积分；这是train-only行为续值回归，不是机场多步RL或最优动作Q值。三份训练MSE分别为139,668,714.121、141,164,128.704、153,645,757.153（件·秒）²，没有独立泛化误差估计。

## 异步与当前路径性能

`A3_train_async_001` 未在运行中提交有效正文，`A4_train_async_001` 因真实时间/状态变化被保护拒绝，均保留为负结果。
`A5_train_async_001` 获得两个运行中的 worker 正文→新 current→完整保护→submit→updated ACK→唯一 7→8 实体效果。六件实际完成时间和为 99.734，原参照为 120.612；同样的当前规则也会选 8，因此不是异步排序独立收益。

性能优化仅复用不可变的十个静态合同注册表。当前端点、来源年龄 `.05`、ACK、generation、headway、capacity、native handle 和逐件保护仍逐次检查；未缓存当前预测证明。27 份旧证据的全部预测和逐件保护结果相同，8 份拒绝仍被拒绝。

第一轮实际完整请求“current collection 开始→native submit 返回”规则为 98.0256/142.391 ms，异步为 89.8724/131.1244 ms。纯 evaluate 阶段约 29–34 ms，不能替代完整请求。第一轮发现 6 个初始/最终 roots、4 个 ACK 读取包围区间缺失，以及异常退出计时未持久化；v2 补齐这些仪表后另跑真实原生校准，所有 roots 与 ACK 读取包围区间计数闭合。

v3 进一步去掉保护当前提交路径中未消费的重复 `before_observation`，保留原 submit 路由副作用、默认路径及完整保护；12 个保存真实状态 × 3 候选的字节/AST 对照一致。实际完整请求规则为 **73.9969/94.3618 ms**，异步为 **79.2191/108.7152 ms**。各模式仍只有同一场景的两次请求，业务结果仍为 99.734，不能推出稳定的 100 ms 保证。文件名中的 `R2_discarded_observation_freeze_001` 指第二次性能修订，不表示慢周期 R2 服务。启动冷成本、worker 计算、仿真时间与墙钟分开报告；原生实际路径仅记录墙钟，不将旧 cProfile 的误命名字段当 CPU 计时。

航班前向预测的另一次独立优化把同一 CDF 列表在一次调用内转换为数组，未增加跨调用缓存。`B2_arrays_validation_001` 重算 402 个保存预测（134 组 × 3 方法），并比对三个实际机场公开状态的预测和动作特征，均逐字节相同；AST 除数组物化外相同。这三个离线预测的墙钟从 1231/1176/1086 ms 降为 117/104/93 ms。它们不是原生 R1 计时分布，也未改变权重、公式或信息边界。
