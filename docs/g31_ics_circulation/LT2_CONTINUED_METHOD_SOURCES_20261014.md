# LT2 continued method: sources and lawful planning interface

This is a primary-source and implementation-interface review, dated 2026-10-14. It adds no native command, online solver, experiment, or performance claim. The proposed message below is **not implemented**. Native016 and the completed synthetic study remain the execution evidence. A finite information-partition audit and a stronger fixed-route timing reference are separate work; their results must not be inferred from this design.

## Primary formulations inspected

**Zeinaly, De Schutter and Hellendoorn, TCST 2015, author report 15-019.** Sections II-A and III, equations (17), (25), (27)–(30), formulate joint loaded routing, line balancing, and empty-cart management. The model uses continuous vehicle flows and sampled travel times; unloading baggage queues are omitted under an explicit capacity assumption. The controller uses current state and predicted demand, executes the first control, then replans. The general problem is nonlinear; the simpler LP freezes queue-dependent coefficients, while iterative LP updates them through forward prediction. The objective uses time-weighted queues/flows and empty-flow cost rather than exact individual completion times. These modeling assumptions prevent calling a discrete two-tray G31 controller a literal replication. [Author PDF](https://www.dcsc.tudelft.nl/~bdeschutter/pub/rep/15_019.pdf), [published DOI](https://doi.org/10.1109/TCST.2014.2363135).

**Chen et al., arXiv:2110.14891v1.** Sections III and IV-A–D combine capacity-constrained pickup/drop assignment with collision-aware paths. The objective is total travel delay. Insertion uses marginal completion-related cost; regret compares the best and second-best insertions. Changed assignments trigger cost/path updates, with space-time A* and lazy checks of leading candidates. Bounded destroy/reinsert improvement uses random and expensive-agent neighborhoods. Prioritized path planning is explicitly incomplete. Thus a failed heuristic repair is not proof of physical infeasibility, and an empty-arrival-only rule would omit central mechanisms of this reference. [Primary paper](https://arxiv.org/html/2110.14891v1#S4).

**Parimi and Williams, arXiv:2603.28968v1.** Sections 4.1–4.5 construct a complete seed, select task neighborhoods, take successor closure, repair affected boundary paths, and freeze the remaining exterior. Low-slack and precedence-wait seeds supplement cost/conflict choices. Repair uses regret insertion or a constrained planning proposal; interval path search respects boundary timing, followed by global validation. Threshold acceptance retains a best feasible incumbent. Consequently, successor closure and boundary-aware LNS already have a direct reference; neither is itself our novelty. This source is a preprint. [Primary paper](https://arxiv.org/html/2603.28968v1#S4).

The source reading was targeted to the formulations and algorithms above. No exhaustive prior-art claim, exact paper reproduction, or inherited optimality guarantee is made.

### What the one-shot information certificate can establish

For the existing 24 assessed cells, a restricted deterministic team policy has `route = f_A(observation_A)` and `window = f_B(observation_B)` at the common initial decision. If complete permitted B inputs are identical across all three gates while A distinguishes them, there are at most `2^3 * 4 = 32` such mappings over the declared two routes and four windows. Compare each mapping against every offered job's predeclared incumbent completion in each regime. Retain objective vectors per regime; any scalar regime weighting must be fixed explicitly.

The partition must check complete raw policy inputs as well as their canonical tokens: public clock/configuration, delivered history, own ACK/outbox state, static contract, and any external scenario labels. A common policy may not secretly receive a gate label through its constructor or directory name. Missing/unassessed cells prevent a complete-class conclusion. The certificate is confined to this finite action domain, checkpoint and one-shot policy class. Waiting, earlier signaling, later communication, randomization and additional departure windows are outside it. It is not a general decentralized impossibility theorem or an online optimizer.

## Existing message alternative and its limit

The [native command implementation](../../cpp/ics_core/runtime/circulation_protocol_commands_impl.hpp) supports demand, service forecasts, route commands and forecast/transfer cancellation. The [binding](../../cpp/ics_core/bindings/circulation_session_binding.hpp) exposes fixed schemas. A service forecast is a conditional estimate for a locally visible loaded/loading tray and a next resource. It does not carry the complete future job contract. Initially empty E cannot use that channel to communicate receiver loading/storage details, and the loaded forecast cannot disclose all reuse contracts. Adding arbitrary Python fields to a request does not create an authenticated native payload channel.

Existing delivered forecasts can support later conflict avoidance, as the study demonstrates. A policy may also deliberately wait for additional lawful information, but it must pay the elapsed time and be compared with controls using the same decision opportunities. Reinterpreting request IDs, publication timings or unrelated numeric fields as undeclared gate encodings would change the communication protocol and does not remove the information requirement.

## Minimal typed contract proposal — not implemented

Proposed command: `planning_contracts(owner, target_owner, request_id, scope, publication_delay, expiry)`. Scope can select already observable IDs or all currently observable local contracts; it cannot supply values. At actual source execution, native code captures an immutable projection from the same source-authorized observation used by the owner. Transport, delayed delivery, retries and ACKs remain real native events. No caller-supplied prediction is certified as truth.

| Payload group | Minimal content and authority |
|---|---|
| Envelope | Schema version, source/target owner, message ID, source publication sequence, source capture time, actual delivery time and public static-contract digest. No global state version or future-event identifier. |
| Job contracts | Already observed source-local jobs: ID, origin, destination, arrival, deadline, load/unload/hold durations, mandatory storage node, release time/minimum dwell, protected-service and suffix-reroute permissions. Include locally observable status/stage timestamps if prediction uses them. |
| Tray snapshot | Locally visible tray ID, node/mode, available time, bag ID, generation, traversal, committed prefix, and only the edge/progress fields already authorized in the source observation. |
| Resource snapshot | Source-local observable occupancy/availability, with resource IDs and capture time. Resource ownership, not logistics-zone membership, determines authority. An unobserved receiving reservation is not silently exported as a local sensor. |
| Coverage | Explicit captured job/tray/resource ID sets, scope and completeness semantics. Missing fields or excluded resources are unknown, never zero demand or free capacity. Known future releases are included only when they are already observed contracts; no future-arrival enumeration. |

For this study, A would publish `loaded`, `receiver`, L and its local resources; B would publish `reuse1`, `reuse2`, E and its local resources. Public topology and operation rules need not be retransmitted beyond their identity. If a conflict predictor requires reservation state that is not currently observable, either expose that state as a separately justified local sensor or return unknown. Merely adding a field to this proposal does not establish its lawful source authority.

Static job contracts remain attached to their captured identity; dynamic snapshots age. Use public maximum-age rules and monotone publication identities. A newer withdrawal/expired record must not resurrect an older favorable snapshot. Expiry, missing counterpart, changed local generation or unresolved current ownership causes revalidation or an unknown result. Capture consistency across owners is conditional: these are separate delayed observations, not an atomic global snapshot.

To ensure both owners compute the same plan from the same pair of captured summaries, the sender also needs its exact captured summary through a source ACK or a delivered self-copy. Using each owner's current self-state plus stale peer state can produce different joint choices. Plan identity should bind the static contract, both message identities/sequences, the public generator version and proposed first actions. If delivery cannot complete before 0.11, move the common decision time and all controls; do not use later delivery retroactively.

This message conveys information, not a joint commit. Each owner still submits only its own legal action. Rejection, expiry, lost ACK and partial execution remain possible. A sequential ACK handshake costs time and must be common to every compared method; independent simultaneous requests do not provide atomicity. Claims of an executed joint plan require all selected native ACKs plus actual movement receipts, including no-op edge verification. No implicit rollback is available.

## Shared public planning interface

The minimal implementation boundary is a pure Python model with inputs `(public_contract, local_view, delivered_contracts, local_ACKs, now, candidate_actions, continuation_contract)`. It must not receive a native session, checkpoint bytes, private state, result tables or branch labels. Native forks remain a separate offline evaluator. A test should replace the native object with an object that raises on every method and show that proposal generation still works; changing unseen remote truth while keeping the public input identical must preserve the proposal.

The prediction state needs discrete trays and explicit operations: loading, directed movement, mandatory on-carrier storage, release, unloading/hold, actual empty return and later loading. Its resource calendar must model public node/edge capacities, headway, receiving admission, source/receiver permissions and command latency. Native validation is still authoritative. Stage timing or admission semantics not determined by available inputs produces an unknown prediction, not a made-up exact trajectory.

Return predicted per-job completion values or bounds, outstanding obligations, resource uses, a dependency list of message identities, and one of `model_feasible`, `model_infeasible` or `unknown`. A failed bounded heuristic is `unknown`, distinct from a constraint contradiction. Track separately whether the real command is pending/accepted/rejected and whether evaluation later proves all-offered protection. Predicted protection is not a native certificate.

For the closed four-job domain, completeness can be a declared experiment contract after all four observed contracts are available. For an open workload, absence of future demand is not established by absence from a message. Finish or bound every offered job included in the protection requirement; do not improve an objective by omitting unfinished jobs. Without suitable bounds, the fallback is the predeclared incumbent and an explicit unresolved comparison.

## Concrete B3 and B4 adaptations

**B3: discrete joint receding-horizon control.** On the public model above, choose current loaded next-hop, empty departure/receiver and future route/return decisions over a declared finite action/time grid. Keep exact two-tray conservation, mandatory storage, node4 export restriction and all four jobs. Predict through both L reuses, minimize the sum of predicted completion times, and screen each job against a prediction of the same incumbent under identical model inputs. Execute only the first legal action and replan at subsequent observed events/messages or declared timers. Warm-start from the prior still-valid plan; retain an incumbent when the budget expires. Record the grid, horizon and unresolved tails. This is an executable G31 MPC adaptation, not the paper's aggregate-flow LP or an exact optimum over continuous windows. A one-time lookup of the saved 24 outcomes is not this baseline.

**B4: boundary-aware repair on the same model.** Construct the L load–storage–return–reuse1–return–reuse2 obligation chain and E–receiver chain with resource conflicts. Use cost, low-slack, precedence-wait and deterministic random seeds; include dependent successors, repair affected boundary timing, and test the stitched whole schedule. Repair may use regret insertion plus capacity/headway-aware interval routing. Preserve all permissions and the frozen exterior only while its supporting contracts remain valid. Give the repair solver route/window/order alternatives and multiple priorities; bounded search failure stays unknown. Deploy the best fully validated, protection-screened incumbent, even if exploratory search accepts worse costs. This adaptation needs an implemented repair solver; merely computing a closure set is not B4.

A strong Chen-style comparator should evaluate collision-aware marginal cost over complete service obligations, maintain best/second-best insertion alternatives, and update affected candidates after each placement. It may use bounded destroy/reinsert improvement. Restrict source/tray alternatives only by the actual G31 permissions. In this two-tray study there is limited assignment freedom, so report that restriction instead of claiming a capacitated fleet benchmark. Replacing this comparator with a nearest-empty heuristic would be materially weaker.

All methods must share the same delivered information, proposal opportunity, public predictor, action domain, finite stock, protection rule and total request budget. Give reference methods the same model evaluations or wall-time accounting, including observation construction, messaging, candidate construction, validation, serialization and command submission. Report each component and budget-unknown candidates. Prior full1x profiling identified candidate construction as a major cost; this design does not assume that native observation alone is the bottleneck.

## Contribution boundary

Joint routing/empty management, completion-cost insertion, receding-horizon control, successor closure and LNS are established mechanisms. The current synthetic evidence demonstrates physical reuse and a separate finite-reference gain; it has not established a new online method or an advantage over strong B3/B4 implementations. The gate6 winner does not require the observed node8 feedback branch.

A narrower research hypothesis is a checkable boundary condition for which action-dependent tray-release and cross-owner obligations must enter a local repair, and when the exterior can safely remain fixed using only delivered information. A claimed improvement would need a concrete algorithm or sufficient condition, counterexamples when its prerequisites fail, and computation/quality comparisons against the adaptations above on more than the present tiny domain. The proposed message and an information-class certificate are interface/correctness work, not novelty evidence by themselves.
