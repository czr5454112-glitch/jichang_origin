# P5 时间化接收与替代供给：事前有限诊断

本附录独立于旧 factor001、16 分支修复和 receiving-cut002。旧图及其不相容结论保持不变。新因子在首次 native 运行前固定为四种：Storage 放行余量10秒、无该余量、第三供给口最低库存1禁止导出、P的通行窗移至8秒形成不同时竞争。每种均保留 U0/U1/U2/P/D0/D1 六件业务、四个真实盘、capacity1 和全部保护义务；源准备服务后才可能产生空盘。不能把合成小图当原图或现场许可。

具体因果问题是：远端接收租约从实际 grant 起占位，早到并不自动兼容保护载盘P的接收权；另一个接收任务D1的后续Storage放行余量可能允许较慢替代盘承接，使较快盘服务D0并避开P。拟检验的是替代供给与可吸收服务延迟共同造成的候选覆盖，而非增加任意扫描时点。

权限事前明确：供给区、接收区属于不同 zone，但源0/1/2、接收3/4及Storage6拥有相同resource_owner A；D0/D1完整业务合同可从A的本地原生投影读取。P在owner C、从7途经3到8，只有通过真实C→A下一节点预测公告获取P窗口。没有把远端demand中不存在的Storage私有合同免费广播。此因子使用native011的既有owner限制和延迟公告接口，不启用新增owner_protocol通信合同，不证明多owner协商已接通。

共同候选为最多三源、两个当前需求的全部部分单射指派，每对只有最早释放时刻及越过所冲突接收窗的第一个时刻；窗口结束另加1e-6数值边界余量。最多64动作/因子，H=160、每分支100000事件、整批180秒。保留WAIT、部分指派、异步拒绝与未兑现请求，全部通过真实native fork，不创建第二个物理推进器。

比较普通空盘到达时间指派、保持指派的一轮接收重定时、同信息服务完成时间指派、联合容量提案、同有限域全部native参考。服务完成时间指派必须提前加入强基线，不能把Storage成本遗漏当作创新。完整逐件保护同时相对普通指派、WAIT及强服务指派记录，六件分母固定。有限参考离线可使用真实结果，只认证本域与固定继续策略；在线选择仅使用事前合法观测。预测窗及预测租约结束均不是硬授权；native实际复验有权拒绝，顺序提交不冒称原子事务。

最近邻核对（2026-10-13）：[Chen等，2021](https://arxiv.org/abs/2110.14891)已把实际交付代价引入任务分配并结合LNS；[Parimi与Williams，2026](https://arxiv.org/abs/2603.28968)已研究重指派及边界可行性恢复。因此“联合分配＋窗口＋局部修复”本身不成立为新主张。本轮预期交付是可达见证、强基线补全或反例；若普通服务感知指派追平，明确记为零独立增量，不放行大训练、不降低原长期研发门槛。

### 最近邻原文与创新判定

2026-10-13重新读取两篇原文HTML，而非仅根据摘要推断：

- [Chen等2021，§IV-B及Algorithm 2](https://arxiv.org/html/2110.14891v1#S4.SS2)：按任务插入后的完成代价计算边际成本，并通过路径规划及冲突检查更新可行代价；§IV-C比较最佳与次佳执行者；§IV-D及Algorithm 3反复移除、重指派已有任务。这直接阻止把本次“为较慢接收任务换盘、让快盘服务另一件”写成新方法。此处普通解析只是同模型强基线，不是该论文算法的完整复现。
- [Parimi与Williams2026，§4.2–4.4](https://arxiv.org/html/2603.28968v1#S4.SS2)：§4.2的Low-Slack算子已经按紧张时间余量挑选修复种子，随后取后继闭包、重规划边界任务、重定时后续任务并冻结外部；§4.3–4.4在冻结外部占用与释放界下修复。因此“余量触发＋局部闭合＋重定时”不能独立成立为本项目创新。

本次可支持的新增认识是具体模型诊断：只最小化空盘ETA会漏掉grant起的接收占用和后续Storage等待吸收；固定指派重定时不能替代多源重指派；即使总时间改善，去掉服务余量仍能损害逐件保护。独立普通服务基线已经解释全部收益，**本因子不构成新的预测论文增量或P5方法门完成证据**。下一步应把这份强比较纳入真实有权读取业务合同的控制场域，继续检验多候选共同资源耦合及合法跨owner消息带来的未覆盖部分；不能在本因子上追加更多时点或小网络来追逐不存在的headroom。
