# 成对采集前的完整状态所有权修订

本修订发生在 runtime002 的旧场景 C00 长诊断期间，首批成对原生实验、
拟合与正式测试输入尚未执行或打开。所有旧版本、已登记但未启动的计划、
失败尝试及其分母均保留。

长诊断表明，分段调用反复深拷贝完整协议历史会提高运行时间和内存峰值。
bounded controller 新增私有 `_consume_state=True` 实现选项：调用方交出
状态的独占所有权，ProtocolClient 直接承接并返回同一完整状态。默认接口
仍保留原深拷贝语义。该选项不进入策略 config，不删除或截断历史，不改变
快照、消息、恢复、控制周期、物理输入、候选动作、学习或开发选择规则。
发生异常时，已交出的状态标为不完整，禁止继续复用。

所有新成对实验和正式五组统一使用冻结的 runtime003。第 24 次短门禁
在调用 owned controller 前因比较脚本未统一 tuple/list 表示而退出，
保留为失败尝试，不能提供 owned controller 原生一致性结论，也不追加
短门禁。纯测试已覆盖完整状态及连续/分段调用语义。随后以旧场景 P901、
N22、C00 的一条 reserve 长分支与 runtime002 核对完整物理结果及控制器
状态，只有真实长窗口一致性核对通过，才启动成对训练采集。
完整 source hash 不同仍明确披露，不能仅凭优化意图宣称同源码或等价。

仍采用已登记的 2280/2400 秒软/硬上限，750000 全局事件上限、
单次 advance 100000 事件预算、原物理截止时间及原总预算。无测试结果
参与本实现修订。原始大工件和独立审计收据保留，以便复查一致性与资源收益。
