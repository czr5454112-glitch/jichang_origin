# 成对采集前的实现校准

本修订发生在首个旧场景诊断运行期间；首批成对实验、拟合、开发选模、
新正式测试输入均尚未执行或打开。原预登记与第一次源码快照保留。

1. 开发选模与部署采用相同的完整 K≤13 目录和排序。若胜出动作没有实际
   续行标签，该根收益及服务效应未知；完整父级开发收益未知时不晋级。
   reference 始终是候选。不以仅二臂排序结果替代完整目录部署选择。
2. 首个 C00 诊断暴露离线记录的内存累积：每个控制 tick 保存的
   `refreshed` 包含实际快照 ACK 正文。后续采集按 segment 将记录追加到
   gzip JSON array，保留原字段、顺序、内容与文件接口。在线控制、库存、
   消息、物理参数均不因该写盘修订改变。原分支保持自己的源码与实际结果；
   不覆盖、不把旧进程结果换成新版本结果。
3. 首条单进程诊断在模拟 10/11/12 小时分别约用 316/451/612 秒。
   初始软/硬行政上限 1200/1260 秒可能截断完整 16.5 小时窗口。后续成对
   及正式分支统一固定软/硬上限 2280/2400 秒，仍保留原物理截止时间、
   全局 750000 事件上限和单次 advance 100000 事件预算。失败和超时仍
   进入分母，不使用较短窗口代替原成绩。

整体 16 小时、原生并发最多 2、长分支最多 128、短门禁最多 24 的预算
不变。每次启动必须有足够剩余整体时间容纳完整硬上限。新的公共源码
快照在首批成对采集前冻结，全部训练/开发成对分支及正式五组使用它。
旧诊断若有采集版本差异，审计明确列出；不把仅采集器差异称为严格同源码。

上述修改修复选模语义和采集资源问题，不使用测试结果选参数。
