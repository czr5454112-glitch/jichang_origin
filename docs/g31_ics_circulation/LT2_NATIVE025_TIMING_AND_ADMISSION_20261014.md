# Native025 timing compatibility and experimental business admission

Native025 timing has a separate closed ABI and contract. The accepted native022 validator, binary, compiled-source archive, driver and saved evidence are unchanged. Native025 adds exactly `RequestTimingIdentity::planning_snapshot_v2 = 10`; all earlier identity numbers, all 24 phase names and all 14 method names retain their numeric order. `protocol_planning_snapshots_v2(owner)` shares method 10, `planning_snapshots`, with the v1 query. It does not add a method tag. Unexpected additions, reordering or changed numeric assignments fail closed.

The new [versioned validator](../../scripts/experiments/g31_ics_circulation/native025_request_timing.py) reuses the exact original validation algorithm in an isolated function-global namespace containing only the explicitly extended identity tuple. It does not mutate original globals, translate raw rows, or generically accept unknown tags. The original algorithm's source hash and the versioned source hash are pinned in the contract. Separate publication namespaces distinguish v1 and v2 native index 0; resolving v2 through a v1 command identity is rejected.

The native wire timing schema still says `g31.native_request_timing.v1`, so it is insufficient by itself to identify the compiled ABI. A campaign reference pins the contract file hash, exact build-only receipt, all archived compiled sources, binary path/hash, closed enum tables and endpoint inventory. Every source and binary hash is checked. The [capture proxy](../../scripts/experiments/g31_ics_circulation/capture_native025_request_timing.py) checks that the actual session type belongs to the supplied module at that binary path, records the actual endpoint on every envelope, and preserves explicit policy/recent-policy type capabilities. It requires an explicit acceptance-probe option while runtime acceptance is pending.

A passing structural partition on synthetic records is called a candidate partition. Without the separately accepted raw gate, the public025 analyzer remains `unknown_runtime_acceptance_pending`. Required gates are v1 ordered public behavior and native seal, timing-off/on ordered behavior and seal, v2 query coverage, v2 publication identity resolution, overflow/exception failure handling, and phase conservation. A hash-pinned report with passing flags is only an external attestation; it does not independently verify the underlying native executions. The reader validates its explicit attestation schema, gate, status, binary/build/validator identity, unchanged sources and named check flags, but **even a complete valid attestation cannot enable runtime acceptance**. The separate closed raw-evidence verifier described below is the only acceptance path. Failed reports, arbitrary text and mismatched identities fail closed. Build success or the ordinary v2 functional tests alone do not satisfy those timing gates. Build-only preparation and external attestations provide no live timing, speed, full-request, or100ms claim.

The existing current-header ABI test now recognizes only the two exact documented ABI tables, so unified regression no longer needs a permanent skip. Separate tests verify that native022 still rejects identity10. [Unified pure XML001](../../outputs/experiments/g31_ics_lt2_sustained_20261014/native025_timing_pure_001.xml) records96 passes. Tests also cover absent/wrong endpoint names, cross-version identity substitution, unknown tags, missing spans, exceptions, changed binaries/archives/contracts/validator hashes and missing runtime gates.

## Experimental admission bridge

[BusinessUpdateOutbox](../../scripts/experiments/g31_ics_circulation/business_update_outbox.py) is a separate prototype; no production controller calls it. It requires a fresh, exclusively owned actual `ProtocolClient`. The caller supplies an explicit one-job finite update contract and causal parents before a public observation is performed. This does not assert that the user accepted a replacement for the original business-request definition.

New operation identities and immutable canonical payloads come from the actual client outbox. Required terminal statuses are declared per operation and remain unchanged on retries. Actual refresh records link transport retries back to the original identity/root. Terminal ACK handling uses the real returned query identity plus its last-delivered ACK body; native ACK bodies do not contain request_id, so the bridge binds it from that actual query response. A row's terminal flag, submission rejection, acknowledged pending/granted/dispatching status, or forecast cannot substitute for the required delivered outcome. A direct submission rejection without a delivered ACK remains unresolved in this deliberately limited prototype.

A replacement/fallback root explicitly names its predecessor and parents. An independent new update that reads an old reservation does not extend the old root. No-action roots still require a real same-timestamp native drain and output serialization. A native budget cut leaves the update incomplete without extending its horizon. A successful `updated` route outcome means the declared installed-decision contract only; it does not mean physical job completion or an executed full route suffix. The caller can declare `cancelled` for an actual cancellation operation. Failed reads, unclassified external client activity and mutated outbox payloads invalidate the prototype capture.

The helper records acceptance-to-return elapsed envelopes, including logical waits. It has no exclusive compute, stage accounting, shared-work allocation or100ms certificate. Actual native integration/permission/causal coverage tests remain necessary before using it as runtime request accounting. Pure tests exercise the real `ProtocolClient` implementation over deterministic public endpoint fakes, including lost ACK resends, wrong terminal status, cancellation, explicit fallback, independent reads, no-action drain cuts and failures. No native workers were used for these prototype tests.

Job scope is checked separately from operation completion. A route must name the admitted job and that job must be present in the returned local jobs or tray contract; a mismatch is rejected before any submit side effect. A continuation cannot change its parent's admitted job. Observation provenance retains the view hash and extracted job identities. Empty transfer and cancellation payloads do not by themselves prove affected-job authority. Their completed operation lineage is reported as `complete_declared_operation_lineage_job_scope_unverified`, with `job_scope_verified:false` and `job_scope:declared_label_only`. Missing observed jobs produce the same limit for no-action results. These labels prevent a successful unrelated operation from being reported as a verified per-job update.


## Actual native025 phase acceptance

[Native gate001](../../outputs/experiments/g31_ics_lt2_sustained_20261014/native025_timing_gate_001/receipt.json) executed12 native022 plain cases,14 native025 plain cases, and16 native025 instrumented cases in sequential subprocesses with at most one native worker. The additional two instrumented cases require actual overflow and exception handling to remain unknown. [Independent reassessment](../../outputs/experiments/g31_ics_lt2_sustained_20261014/native025_timing_gate_001/independent_reassessment.json) recomputes all eight gates from saved raw data. Every v1 ordered transcript and native/checkpoint seal matches022; every025 off/on pair matches; v2 queries use method10 and actual publication spans resolve identity10. Whole native envelopes and all unclassified remainder remain included.

The [closed raw verifier](../../scripts/experiments/g31_ics_circulation/native025_timing_gate.py) requires the exact predeclared12/14/16 case sets and input scenes, per-case endpoint sequence, matching timed envelope count/order and submission/query identity, actual terminal outcomes, nonempty64-hex seals, phase conservation, real overflow bit and exception records. It checks exact source-file inventory, live/archive hashes, gate/versioned/legacy validator cross-links, accepted022 build/archive, actual binary identities, all raw-file hashes and process receipts. Matching empty transcripts or placeholder seals cannot pass. A tampered report whose hashes are recomputed still fails the corresponding raw invariant.

The [accepted025 contract](../../outputs/experiments/g31_ics_lt2_sustained_20261014/native025_timing_accepted_001/contract.json), SHA `dc4952fdd9c0c74ea642800f8c9052a2868f44e4c2242b2bf3f3cf790d9e4bf7`, pins this finite runtime evidence and returns `validated_partial_native025_phase_partition` on the actual v2 trace. This accepts the closed phase ABI and finite observed coverage, **not complete business-request attribution or100ms latency**. Native022's validator remains unchanged and still rejects identity10.

[Pure gate XML002](../../outputs/experiments/g31_ics_lt2_sustained_20261014/native025_gate_pure_002.xml) records84 passes. [Actual saved-data adversarial XML001](../../outputs/experiments/g31_ics_lt2_sustained_20261014/native025_gate_saved_tests_001.xml) records9 offline passes, including deletion of all paired transcripts, null seals, missing v2 identity/case, missing source inventory, changed validator cross-link, failed process and wrong binary after evidence hashes are recomputed. No additional native runs were used for those adversarial checks. Earlier build-only contracts and external-attestation-only drafts remain preserved.
