# Native v2 rolling proposal: execution and limits

The first twelve native025 branches completed all four jobs and both real tray
returns, but all twenty-four later model decisions fell back. This is a physical
continuation result, not successful online rolling optimization. All methods
had identical completion vectors within each gate and zero measured gain.

Evidence is under `outputs/experiments/g31_ics_lt2_sustained_20261014/`:
`native_rolling_joint_001/` contains the predeclared twelve rows, source archive,
all raw owner views/captures/ACKs/actual edges, native results and independent
physical audits. Its worker completed in 13.723 seconds, with no native fork or
result used by the policy. `native_rolling_joint_001_diagnosis.json` retains the
exact twenty-four failure reasons. Source hashes did not change during the run.

The twelve first-return failures came from an adapter scope mismatch.
`observe_protocol(owner).jobs` retains completed source jobs, while the capture
explicitly covers waiting and locally carried jobs. At gate6, A's full view
contained completed `loaded` and `receiver`, its active capture had no jobs, and
its v2 extension contained both actual destination completion receipts. The
repair compares the declared active scope and separately requires a delivered
terminal receipt for every excluded completed job. It still rejects missing
receipts, changed contracts, new physical actions and autonomous local changes.
Offline revalidation of the saved data accepts all twelve first-return pairs as
conditional data; it does not authenticate a new native execution.

The twelve first-reuse-route failures were genuine information uncertainty.
A's return had physically arrived at B, but A's last delivered transfer ACK still
said `departed`. Its ordinary 0.5-second immutable retry had not yet delivered a
`received` ACK. The v2 capture correctly retained the unresolved source action.
This guard is not relaxed, and hidden transfer state cannot clear it.

The second protocol is a separate amendment, executed in
`native_rolling_joint_002/`. On an actual B
local `L` loading `reuse1` at7, B publishes one native v2 preflight message. A
reacts only after delivery, retransmits its matching immutable pending6→7
return ID once, waits for a delivered `received` ACK, then replies. At the later
actual load completion, B starts the ordinary fresh capture pair before deciding
its route. This uses the real 0.1-second load interval as communication lead
time. It preserves the 0.01-second command/publication delay, 0.02-second ACK
delay, 0.05-second capture-age guard, ordinary 0.5-second retry timer and physical
service. Missing or late messages still produce explicit unknown/fallback rows.

All twelve second-campaign branches completed in 14.653 seconds with unchanged
source hashes. Twenty of twenty-four later decisions used native-verified
delivered model inputs. Gates 6 and 12 had no fallback. Gate 0's B decision retained
unknown because A's snapshot exposed one unrepresented receiving occupancy
at 4 while E was in transit; that guard remains intact. All four methods selected
zero return delay and route 3 and achieved identical actual completion vectors.
Every job passed strict protection against the matched frozen-later arm, and
every measured gain was zero. This demonstrates conditional online replanning
in the supported states, not a beneficial joint method.

Strict coordinate search evaluated 9 of 16 candidate actions per valid solve;
plateau coordinate and resource-pair repair evaluated all 16. Their model gains
were also zero. The selected projections matched the first three actual job
completion times but predicted reuse2 about 0.04 seconds later than native in
every valid solve. That remaining continuation/tick discrepancy is retained;
there is no certified prediction error bound. The gate 6/12 receiver tray was
already finished before the return decision, leaving no later shared-resource
competition to resolve. `native_rolling_joint_002_action_audit.json` binds all
twelve raw files and retains every decision and prediction residual.

All gates0/6/12 retain the same two trays, four jobs, graph, Storage gates and
capacities. The four methods are frozen later actions, strict coordinate moves,
coordinate moves allowing equal-objective intermediate states, and resource-pair
repair. All receive the same protocol and a thirty-two-evaluation model budget.
At A only the return departure delay is executed. At B a fresh solve selects
only the immediate next route. An earlier predicted future action is never
silently carried forward as a new decision.

Protection requires every actual native job completion to be no later than the
same-gate frozen-later arm, with zero tolerance. The conditional model is not a
proof of that property. The model's predicted-versus-native errors remain in
every raw row. Current causal records cover declared owner-activation proxies,
immutable retries and delivered-message/rejection causes; cross-owner creating
roots are explicitly unknown where not transmitted. There is no complete
business-request denominator, compute-span or100ms certificate, atomic agreement
claim, or solver novelty claim.
