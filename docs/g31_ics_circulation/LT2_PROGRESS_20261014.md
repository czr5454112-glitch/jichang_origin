## 已落实的接入修改

- C1：新增 `LocalContextToken`，分开合法决策依据与请求身份；P5 协议入口不再读取
  已去除的真值 `version`。隐藏远区变化不改变本地 token，实际消息送达后才改变。
  缺少跨区服务合同返回 unknown，原生接收端仍在真实送达时复验。
- C2：将传输重试、终态拒绝冷却、预测刷新/过期/撤销、接收预测过期与路线租约分开。
  定时堆、去重 generation、未结束 owner 轮次和通知游标进入状态；同刻原生事件先排空。
  新增协议状态版本校验，修复 JSON 往返后条件签名的 tuple/list 差异。
- C3：同一次 owner 激活内复用只读观察；任何中间提交，包括拒绝，都会使复用失效。
  `compact=False`、后续残余候选和跨原生推进重新观察，公共字典没有共享缓存。
  深拷贝缓存的实测成本反而为两次原生观察的 5.69–8.15 倍，已作为负结果保留。

预测有效期是所有策略共同使用的客户端年龄合同，不是新增的原生消息承诺。
checkpoint 仍必须配合**同进程**原生对象；单独保存 JSON 不能跨进程恢复物理状态。
详见 [观察复用证据](LT2_OBSERVATION_REUSE.md)。

## 原图 R1 与真实返供证据

新 `research_r1_authorized` 档只授权未承诺后缀。冻结 original24 的权限和负对照保持不变。
原始 28,506 件的静态分类为：24,490 有替代候选、4,001 必经阶段不可达、15 无选择。
这些类别仍保留在原流分母，不是筛完后的成功率。

`r1_storage_in_016` 与 `r1_post_storage_016` 共 32 个上下文、99 条原生分支；
它们来自同一模拟日 **16 个来源任务**的两个阶段，每个上下文隔离为一件业务和一只现有盘，
不能当作 32 个独立任务样本或并发原流。候选确实改变后续逐跳行为，已执行前缀保持，
首次改变下游物理边前已收到真实 ACK；全部达到同一 H 并通过物理审计。
当前有限候选没有获得 S4 之外的业务收益：入 Storage 的差异被释放门吸收，门后的绕行则造成延迟。
首个见证是 Storage 到达**晚 79.54 秒**而最终卸载相同，不是提前 79.54 秒。

`r1_reuse_002` 用三个原始选定任务、一只实体盘和两次实际跨区返供继续执行。
预测条件请求分别比空盘释放早 15.95 秒和 344.843 秒；真实授权仍等待释放。
R1 的 0.9 秒变化传递到后续释放、返供、接收与装载，第二轮后被 Storage 门吸收。
该候选使两件业务变慢，不通过零退化保护。两种继续策略的 factorial 数值为零，
但它们不是同一继续策略下的联合动作 κ，不能据此宣布联合问题可分。

详见 [R1 与复用原件入口](LT2_R1_AND_REUSE_20261014.md)。

## 新耦合诊断与方法边界

`synthetic_contention_003` 的四格实验固定同一 checkpoint、合法信息、两只盘、
全部业务和后续规则。R1 后缀与 R2 出发窗争用真实接收位、节点及下游边，
全部执行并收到终态 ACK，得到 **κ = −1.841 秒**。
这证明该合成域具有不可分的动作后果；三个非基线格均使正常载盘业务变慢，全部被保护规则拒绝。

另一个独立固定三盘因子完整执行八个子集：所有两两组合可执行，三方组合收到两盘，
第三条得到实际送达的 `receiving_full` 拒绝。分类器已补上未完成/未决 ACK 保持 unknown 的检查。
这是高阶容量反例，不能计作新算法。详见 [合成耦合记录](LT2_SYNTHETIC_CONTENTION_20261014.md)。

随后预声明的 `synthetic_reuse_chain_003` 扩展为 3 个释放门 × 2 个初始后缀 × 4 个出发窗，
固定两盘、四件业务、共同因果继续规则。24 个最终分支全部完成四件业务，
同一 L 盘都真实返供两次并装载 `reuse1`、`reuse2`，改变的路线均有终态 ACK 和实际逐跳记录。
固定路线四窗口参考与联合八格参考的受保护收益分别为 **0、1.41、0 秒**。
中间门条件下，仅 receiver 提前 1.41 秒，其余三件完全相同；严格使用逐件 `delta <= 0`，没有正容差。

另有 R2 出发窗经实际送达服务公告改变后续 R1 的 3→8 选择，但这些分支没有通过保护；
获得 1.41 秒收益的分支仍选 3。**反馈存在与受保护收益是分别成立的证据，尚未证明反馈导致该收益。**
这里的精确参考仅覆盖每门八个初始决策、固定继续规则，不是连续时间全局最优、完整 B2、B3/B4 或新在线求解器。
原始失败与修正过程保留：001 在原生运行前因校验值错误失败；002 的冗余保持路线请求使部分格未决；
003 完整重跑 24 格，本轮该研究总计 48 条原生分支。之后仅强化评分器，使用执行部分 AST 不变检查与
保存原件复算确认 24 格结论不变，未伪称新原生重跑。
详见 [复用链有限参考及独立复核](LT2_SYNTHETIC_REUSE_CHAIN_20261014.md)。

## 性能、分母与长期执行

original24 的一次串行观察复用对照从 87.707 秒降至 50.745 秒，原生观察次数
17,891 降至 10,005。1,489 次提交（含重试）、8,934 次 owner 决策、16,008 个原生边界、
JSON 状态、原生状态及业务/盘/返供/receipt/leg 字段一致。它是本机诊断，不是两机硬实时认证。
基准驱动最后的报告断言因修改了读入的旧 config 而失败；原失败回执保留，
之后从未修改的保存原件独立复核通过，不能把原失败回执改成成功。

之后新增按 owner 派生的活跃请求/冷却索引，完整 outbox 历史仍保留，JSON 恢复后重建索引。
在原图 joint 至 H10800 的三个已保存分段上，索引与全扫描的请求、激活、原生边界、控制状态、
五类物理结果及原生状态均一致。实际耗时 13.524 秒对 13.538 秒，**没有测出加速**。
469/475 终态记录的无效扫描虽被消除，主耗时仍在其他环节；不能据结构变化声称解决了全量性能。

新增逐请求保守计费保留失败、拒绝、重试和未结束请求。owner 观察/决策/提交/ACK 处理、
原生送达与接收验证都纳入；共享批次整段计入每条依赖请求，不按批大小平均。
全局调度残差也整段计入每条请求，因此上界超过 100ms **不等于**证明单请求实际耗时超限。
未结束请求的完整生命周期上界为 null。乱序、缺段、缺失原始提交或不可能的 ACK 时间均返回 unknown。
