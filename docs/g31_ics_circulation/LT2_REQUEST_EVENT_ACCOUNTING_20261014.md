# Full request measurement: event ledger and remaining instrumentation

The existing 6.4-second residual is a conservative whole-run charge, not a measurement that each request used 6.4 seconds. Reallocating that number by averages would not establish the 100 ms requirement. A precise measurement needs interval locations and causal identities. This work supplies separate validators, a read-only diagnosis and an external runtime wrapper. The wrapper measures complete native calls without editing native stage instrumentation. No result here certifies the full requirement.

The attached LT2 plan §9.1 requires observation, preprocessing/prediction, candidate generation, solve, actual source/receiver validation, commit and ACK processing; it also requires retries/fallback/serialization, exclusive nested accounting, full shared costs, and separate queue/transport/end-to-end figures. Every observed overrun counts, and a finite ordinary-OS sample is not a hard real-time proof.

## What the saved 5000-activation trace says

The input still contains all 28,506 original projected jobs, but the run stopped at physical time 12,249.637986 with only 57 arrived jobs. It is an input-complete **prefix**, not a completed full-workload experiment. There are 1,186 outbound protocol identities, 1,368 submissions including retries, and 5,000 owner activations. A protocol identity is not the same denominator as a business update: activations that return no command can still perform observation, search and fallback work.

The separate [diagnostic](../../scripts/experiments/g31_ics_circulation/audit_request_measurement.py) preserves those no-message activations, verifies input/message counts, and reports the unresolved global residual. It never converts missing timestamps into invented per-request intervals. Its receipt records source/input hashes and zero new native runs. The old trace used cProfile, so its activation timings include profiling overhead; no unprofiled speed or production-latency claim follows.

## Implemented ledger validator

[request_event_accounting.py](../../scripts/experiments/g31_ics_circulation/request_event_accounting.py) accepts `g31.request_event_ledger.v1`. It deliberately supports one execution lane and a monotonic nanosecond clock. A parallel implementation needs explicit dependency/clock treatment before using this schema.

- `requests`: root identity allocated **before** observation, opening/closing clock values, explicit status including `no_action`, `fallback`, failure and open/unknown, business-job associations and phase coverage.
- `messages`: immutable protocol identity, dependent root IDs, terminal or unresolved outcome, and per-message phase coverage. Serialization/submission cannot be declared absent; terminal transport outcomes require ACK processing. Immediate submission rejection is the explicit ACK exception.
- `service_windows`: every measured controller service interval, including resumption and required output/copy work. These windows must be covered exactly by top-level spans.
- `spans`: monotonic start/end, parent ID, phase, dependent root IDs, optional protocol identity and work class. Classes are control, physical simulation, waiting, diagnostic work, or unclassified work. The last three exclusions need explicit reasons where applicable; they are instrumentation assertions, not classifications inferred from names.
- `phase_coverage`: each required phase is measured or explicitly inapplicable with a reason. The validator checks declared measurements against spans. Semantic correctness of an inapplicability reason still requires review against actual control flow; the ledger cannot prove that an emitter told the truth.

Nested children subtract from their parent's exclusive time. Children inherit ancestor dependencies. A shared 70 ms span needed by three roots is charged 70 ms to **each** root. It is never divided by three. Separate spans for the same protocol message accumulate across retries; phase coverage is checked for every message, so one measured validation cannot stand in for another request's missing validation.

Coverage gaps, unclassified native work, unattributed control work, missing phases, invalid clocks/overlaps, open requests, unknown identities and incomplete instrumentation prevent a passing result. Even a complete ledger always leaves `complete_business_requirement_certified=false`: the declared finite measurement scope and the business requirement are distinct. The output reports accumulated dependent control wall time and maximum continuous compute segment. Physical/logical time is not substituted for CPU or wall computation. Logical end-to-end duration may be recorded separately; queue-versus-transport remains explicitly unmeasured until its actual events are instrumented.

`owner_activation_updates` is the useful first measurement scope. Give each activation a diagnostic ID derived from run/owner/epoch and retain all activations, including no action. This is not an assertion that the original field requirement defines one task as one activation. For `explicit_business_updates`, the external update ID and its causal chain through one or more activations must be recorded. Do not infer those IDs from whichever protocol commands happened to be emitted or treat all jobs touched by a shared activation as independent averaged requests.

## Concrete Python hook locations

In [event_protocol_control.py](../../scripts/experiments/g31_ics_circulation/event_protocol_control.py), root allocation precedes `_activate_owner`. Its observation/refresh, `_publish_owner_demand`, `_publish_services`, `transfer_candidates`, residual candidate recomputation, `_sync_owner_timers`, and return-record construction need nested spans. Owner initialization/resumption, state deep copies, pending-owner dispatch, notification interpretation, timer collection and output checkpoint copies need located scheduler spans outside activation wrappers. Their dependencies are the actual pending/created/resumed roots that need them, not every historical request in the run.

In [protocol_control.py](../../scripts/experiments/g31_ics_circulation/protocol_control.py), instrument `ProtocolClient.submit`, `_send`, `refresh` and `view`, including payload/reply copies and codec serialization. Bind each immutable request ID to its creating root; every retry and ACK callback retains that parent link. An ACK-handling activation may have both its own update root and outstanding parent roots. Charge shared work in full to each, with exclusive nesting to avoid charging nested submit twice. Logging/profiler overhead must be measured or left conservatively charged, never subtracted using an optimistic constant.

The sidecar telemetry must not enter legal observations, policy state, checkpoint hashes or action selection. Restore carries telemetry separately alongside the existing native/controller continuation; it must not reset an open request's cost. If a process exits without native persistence, the interrupted cohort stays unknown. Rebuilt work is a distinct replay, not a resumed measured lifetime.

## Conservative complete bundles before native stage probes

The separate [bundle recorder](../../scripts/experiments/g31_ics_circulation/request_bundle_measurement.py) and [bounded driver](../../scripts/experiments/g31_ics_circulation/profile_request_bundles.py) now provide a second measurement mode. External wrappers allocate an owner-update root before `_activate_owner`, link actual protocol IDs at submission, preserve parents across retries/controller calls, and close transport children only after terminal client-visible processing. Updates without a new command remain roots.

Every full native advance is charged to all outstanding message roots and to updates triggered by its notifications/timer boundary. **No physics is subtracted.** Monotonic wrapper endpoints partition the rest of each controller call into located scheduler gaps and returned-state/output work. Shared initialization/output costs apply in full to that call's cohort; unassociated background native work is conservatively charged to the same cohort. This can still overcharge, but does not assign the whole experiment's residual to every historical request. Instrumentation finalization and evidence file writes are separate diagnostic costs; actual controller copies, route serialization and submission are inside the measured windows.

The bundle validator checks complete exclusive window coverage, creation/terminal linkage and inclusion of every native interval during each message lifetime. A no-action or ACK-terminal update remains open until its mandatory post-activation native drain actually reaches a complete timestamp. A native event-budget cut cannot complete that drain. Timer/periodic origins are captured where `_due_timers` runs immediately after native-boundary validation, before owner dispatch; notification origins use the delivered owner/sequence identity. If a pending cause crosses a controller checkpoint, its eventual root also inherits the originating native interval, trigger-processing gap and required checkpoint output. Open roots have no complete upper bound. It reports `complete_compute_upper_ns`, not isolated source/receiver validation times. A complete conservative bound at or below 100 ms is useful finite-cohort evidence without stage isolation; a bound above 100 ms remains inconclusive about isolated request cost. Passing the bundle calculation does not by itself establish full-workload, per-job business-request or two-machine acceptance.

The driver persists each raw controller segment outside measured service windows, including control records, immutable submissions and native boundaries. This allows an independent reviewer to compare an outer activation interval with the controller's inner `compute_wall_ms`, inspect rejected/retried actions and reproduce semantic checks. The prior saved trace is released after extracting configuration; raw segments and copied ledgers are released before the next measured call. The mandatory controller state and causal accounting sidecar remain live. Replay uses the original requested activation limit, including when a native budget cut produced zero activations, and reads one saved segment at a time outside controller execution. Recorder bookkeeping remains conservatively included where it runs inside a controller window. Evidence compression/finalization and the separate replay are diagnostic work, not controller latency. No garbage collection is disabled; memory retained by telemetry can still affect observed pauses and must be disclosed.

Its measured controller windows total 22.5514 seconds. The complete original input has 28,506 jobs; only 57 had arrived by physical time 12,249.637986, so this is a prefix, not a completed workload.

Independent self-review found that frozen001 associated timer causes with the native call preceding activation, which can differ from the call that created a waiting timer cause. Earlier checkpoint/trigger-processing dependencies were also not retained explicitly. Its original per-root completeness result is therefore **not accepted**; the stricter validator fails closed on missing causal evidence. The original artifacts are unchanged and the [scope review](../../outputs/experiments/g31_ics_lt2_sustained_20261014/request_bundles_full1x_5000_001/independent_scope_review.json) records the limitation. Three outer owner-wrapper intervals exceeded 100 ms, with maximum 264.842 ms; these include instrumentation and ordinary-OS scheduling and do not establish a deployment latency claim.

The corrected recorder has pure tests for timer origins and shared checkpoint costs across shards, mandatory post-owner drains, partial native timestamp cuts, pending/lost ACKs, immutable retries, no-action roots, complete shared charging, raw lifecycle tampering and preservation of the private policy-observation API. [The latest pure test receipt](../../outputs/experiments/g31_ics_lt2_sustained_20261014/request_accounting_tests_010.xml) records 54 passing tests, including two fake-native driver/replay cases and six independent raw-trace checks. The preceding008 receipt is preserved: its two file tests hit Windows sandbox temporary-directory rename denial; rerunning with a workspace temporary directory passed. The separate [raw-trace verifier](../../scripts/experiments/g31_ics_circulation/verify_request_bundles.py) matches execution order and every owner/cause identity to the ledger, verifies all native boundaries and submission payload/attempt counts, and checks that the final outbox contains exactly the recorded immutable message identities. It reports inner controller and outer-wrapper timings separately. Deleting a no-action activation, native batch, submission or outbox history prevents verification. This check runs offline and makes no native calls; it complements rather than substitutes for the uninstrumented execution replay.

## Native attribution hooks for precise stage measurement

These are read-only source findings, not implemented timing probes:

| Entry point | Required scope and request linkage |
|---|---|
| `NativeSession::submit_protocol_transfer` / `submit_protocol_command`, [binding](../../cpp/ics_core/bindings/circulation_session_binding.hpp) | Python/C++ decoding, return encoding and immediate rejection are nested submission work. Capture the supplied protocol ID before validation can reject it. |
| `submit_circulation_protocol_transfer` and `submit_circulation_protocol_command`, [transfer protocol](../../cpp/ics_core/runtime/circulation_protocol_impl.hpp), [command protocol](../../cpp/ics_core/runtime/circulation_protocol_commands_impl.hpp) | Namespace, ownership, immutable retry matching, enqueue and timeout scheduling. Preserve attempt numbers; retries are not new business roots. |
| `process_circulation_protocol_command_event` | Actual source execution on `protocol_command_wire`, source outage deferral, duplicate handling, typed route/publication dispatch, command ACK generation/delivery and timeout. Map native command indices back to the existing input request ID. |
| `process_circulation_event`, `module_message` branch, [runtime](../../cpp/ics_core/runtime/circulation_runtime_impl.hpp) | Wire arrival, client/physical identity lookup, source/receiver availability, duplicate handling and pending transition. These are controller work inside native advance. |
| `circulation_progress`, transfer loop | Per-pending-transfer source readiness/export/min-stock and receiver permission/capacity checks, including each repeated failed/deferred evaluation. Instrument shared scan setup separately. The grant mutation, receiving lease and `circulation_create_leg` belong to commit; do not classify the whole function as physics. |
| `process_circulation_event`, `control_route` branch | Generation/traversal/prefix, service permission, static reachability, advertised fault, deadline bound and `can_enter` validation; updated/rejected result and wakeup/commit, mapped to the route command. |
| `circulation_protocol_send_ack`, `circulation_protocol_command_ack`, their delivery branches and binding request readers | ACK generation, simulated drop/duplicate bookkeeping, actual delivery and client-visible decoding, attributed per message/attempt. Logical scheduled delays are reported separately from measured execution. |
| `circulation_leg_completed`, `circulation_leg_failed`, `can_enter` / edge admission and recovery call sites | Keep the causal tray/leg/transfer mapping for completion, failure, resource revalidation and required fallback. `can_enter` also runs from [event_driven_junction.hpp](../../cpp/ics_core/runtime/event_driven_junction.hpp) and [recovery](../../cpp/ics_core/runtime/circulation_recovery_impl.hpp); timing only the initial command would omit these later checks if the declared request lifetime includes them. |

Native and Python clocks must share a verified monotonic timebase or a measured mapping; do not assume C++ `steady_clock` and Python `perf_counter_ns` have the same epoch. An alternative is native child intervals relative to the enclosing native call with an explicitly measured conversion and bounded mapping uncertainty. For stage-isolated accounting, whole native advance remains unclassified until all relevant validation/commit paths are covered. The separate conservative bundle mode instead charges its entire cost. Pure physical movement may be excluded only after demonstrating that no required controller validation is hidden in that interval.

For a finite transport request, the current lifetime ends when its terminal delivered ACK is processed. For a route-update requirement, distinguish installed preference ACK from later physical service completion. If later mandatory revalidation/fallback is part of the requested update, keep its root open or attach that work through an explicit parent chain. State that boundary before measuring; changing it to discard slow work is not an optimization.

## Acceptance and falsification experiment

1. Freeze the complete original 1× and 2× input files, permissions, controller/configuration, native binary, source hashes, hardware/power/concurrency settings, root-scope definition and cohort cutoff. Do not shorten business input, mute legal timers or discard no-action requests. Predeclare a finite follow-through horizon for requests accepted before the cutoff; any unclosed member stays unknown. Later root updates remain in a separate reported denominator and can still carry work of the selected cohort.
2. First check instrumented versus uninstrumented execution on the same frozen case for exact payload order, decisions, native receipts, controller checkpoint and native state equality. Telemetry cannot change dispatch order or policy clocks. Run unit cases with nested work, shared batches, retries, dropped/duplicate ACKs, rejection, fallback and serialization failure. The separate validator already covers accounting counterexamples; it does not replace these runtime checks.
3. Run unprofiled, single-worker cold and warm full-input cohorts on each actually available required machine. Record bursts, fault-triggered updates and long-history cases without changing the physical contract. Do not run competing benchmarks concurrently. cProfile is for diagnosis, not the final timing sample. Keep attempted, rejected, timed-out, duplicate and censored roots in denominators.
4. A measured dependent root total over 100 ms falsifies that tested implementation/configuration's finite-sample requirement; a slow no-action update counts. A missing stage, incomplete workload or open cohort cannot pass. A conservative upper bound above 100 ms alone does not establish actual isolated overrun. Every measured root at or below 100 ms with complete coverage supports only the stated finite tested domain, not all future OS schedules or unavailable second-machine cases.
5. Solver budgeting must reserve observed submission/validation/serialization capacity and return a still-legal incumbent before the remaining budget is consumed. This is an algorithm change requiring equivalence/protection evidence; the analyzer does not enforce it, and measured overruns cannot be reclassified as fallback success.
