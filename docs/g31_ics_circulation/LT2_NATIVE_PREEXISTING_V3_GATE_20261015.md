# Separate native027 integration gate for the third-tray fixture

This prepared integration is separate from the frozen native025 delivery002
study. It keeps the same six three-tray/five-job configurations, corrected
10-by-10 derived potential, initial action domain, ten methods per case, and
strict physical comparison. No native branch has been executed with this
runner at the time of preparation.

The stages remain nine initial-delivery branches (six normal cases and the
same three missing/expired/lost-ACK negatives) followed by sixty business
branches. Every case includes the frozen incumbent, each of the four fixed
initial-route E departure windows, strict coordinate, plateau coordinate,
pair repair, finite enumeration, and the explicit later-route-3 ablation.
All methods receive the same public contracts, action budgets, message rules
and fallback. A complete stronger fixed-initial reference requires all four
windows. Missing, failed, censored and unsupported outcomes remain visible;
an unfinished job never becomes a zero regression.

Those nine rows test the initial **v1** planning pair on native027. They are
not evidence that a later v3 model input has been collected. The separate
21/44 native gates establish API semantics/compatibility; actual later v3
collection is retained in the subsequent business rows.

Before constructing a campaign session, the runner requires the closed
native027 legacy/v3/timing saved-raw verifier and the separately bound
21-case semantic regression verifier. The latter checks actual pytest fixture
binary provenance, source/archive identity and the exact XML cases. Build
success, a caller Boolean, or a hash without the raw verification cannot
admit execution. Preparation does not require or imply either runtime gate.

`native_preexisting_v3_adapter.py` binds the actual loaded extension and
`NativeSession` to the accepted artifact. It reuses the session-and-owner-bound
initial native job ledger, reads only that owner's current observation, own
command ACK and v3 recipient endpoint, and selects the explicit peer message
after the collection start. All three raw endpoints, including the complete
returned inbox and failures, remain in the decision record. The pure data
adapter independently validates the nested captures, digest, source scope,
terminal/action coverage, actual capture epochs and own current state.

A successful read is returned with an in-process seal bound to its session,
physical time and exact serialized content. A supplied dictionary, copied
JSON, changed result or caller-supplied delivery flag cannot authorize the
runner's later proposal. The seal authenticates collected data only. The
capture-union stability condition, simultaneous current state, atomic
agreement and model protection remain uncertified. The conditional predictor
and all earlier unknown guards are unchanged.

This version introduces one explicit common policy amendment. An owner with
a pending later collection does not admit a new physical operation. An owner
answering a delivered `first_return` or `first_reuse_route` invitation also
holds new physical admissions for 0.08 seconds. The preflight ACK-refresh
invitation does not establish a later-decision hold. The runner records the
hold's source message, phase and interval. Native physics, already queued
operations and immutable retries continue. A locally overlapping collection
cannot bypass an active peer hold; its decision may become stale and use the
same recorded fallback. This rule applies to every arm and does not imply
that the physical state is quiet. Unresolved actions or autonomous changes
inside the actual capture union still reject the model input.

The earlier interval before the peer receives an invitation is not covered
by its reply hold. The draft2 consumer therefore preserves every source's
complete submitted physical-action set and requires every terminal delivered
ACK to be **strictly earlier than the earliest capture**. Same-time ordering,
late ACKs, missing times and missing action coverage remain unknown. A route
update can change preference without changing lifecycle, generation or
committed prefix; that preference and its execution time are not present in
v2/v3 action coverage. The consumer does not infer an earlier execution from
a terminal ACK or treat a later captured preference as modeled state.
This can reject an operation that physically finished earlier but whose ACK
arrived later. The conservative rejection is intentional.

`preexisting_v3_action_union_correction_001` preserves a pure supplied-data
counterexample accepted by the earlier consumer, plus its pre-correction
sources. It is not a demonstrated reachable trajectory of the fixed native
runner. The unexecuted preparation001 remains preserved; preparation002 uses
the strengthened consumer.

The v3 extension supports only the restricted already-observed moving E cases
specified by the pure model. It does not expose a future event heap, permit a
foreign action, enlarge capacities, change FIFO, pause native time, weaken the
0.05-second age limit or alter per-job zero tolerance. Each owner executes only
its current first action and must collect fresh information before the next
decision. Source-authored facts and delivered ACKs remain distinct from
physical completion evidence.

Business assessment retains every actual job completion, transfer/route ACK,
executed edge, same-L two-return/reload witness, blocker 1→9 path, full tray
audit and common horizon. Physical comparison can be assessed when every
physical gate passes even if a policy used fallback; the separate joint-policy
evidence status remains unknown in that situation. This prevents a protected
fallback trajectory from being reported as evidence for the new rolling
model. No original-map benefit, optimizer novelty or full-request 100 ms claim
is made by this finite synthetic gate.

Execution uses a bounded parent (at most 180 seconds), explicit accepted
artifact references and a frozen imported-project source closure. Existing
prepared directories require their exact plan hash and are not overwritten.
After the nine delivery rows, business admission independently rereads the raw
gzip files, input hashes, source archives, capture digests, own ACKs, peer
delivery and exact fault causes; summary booleans cannot open the gate.
