# HCA 段执行身份修复与两地图重跑协议

用户于 2026-09-06 授权修复历史 HCA 段计数异常并重跑完整实验。本协议在新 HCA 完整结果产生之前记录；是否接纳运行依据身份与执行账目正确性，不依据 G31 的输赢。

## 修复范围与版本

新方法标识为 `HCA_SEGMENT_IDENTITY_V1`。旧 HCA 路径规划源代码、旧 wrapper 与旧实验档案保持原样。新 wrapper 为每个业务段提供唯一执行编号，将执行编号明确映射回原始行李、段类别、起终点及计划时刻。活动路径、节点预约、推进和完成记录都必须使用该独立身份；仅改日志或补造完成事件不构成修复。

寻路代价、预约时间公式、速度与释放规则沿用现有 HCA。新的编号可能影响 Java HashMap 的遍历顺序，因此这是单独标识的执行修复版，不称与旧轨迹完全等价，也不称恢复了旧运行缺失的 class 身份。源码和编译结果逐文件 SHA、编译器、Java 版本、命令及输入身份在预检前记录并在全部正式运行中锁定。若原生实现需再改动，原先预跑单独保留，不能混为同一版本矩阵。

- 仿真从 epoch 8260 开始，最多 90000 个整数 epoch，末 epoch 98259；无故障、无修复事件、速度 2.5 m/s、无任务截断，不额外扩大任务量。未完成、不可规划和到达时域上限的任务保留，不删袋或种子。

- TH 为到绝对 epoch 98259 的完成原始行李数量，不能直接解释为每小时峰值容量。

## 预检与正式运行

首先用独立微测试验证普通单段、同一行李重叠双段、唯一编号映射、重复完成拒绝及段状态守恒。再执行南宁 1× 的三个历史异常种子 155921、181081、232003，以及 map2 1.75× / seed 104729、南宁 2× / seed 104729 的完整人口预检。高载预检不要求全人口完成，只要求每个段的终态可解释且指标口径合格。

预检若与最终冻结实现、输入及命令一致，可作为正式 60 格中的对应结果，不额外选取更好的重复。预检通过后，以同一版本补齐其余 55 格。每格独立 Java 进程和输出目录，默认 4 并发、每 JVM 1536 MiB 堆，禁止同格并行重复启动。错误停止并保留证据；再次调用只能核验并复用同版本已完成格，不能覆盖冲突档案。

原始人口必须可以分解为未释放、待规划、执行中和已完成的段；同一段不能同时出现在互斥终态。每个完成事件必须唯一对应 canonical 段，原始行李仅在所有段完成时计入 TH。全程保留实际释放、成功规划、完成、段身份映射、终态任务记录及逐段/逐袋派生结果，并压缩保存可重算证据。段账目通过并不单独证明所有连续时间物理约束正确，报告须说明微测试与原生轨迹证据的覆盖范围。
