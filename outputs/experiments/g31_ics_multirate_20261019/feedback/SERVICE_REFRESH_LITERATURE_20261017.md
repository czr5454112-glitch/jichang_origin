# 服务预测刷新：原文核验、复用前提与实现边界

日期：2026-10-17。本文是后续实现和独立审阅的研究依据，不是新算法证明、代码完成记录或性能报告。只使用实际打开的论文原文及作者版本记录，不把之前审阅文件中的引用直接视为已经核实。

总体目标不变：在去中心化、有限托盘、载货与返空共网的 ICS 中，联合考虑当前载货服务和空盘后续供给；保持实际信息权限、已发命令语义与严格逐件保护。完整请求 100ms 目标不因本文调整。当前有限候选集合不是最终系统必须固定采用的候选规模。

## 核验范围与主要结论

本次重点阅读四份原文的相关建模、触发或分解章节，并补读第五份作者 PDF 的摘要、引言、系统假设和优化问题。没有复现这些论文的优化器、实验或定理证明。网页抓取日期不作为发表日期；预印本按所读具体版本引用。

文献支持将“每次检查是否需要更新”与“每次重新求解全部预测/优化”分开，但不支持在缺乏有效性依据时任意延长刷新间隔。也不支持用旧预测替代当前观察，或把总成本改进转换成每件任务不退化。温启动、局部分解、保留回退方案和事件触发本身均不是本项目的新颖性结论。

## 一、已核原始来源

### L1：联合行李路由、线平衡与空车管理 MPC

Yashar Zeinaly、Bart De Schutter、Hans Hellendoorn，*An Integrated Model Predictive Scheme for Baggage-Handling Systems: Routing, Line Balancing, and Empty-Cart Management*，IEEE Transactions on Control Systems Technology，23(4)，1536–1545，2015。

[作者全文](https://www.dcsc.tudelft.nl/~bdeschutter/pub/rep/15_019.pdf)；[DOI](https://doi.org/10.1109/TCST.2014.2363135)；[作者机构出版记录](https://research.tudelft.nl/en/publications/an-integrated-model-predictive-scheme-for-baggage-handling-system/)。作者 PDF 共17页，含封面，不能直接把其 PDF 页码当期刊页码。

核读定位：§II-A 的 A1–A4，§III 开头与 §III-A，§III-C 式(28)–(29)及脚注3。论文每步根据当前状态及预测需求求解，执行首步；上一时刻输入序列可用于初始化新预测。其模型使用连续流近似，目的端行李队列有简化假设，时间窗以软成本处理。

可迁移：装载、运输、卸载回供和空车调配应联合考虑；旧解可用于温启动。不可迁移：流量目标或软时间窗并不证明离散 FIFO、有限泊位和实体复用下的逐件不劣；旧输入序列也不是当前仍合法的证据。不复制论文案例的采样周期或求解秒数作为本项目指标。

### L2：有扰动离散线性系统的事件触发 MPC

Daniel Lehmann、Erik Henriksson、Karl H. Johansson，*Event-Triggered Model Predictive Control of Discrete-Time Linear Systems Subject to Disturbances*，ECC 2013。

[作者全文](https://people.kth.se/~kallej/papers/event-triggered_ecc13.pdf)；[DOI](https://doi.org/10.23919/ECC.2013.6669580)。PDF 共6页。

核读定位：§III，式(7)–(10)，定理2及其假设。式(7)在实测状态偏离预测达到阈值，或预测时域耗尽时触发重算；触发时重新以当前状态锚定预测。其误差与稳定性结论依赖线性模型、有界扰动、相应可行性和稳定性条件。

可迁移：显式记录有效时域，状态偏差和时域耗尽均可触发更新。不可迁移：本项目尚未建立相应误差界，不能据此允许任意非零服务退化，或直接采用论文中的偏差阈值。没有新消息也不代表没有到期事件。

### L3：FICO 的有限时域兼容分解

Jiarui Li、Alessandro Zanardi、Federico Pecora、Runyu Zhang、Gioele Zardini，*FICO: Finite-Horizon Closed-Loop Factorization for Unified Multi-Agent Path Finding*。

[所读 v3 全文](https://arxiv.org/html/2511.13961v3)；[版本记录](https://arxiv.org/abs/2511.13961)。初版为2025-11-17；本次核验 v3 为2026-01-06。按预印本版本引用，不由网页标题推断正式会议发表状态。

核读定位：§V-B 定义 V.1/V.2、Remark V.3；§V-C 的 Lemma V.10/V.14 与 congestion resolution。已固定轨迹与重规划组必须在考虑时域内兼容；可达域相交需要合组，冻结轨迹堵塞可行域时需要扩大冲突组。

可迁移：先验证边界兼容，再固定未受影响部分；局部修复失败允许扩大范围。不可迁移：有限时域的无冲突组合不等于每件服务完成不延迟，也不允许只检查旧路径或预先固定一跳修复半径。其下一步运动可行性质不替代 ICS 的装卸、返空和多次复用义务。

### L4：CDCBS 的完整回退证书与可继承分解

Jiarui Li、Runyu Zhang、Gioele Zardini，*Certificate-Driven Closed-Loop Multi-Agent Path Finding with Inheritable Factorization*。

[所读 v1 全文](https://arxiv.org/html/2604.00428v1)；[版本记录](https://arxiv.org/abs/2604.00428)。本次核验版本为2026-04-01；此处依据该预印本，不把作者主页的会议标记当作已经核验的正式出版记录。

核读定位：§III-A/B，定义 III.2–III.4、Remark III.3、Lemma III.1；§IV-A/B，Lemma IV.2 和 Corollary IV.1。证书包含从当前状态到目标的完整无冲突续行；执行旧证书首步后才能继承尾部。预算约束下可达域收缩支持固定 one-shot 实例内的分组继承。

可迁移：保留经验证仍有效的回退方案，候选未改善时不必替换。不可迁移：fleet budget 是总成本条件，不是逐件完成保护；新任务、资源变化或未按原首步执行会破坏直接套用前提。本项目 initial04 的条件性预测不是该文所需的完整可行证书。

### L5：动态扰动下的事件式非线性 MPC——补充阅读

Pengfei Li、Tao Wang、Yu Kang、Kun Li、Yun-Bo Zhao，*Event-based model predictive control for nonlinear systems with dynamic disturbance*，Automatica 145，110533，2022。

[作者实验室 PDF](https://www.niclab.ac.cn/assets/pdf/2022-Event-Based%20Model%20Predictive%20Control%20for%20Nonlinear%20Systems%20with%20Dynamic%20Disturbance.pdf)；[DOI](https://doi.org/10.1016/j.automatica.2022.110533)。本次补读 PDF 第1–3页的摘要、§1、§2 和 §3.1，未核完整证明及实验。

引言明确区分每步检查触发条件与仅在触发时求解 OCP；自触发方法另外计算下次触发时刻。§2 的系统是连续值状态的离散时间非线性模型，并有扰动界及 Lipschitz 假设，并非本项目的离散事件/FIFO 合同。

可迁移：轻量监测与昂贵求解分别计费、分别设计频率。不可迁移：没有对应模型与界就不能套用其误差、约束收紧和稳定性结论；“少求解”也不等于“不再检查当前状态”。

## 二、本项目的最小可迁移方案

以下是根据上述文献和本项目合同提出的实现建议，不是论文已经为本项目证明的性质，也不是已实现功能清单。

### 1. 先区分四种复用

| 复用对象 | 建议边界 | 不能替代的检查 |
|---|---|---|
| 静态图、动作模板、source 依赖元数据 | 在来源、实现及合同代际不变且原验证继续生效时复用 | 动态当前状态、owner 权限、原生接纳 |
| 同一当前上下文中的候选共享前缀 | 前缀动作、上下文、模型语义和隔离条件相同，计入实际 prefix/suffix 次数 | 未选候选不能提前完整推演；共享不能产生 mutable alias |
| 上一事件的解作为 warm-start | 只当作新求解的建议，依据新合法观察重新验证 | 不能继承旧 capability、旧预测 capture 或当前时效性 |
| 跨事件预测结果、影响分组或完整后缀 | 须先建立覆盖依赖和有效边界的充分条件；未建立时保持待验证 | 不能仅凭时间较近、预测相似或没有收到新消息继续使用 |

初版应实现只读的“需要刷新及原因”判定器，而非直接启用跨事件预测缓存。对每份建议登记来源版本、观察时刻、模型代际、实体身份、动作前缀、依赖资源、覆盖时域和下一必要检查点。判定器不拥有提交权，也不能生成当前观察。

### 2. 服务影响范围必须覆盖完整循环

影响关系至少应包含：载货任务 → 运输与装卸/暂存服务 → 托盘释放 → 返空与接收 → 下一次装载 → 后续运输服务；同时覆盖 FIFO 前驱、边进入间隔、泊位/接收容量、服务日历、既有路线偏好和已发请求。

从已实际送达且校验通过的变化开始，沿可能改变可行性或受保护完成时刻的依赖扩张至闭包。依赖覆盖应包含候选新绕行可用资源，不能只覆盖旧计划。没有有效跨边界条件就继续扩大；最坏回到全当前状态重算，并如实报告没有局部性优势。

已执行、已提交或可能已提交但未收到 ACK 的动作均属冻结边界。对方条件性未来提案不是已兑现资源承诺，不能作为不可变外部轨迹使用。若修复需要改变对方未来选择，必须重新协商并取得真实权限，不能由缓存或本地模型替代。

### 3. 必须保留的失效触发

- 新任务、需求或服务合同变化，以及任务取消或身份变化。
- 托盘位置、business identity、generation、traversal、装卸/Storage 状态变化。
- FIFO 前驱、占用、接收预留、边 headway、服务日历或已安装偏好变化。
- 新命令提交、拒绝、超时、ACK 更新，以及不可撤前缀发生变化。
- 消息过期、来源缺失、乱序或覆盖不足；重复事件去重不能回退已经确认的状态。
- 来源、模型、动作语义或保护参照身份变化。
- 预测时域、已知服务边界或授权有效期到期；即使没有新消息也需检查。

可以同时保留周期性检查和事件触发重算，但周期必须由有效时域、服务边界、通信与动作窗口约束，不在本文预设秒数。观测不足是 unknown，不是“预测偏差为零”。

### 4. 刷新失败时的回退

保留原逐件参考，不以新事件后的较差预测静默抬高基线。候选需同时满足原逐件规则和当前动作条件；总成本较好但某件变差仍拒绝。

重算失败或超预算不自动授权继续旧方案。只有经当前证据重新确认仍合法的原策略动作才可提交；否则保留 unknown/拒绝。已发动作不能取消重写，retry 保持原身份和 payload。`native_default` 仍表示不发新路线命令，不表示固定走某条边，也不清除既有偏好。

每次实际提交前继续检查当前 capability、owner view、own outbox、目标实体、原保护条件和 native 接纳要求。submit 返回、实际 ACK、进入目标边以及业务完成属于不同事实，不能互相替代。

## 三、建议的下一道验证门

先在已有保存轨迹上运行只读失效判定，逐事件输出依赖变化、影响闭包、保留与失效原因。随后在同一合法当前上下文中，与完整重算对照，严格核对预测、动作语义及逐件结果；未执行候选仍无实际业务标签。

至少保留以下反例：遗漏第二次托盘复用影响；新绕行触及旧图之外的共享资源；ACK 丢失后误把命令当未发；没有新消息但服务窗口到期；当前观察已经偏离旧预测；原回退方案在新事件下不再可行。任一依赖不能证明独立时，不通过截断闭包或放宽容差制造通过。

验证正确性之后才测计算收益。分别记录轻量检查、当前采集、候选评分、实际 prefix/suffix 推演、source/dynamic guards、保护选择、提交及必要结果处理成本；不能把整个模型阶段叫作纯预测，也不能用只求解时间替代完整请求时间。是否需要 ABBA、多个场景及更长运行，由后续实验预登记决定；本文不新增任何性能数字、速度优势或业务收益结论。
