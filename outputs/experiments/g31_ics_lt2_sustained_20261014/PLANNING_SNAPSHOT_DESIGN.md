The capture body contains the IDs, source/target, sequence, capture/expiry times, public static digest, semantics, job/tray/node/fault rows and coverage below. The source ACK self-copy renders status at its completion time so later reads are immutable; consumers must always recheck `capture.valid_until` against their current decision time. Capture bytes and hash, rather than a later recipient status, establish payload equality.

Independent read-only review found no concrete owner-membership or ACK chronology defect. The tests include a separately implemented typed digest encoder and mutation checks. Capture currently scans current jobs and historical receipts to reconstruct committed local facts; its full-request cost has not been measured and no 100ms claim applies to this new endpoint. No existing Python controller automatically calls it.

The smallest defensible extension is a new native `planning_snapshot` protocol command whose only caller-supplied facts are request identity, source and target owners, message/publication delays, and a declared absolute expiry. Native source execution captures a typed, immutable local payload. The existing demand message remains unchanged. Route, transfer, FIFO, storage and stock protection rules remain unchanged. The new message is evidence for a conditional plan, never a reservation, remote inventory assertion or grant.

## Payload and information boundary

The envelope should contain `schema=g31.planning_snapshot.v1`, typed `kind`, `message_id`, `source_owner`, `target_owner`, source-channel `publication_sequence`, `captured_at`, actual `delivered_at`, `valid_until`, a public-static-contract digest, a payload digest, and explicit coverage metadata. Use a length-prefixed source/target identity or another unambiguous encoding; do not expose a global event or traversal counter. Expiry is a declared protocol lifetime, not an estimate of equipment availability. Digest the immutable capture body independently of actual delivery metadata so recipient payload and source ACK self-copy can be compared exactly.

The capture set is native-defined: every currently local tray, all released waiting obligations at source-owned origins, and obligations carried by those visible trays. Preserve deterministic input order and native public traversal versions. Do not let a caller select only the convenient jobs and then label the result complete. Origin contracts for handed-off jobs may be retained only as static historical contracts with `handed_off` masking, matching the existing observer; they cannot disclose remote live progress. No unreleased job, future fault, global runtime ID, remote queue or future native event enters the message.

| Typed row | Allowed captured fields and limits |
| --- | --- |
| Job obligation | Native ID, origin/arrival/deadline, destination, mandatory storage node and release/minimum dwell, load/unload/hold durations, protected-service and suffix-reroute permissions. These are known contracts of released local obligations. Include the local status and only locally observed lifecycle facts; mark nonlocal progress unknown. |
| Tray | Native public ID, node, mode, carried job ID, generation, public traversal version, `edge_from`, `edge_to`, reception node, committed prefix and locally observed availability. Never publish the global internal traversal ID or runtime leg ID. |
| Local service readiness | A tagged value such as `committed_local_service_end` from the tray's actual source calendar while it is in service, or `observed_load_completion` from a local LOAD_START plus the contract duration. A queued carrier with no committed service end gets unknown; do not silently call `now` its exact departure time. A deterministic edge completion derived from an observed local entry is a commitment-derived bound, not a downstream clearance guarantee. |
| Local node | Source-owned node ID, native occupancy and actual empty availability, plus coverage of represented trays/jobs. Occupancy may include a committed incoming berth whose remote carrier is not locally visible. Any unmatched occupancy must cause the prototype to report unknown, rather than inventing a remote carrier identity or treating the berth as free. |
| Known fault | Only source-delivered/advertised fault facts, including their observation/delivery provenance. No future outage tape or unannounced closure. |
| Coverage | Exact covered local node/tray/job IDs, capture scope, counts, and explicit unknown/unrepresented commitments. Completeness means this declared local scope at capture time, never a closed-world assertion about future arrivals. |

The static descriptor must explicitly enumerate public node/edge records and contracts, ownership/partition mapping, minimum service duration and the applicable fixed scheduling rules: FIFO, R3 node windows, E4 destination merge, S3/S4 reference choice and merge timing/rule. The native binding sets these in `circulation.cpp:g31_config`. Hashing the whole input or checkpoint would reveal private future arrival/fault data. A mismatch between sender and solver static descriptors is unknown, not a reason to coerce the model.

For the current synthetic chain, A needs to publish loaded L's destination6/mandatory Storage4 contract and the currently waiting receiver's destination4 contract; B needs the two released reuse obligations to destination6. Both also publish their actual local tray/node state and complete coverage. Those fields are sufficient only for the validated stationary, fully covered domain. Inflight trays, unrepresented incoming occupancy, unsupported service-calendar cases, additional current jobs or missing timing facts must stop the finite-domain predictor with an explicit unknown. The 117 offline action checks and 102 exact vectors are model evidence; they are not authorization to widen this domain silently.

## Delivery, retry, expiry and self-copy semantics

1. Submission validates owner namespace, known source/target, finite nonnegative delays and finite declared expiry. The only mutable caller choices are message intent and lifetime. Reject fabricated `jobs`, `trays`, `service_ready_at`, `captured_at`, digests and other payload keys instead of ignoring them for this new command kind.
2. The first native `protocol_command_wire` execution waits for source availability exactly like demand. Reject an already expired intent before capturing. Record actual capture at that execution time, not submission time.
3. Capture once and schedule native target delivery. Any retry after execution returns the existing result/pending state and never refreshes jobs or local timings. Source and recipient outages use the existing waiting flags; recipient recovery delivers the original bytes.
4. On target delivery, set actual delivery time and notify only the target. Preserve a delivered snapshot even if its expiry has passed; expose it as expired/unusable so an older revision cannot revive. A late-delivery final ACK can explicitly carry `expired` and the immutable result reference. A timely final ACK carries `delivered`. Do not use the old `service_forecast` vector or change demand's replacement rule.
5. Source self-copy is available only through a delivered final ACK referencing that exact snapshot, validated like the existing demand capture signature. It is not a live getter that reveals unacknowledged source execution or recipient uptime. The ACK must validate source/target, native index, message/result ID, capture time against executed time and delivery time against completed time. An old pending ACK must never acquire a later snapshot dynamically.
6. The recipient endpoint chooses the highest delivered revision per source channel before testing expiry. Retain the highest expired record as a tombstone. Never filter expiry first and accidentally choose an older record. Return new Python dictionaries on every call.
7. A reusable controller must schedule the declared expiry boundary as a real timer or revalidate it at every decision. The initial bounded prototype can decide once before the recorded expiry and then use the normal native request leases; it must report unknown after expiry rather than pretending it has fresh state.

## Required tests before using a live solver

- Alter a local queue between submission and source execution: only execution-time obligations appear. Alter it after capture and before delivery: message bytes remain unchanged.
- Mutate private future jobs/faults and unrelated-owner activity while current local facts are identical: capture body, public sequence, receiver view and source self-copy remain equal. Alter a known source-local storage gate: that captured contract must change.
- Recipient sees nothing before actual delivery. Source sees no self-copy before a delivered final ACK, including when an earlier pending ACK has arrived. Wrong-owner access and fabricated caller payload fields are rejected.
- Source and recipient outages, delayed delivery, ACK loss, duplicate ACKs, retries before/after capture, and out-of-order revisions all retain one immutable capture per request. Highest expired revision suppresses an older live revision.
- Snapshot/self-copy dictionaries are isolated from native state and one another. Captures survive native fork/restore before capture, after capture-before-delivery, after delivery-before-ACK and after duplicate/lost ACKs. State seals must differ if a snapshot field differs.
- Local service readiness uses observed starts/committed own calendars; queued unknown and unrepresented occupancy fail closed. Fixed synthetic coverage includes both trays and all four released obligations. Unsupported additional facts are retained or cause unknown, never dropped.
- With no planning commands, original full/compact/policy views, ordered serialization, original input physics and request tapes remain exactly unchanged against build019.
- The online prototype runs all three predeclared gate regimes with one fixed topology and tray set. It records actual capture/delivery/ACK times, waits for sufficient compatible snapshots, predicts at that later state, and compares all offered completion vectors to an equally informed baseline. It retains strict zero-regression protection and all unknown/failure outcomes. No old gate-specific outcome screening or full-information oracle selects an online action.
