## 5. 首闭环后 I1 的审查规则

I1 包含两项，不能混写：

1. **执行接通门**：真实同盘两次服务、Storage 进度依赖、卸载/hold、合法空盘返供、满载/拒绝/失败/迟到/无收益变体，以及 legacy 兼容性。
2. **方法增量门**：同 circulation 模型中 C1/C2 开关导致的合法动作与质量—计算变化。第一项通过仍不意味着第二项通过。

本轮 I1 首次真实事件账见第 7 节；各变体未生成数据前不填写预期成功数，也不把外部审核的 1519 项当作本轮新结果。最优状态只接受同模型完整参考/界；可行事件见证应明确写“可行，最优未知”。

后续强基线固定为：同宿主反应式空盘、最强同权限解析预测、单向预测、一轮反馈、同信息滚动约束优化/小域完整参考、新闭合修复无学习、同机制加学习。基础物理和权限公平共享；核心修复算法通过消融区分；全状态中央 oracle 另列信息优势。

## 6. 必须执行的机制反证与接入顺序

| 反证/负对照 | 诊断目的 |
|---|---|
| 同终点常数价值 | 验证动作相关量确实能改变排序；只有训练损失下降不算业务增量 |
| 下游满缓冲 → 延迟盘释放 → 别区源保护 | 检验依赖闭合，防止固定地理半径遗漏远处供给后果 |
| 相同当前信息、未来分别在供区/受区突发 | 明确保护合同与预测不确定性，不以事后删任务掩盖外调代价 |
| 多条长线、预测反转、消息陈旧/丢 ACK | 验证授权失效、真实在途及晚到幂等，不允许凭消息创造盘 |
| 盘充足或没有共享瓶颈 | 接受无收益；若持续“普遍改善”，先查模型、输入、权限、计量是否不公平 |
| 强解析/一轮反馈追平 | 检查是否仍有相同质量下计算节省；否则停止当前优越主张，重构具体机制 |
