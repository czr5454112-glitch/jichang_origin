# G4IRSF17 new ideas and evidence

This is an append-oriented research notebook. An item is labelled **verified** only after a code path, test, or experiment supports it; otherwise it remains a hypothesis.

## 2026-08-06

### Reuse causal infrastructure, remove administrative weight

**Verified repository fact.** The native runtime already exposes a true I1 source-order swap at the same source queue and natural service opportunity. The G15 outcome-free target catalog contains 1,650 I1 entries, of which G17's stricter real-competition filter retains 1,648 executable opportunities. G17 can therefore execute real paired interventions without introducing a parallel scheduler.

**Implementation decision.** Keep the state/action identity checks required by the native causal seam, but do not make hashes a research deliverable or spend the campaign re-sealing unchanged G15/G16 shards. G17 evidence centers on effect sizes, safety, coverage, tails, faults and scaling.

### Treat wait as a conserved flow quantity

**Hypothesis to test.** H5's better network time and worse source wait suggest that local actions can move congestion across the admission boundary without reducing system work. Source and merge policies should therefore optimize a bounded externality-aware utility, not the selected bag alone, and reports should show `source wait + network time = total controllable time` decomposition.

### Diagnose pressure before choosing I1 or G2

**Implementation decision.** Every failed source admission receives one deterministic primary blocker from the real path. Attribution uses waiting seconds, not blocker-event counts. If destination capacity/merge-token blockers dominate the added wait, G2 starts immediately while I1 remains a bounded pilot.

### Separate control quality from compute scalability

**Verified prior evidence.** The `+0.091 s/raw bag` result is simulated business time, not C++ execution overhead. G17 therefore reports TTH/source/network outcomes separately from wall time, decisions/s, events/s and RSS, and optimizes code only after profiling.

### Keep the paper's ordering anchor, test extensions honestly

**Verified source fact.** `legacy/jichang_origin_readonly/src/RUN/Main.java` sorts each source-local task list by `(int)(left.pass_time - right.pass_time)`; the fault-replanning list uses the same comparator. This supports FIFO/pass-time as the localized paper anchor.

**Implementation decision.** Deadline slack, bounded aging, leg type and one-shot repair priority are useful G17 extensions, but are not attributed to the original comparator. They are evaluated as a separate deterministic candidate alongside FIFO/current Q0, linear pairwise and tiny-MLP families.

### Downstream pressure, not source-local service, caused the H5 loss

**Verified 8,192-segment evidence.** The matched cohort contains 4,898 raw bags. H5 added 732.5 source-wait bag-seconds while removing 286.6192 network bag-seconds, for a net 445.8808-second TTH regression. Aggregate native interval reconciliation attributes all 732.5 added source-wait bag-seconds to `DESTINATION_MERGE_TOKEN`; the source-service contribution is zero. This is an aggregate cell reconciliation, not a claim that individual bags have been assigned a causal blocker.

**Decision.** Keep I1 as the promised bounded causal pilot, but move the main control-design budget to the downstream token boundary.

### A scoring rule is useful only when the runtime exposes a choice

**Verified 144/512/2,048/8,192 screen.** Twenty matched comparisons covered M1 FIFO against M2--M6, using 24 real native arms in total. Every arm passed hard safety, yet every exact arbitration counter reported zero boundaries with at least two live eligible requests. The pending-grant peak was one and every raw-bag TTH/source/network delta was zero.

**New design direction.** The eager token implementation reserves a future service slot as soon as each request arrives, so M1--M6 never receive a real choice even under the 8,192-segment load. The next G2 seam should keep a bounded, strictly local pending set and issue the token just in time for the next natural service slot. That creates a genuine local MAPF-style reservation decision without a global scan or an artificial batch delay. Re-scoring the current eager seam is a no-go.

### Separate a trainable local label from system authorization

**Verified integration finding.** A hard-gated H_bag swap observes both directly reordered bags and can train a bounded-local ranker on their summed effect. It does not observe downstream system externality. The training protocol now accepts that two-bag cohort for model fitting, while requiring real H_system observations before any externality authorization. Native closed-loop remains fail-closed until later shadow and system gates pass.

### Preserve the denominator of each verified workload protocol

**Verified runtime finding.** The G10 source-queue protocol quantizes Java release time to the epoch and can place it less than one second before the floating raw entry timestamp. G17 therefore keeps original-entry TTH for the protected ladder and explicitly uses Java-release TTH for the G10-derived fault/scale matrix. A real 144-segment scale-input smoke completed with the new branch and reconstructed `source wait + network = Java-release TTH`; the old original-entry branch remains strict.

### Count fault mechanisms, not duplicated labels

**Verified catalog correction.** The first noncritical and merge-incoming selectors originally chose the same physical edge. The noncritical case now selects the next reachability-preserving alternate edge and records that it also enters a different merge on this map. Recovery gates additionally require actual affected-bag completion, zero stranded bags, recovery telemetry and fault/repair events; a censored or unobserved mechanism cannot pass by label alone.

### Grandfather proven in-flight work, never an unsafe new entry

**Verified native and real-campaign finding.** A bag may enter a healthy edge with an exact destination merge grant, then observe a real physical-fault generation change before edge exit. Revoking that already-committed traversal at exit stranded one real segment in the 1× noncritical-edge campaign. The runtime now consumes the still-exact destination lease only when the same grant, owner, directed edge, destination, unexpired slot and exact calendar reservation all match, a healthy `EDGE_ENTER` proof was recorded, and the local edge fault-instance history proves that the physical fault began after entry. A raw generation mutation alone still fails closed.

**Evidence.** The real 43,603-segment `(6,12)` job changed from one `destination_merge_grant_rejected_at_edge_exit` failure to `COMPLETE`: the new recovery counter is 1, all 23 fault-affected bags completed, failed segments and stranded bags are zero, unsafe edge entries are zero, and the hard-safety gate passes. The original eleven negative edge-exit cases retain recovery count zero. This is a bounded one-edge MAPF-style lease rule, not a global exception.

### Bind coordinated model artifacts without hash ceremony

**Verified integration decision.** Phase-D pairwise and selective-gate exports now share one readable `artifact_set_id`, which is carried through the Python adapter, native configuration, summaries and decision traces. Both the Python adapter and native parser reject a deliberately mismatched pairwise/gate set. This prevents accidental cross-run model/gate splicing while avoiding SHA-based packaging work that does not advance scheduling quality.

### Stop I1 when the real frame makes its support gate unreachable

**Verified 512-address evidence.** Of 512 real H_bag addresses, 248 changed the native source winner and passed causal/safety gates: 18 were beneficial, 16 harmful and 214 neutral. All eight bounded H_system pairs were eligible and one was harmful. The available frame contains 1,648 nominally competitive addresses but only one source and one leg class, so neither more resampling nor a 1,024-address run can satisfy the frozen 3-source/2-leg support gate.

**Decision.** This is a frame-scoped I1 support no-go, not a claim that source ordering can never matter. Keep the learned families as transparent diagnostics/risk selectors, leave runtime authorization false, and spend the next causal budget on the JIT bounded G2 merge-token seam already indicated by the source-wait evidence.

### Compare only observations from the same decision boundary

**Verified schema finding.** The exact G16 29D vector exists at junction dispatch, while the I1 label is created at a source-front bag-order boundary. Serializing the junction vector against the source-order label would be a proxy with mismatched action semantics. G17 records `LEGACY_29_NATIVE_SNAPSHOT_UNAVAILABLE` instead of manufacturing that comparison.

**Verified canonical ablation.** On the 248 eligible H_bag rows, a real native 18D static-local subset versus the full 39D source/temporal/pressure/merge observation reduced nearest-neighbor conditional variance from 0.19461 to 0.14111 and sign conflict from 0.813% to zero, with coverage changing from 99.19% to 90.73%. This supports the added local temporal context within the I1 boundary, but is deliberately not reported as legacy-29 superiority.

### Treat 2x load as a measured capacity knee

**Verified release-scale evidence.** Fixed-map input doubled from 43,603 to 87,206 segments and still completed with every hard gate passing, but mean TTH rose from 217.58 to 1,388.01 seconds and P95 from 270.05 to 7,967.05 seconds. Source wait contributed 84.19% of the mean increase and affected 34.62% of bags versus 1.78% at 1x. Decisions stayed near-linear at 2.011x, while events grew 2.829x and CPU per event 1.921x, producing 5.436x total CPU.

**New optimization direction.** The next scalability work should target bounded source-admission/backlog control plus profiling of event-queue and merge bookkeeping. Higher-load outcomes remain explicit COMPLETE, hard-boundary or censored observations; they are never extrapolated into wins.

### Publish causal signal, not dense zero-delta replicas

**Verified evidence-compaction result.** Each H_system checkpoint retains the full local runstate, but its tens of thousands of dense cohort rows duplicate separately stored realized deltas and sufficient aggregates. Omitting only those redundant rows reduced one representative compressed chunk from 10.458 MB to 0.028 MB and the final 520-pair science-facing dataset to 0.924 MB. Effect calculations, coverage counts and externality metrics are unchanged, while Git history stays usable.

### Make capacity censoring a terminal scientific result, not a missing cell

**Verified 4x control boundary.** The exact-equivalent fixed-map E4/off no-fault scale control reached the frozen 20,000,000-event cap after completing 10,093 of 174,412 segments. It consumed 3,905.02 CPU seconds, 3,963.75 worker-wall seconds and 2,328.84 MB peak RSS, and failed the completion hard gate. The same execution semantics would reach that cap within the shorter 7,200-second fault timeout.

**Protocol amendment.** Phase G reuses this control once as `CAPACITY_CENSORED_BY_EQUIVALENT_CONTROL`. The ten remaining 4x fault treatments stay visible but terminal as `NOT_RUN_CONTROL_CENSORED`; they are not executed, evaluable, passed or failed, and no synthetic result checkpoints are created. The 1x fault matrix remains complete, the original 4x matrix remains incomplete, and 4x fault advantage is explicitly `NOT_ESTIMABLE`. This saves compute without manufacturing evidence.

### Keep a verified micro-optimization in its proper scope

**Verified two-repeat profile.** Reserving the event priority queue for `requests + 2*fault_windows` before initial pushes preserved exact status, completion, TTH tails, source/network time, event/decision/beacon/PIBT counters and every hard-safety gate. Relative to the 1x baseline, two optimized repeats reduced mean CPU from 28.7656 to 27.8203 seconds (-3.2863%) and mean worker wall time from 28.9874 to 28.2399 seconds (-2.5787%), with peak RSS near 1,398.60 MB.

**Claim boundary.** This is a safe initialization improvement, not a solution to 4x event amplification or source-admission overload. Those remain algorithmic capacity targets.

### Treat abstention as a first-class closed-loop result

**Verified reporting correction.** No learned or deterministic I1 candidate passed the offline authorization gate, so running a candidate ladder would violate the promotion protocol. An empty CSV was nevertheless ambiguous: downstream reporting could mistake deliberate abstention for missing evidence. The ladder now publishes one explicit `TRACK_STATUS` row with `BASELINE_ONLY_NO_AUTHORIZED_CANDIDATE`, the five completed E4/off baseline levels, zero authorized candidates and no invented matched delta.

**Reusable lesson.** In a safety-gated decentralized controller, "keep the verified local baseline" is an executable decision, not an absence of work. It should be represented as structured evidence rather than inferred from an empty table.

### Separate workflow terminality from scientific matrix completeness

**Verified protocol correction.** The capacity-censored 4x fault control makes the remaining 4x treatments non-evaluable under the frozen protocol. The workflow can therefore reach a terminal, actionable pivot while the originally requested scientific matrix remains incomplete. G17 records these as separate axes: `workflow_terminal=true`, `protocol_amended=true`, and `scientific_matrix_complete=false`.

**Reusable lesson.** Collapsing those axes would either leave a permanently non-resumable campaign labelled `IN_PROGRESS`, or incorrectly promote capacity censoring into `FULL_NO_GO`. The two-axis state keeps the stopping decision honest without manufacturing evidence.

### Measure the capacity curve to its bounded terminal states

**Verified 1×–16× evidence.** The exact E4/off fixed-map baseline completed 43,603/43,603 segments at 1× and 87,206/87,206 at 2×. It then reached the frozen 20,000,000-event cap at every higher load: 10,093/174,412 segments at 4×, 11,123/348,824 at 8× and 14,127/697,648 at 16×. CPU/RSS rose from 3,905.02 s/2,328.84 MB at 4× to 6,516.64 s/2,990.55 MB at 8× and 9,944.13 s/5,174.64 MB at 16×. These are measured hard-gate failures, not extrapolations or scale wins.

**Denominator boundary.** The segment progress ratios above use completed requested segments. The published `completion_rate` field for 8×/16× uses completed raw bags divided by the Java-release-TTH raw-bag cohort and is therefore 0.018198/0.010156; it must not be silently substituted for segment progress. Both measurements are useful only when their denominators stay explicit.

### Partial queue telemetry is evidence, not a cross-scale bound

**Verified 16× observation.** The 16× terminal row records a source-queue peak of 49,116, a source-delay peak of 50,030.751 seconds and a junction-queue peak of 32. It also retains zero full A* calls, zero global scans, zero future-route reads/stores, zero unsafe entries and zero conflict violations. The overall hard gate still fails because of incomplete coverage, the event cap, starvation and 13 unresolved deadlocks.

**Claim boundary.** Only one of the five required scale rows has the new per-node queue fields. The evidence therefore diagnoses severe source-side accumulation at 16× but cannot establish a cross-scale queue-peak curve or fixed bound. Aggregate TTH/source-wait/event counters are not used as substitutes for the missing 1×–8× node-level observations.

### Optimize where the decentralized runtime actually amplifies work

**Verified capacity diagnosis.** From 1× to 2×, mean/P95/P99 TTH increased 6.379×/29.502×/35.342×. Source wait accounts for 84.19% of the mean increase. Event count increased 2.829× and CPU per event 1.921×, jointly producing 5.436× CPU. Near-linear decision count is therefore not enough to make the system scalable when admission pressure and event/merge bookkeeping amplify superlinearly.

**Actionable hypothesis.** Keep the strict-locality contract and separate three bounded interventions: (1) source-admission/backlog control, (2) just-in-time destination service-slot arbitration over a bounded pending set, and (3) event-queue/merge bookkeeping reductions with exact semantic parity. This targets the observed failure mechanism without reintroducing centralized A* or treating a learned policy as authorized before it earns a real decision seam.
