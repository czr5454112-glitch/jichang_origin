# ICS V3 第二阶段交付与实验记录

日期：2026-10-09。依据用户提供的 V3 研究设计继续实现。本文记录已运行的代码与实验，不把设计建议、合成代理或纯路由测量写成现场验收。

本轮已做出可恢复的有限盘闭环、首个安全前缀干预、区域门点候选、预测预调，以及两种线性价值模型。实际结果支持继续使用更强的时间化解析评分作为主要对照；尚未证明残差学习具有稳定优势，预测预调也不是在所有场景都获益。

## 1. 可运行的新增能力

实现位于 [独立实验目录](../../scripts/experiments/ics_circulation_v3/)，入口、参数和复现命令见 [PHASE2.md](../../scripts/experiments/ics_circulation_v3/PHASE2.md)。本轮没有修改旧 G31/native/Java 路由链路，也未改动工作区原有的 C++ 修改。

|部分|本轮实现|明确边界|
|---|---|---|
|连续运行与干预|保存/恢复完整账本、在途、成本、事件阶段和策略状态；从真实可达中途状态分叉|未来轨迹仅由事件引擎消费，不交给策略|
|安全前缀|载盘候选先检查完整见证，再执行至首个可等待节点；不可等待链整体提交|硬保护任务保留完整承诺；非保护任务才逐段重选|
|资源授权|提交时复验版本、容量、接收与代理模块权限；资源所有者串行化提交|不是分布式通信协议，也没有证明任意故障下递归可行|
|区域候选|控制分区门点宏图、非负搜索下界、局部时间细化、有限候选/展开/预算|每个区内宏边仅一个静态见证，可能遗漏动态拥堵下的替代路线|
|预测预调|真实盘首次可用事件、旧在途、已有调拨义务、源节点/源区需求前缀保护|有预算的贪心方法；原供应方模块仍是固定代理|
|模型与学习|时间化共享通道解析评分；同样 23 个可见特征的直接成本 ridge 与解析残差 ridge|未训练 MLP，不是 PPL 或 DG-PG 原算法|

硬保护任务先于两种软决策顺序申请完整资源。不能接纳的任务仍保留并记下失败，不以 `protected=True` 自动推断一定按时完成。学习实验中的目标是**可重规划、软截止期任务**，不将其收益外推到硬保护任务。

## 2. 本轮发现并修复的问题

第一处是保护任务在逐段执行中可能丢失后续资源承诺。现在对保护任务保留完整行程预约，并在两种协调顺序前先处理保护任务。

第二处是把“预测名义时刻已过”当成需求消失。联合实验中，C 节点没有入边，预测 6 tick 到达的行李实际 8 tick 到达，旧逻辑可能提前导出 C 唯一的盘，之后无法补回。现在带身份但尚未观察到的需求仍处于 pending：实际到达、已发布新版明确取消或 TTL 到期才解除；先取最新发布版本，再处理取消与过期，避免旧预测复活。TTL=60 是合成规则，不能直接认作现场规则。

第三处是最终接口审查发现同 ID、同发布时间但行李身份不同的消息没有被拒绝。补充了同版本语义冲突检查，并单独复跑 16 次预调与 144 次联合实验：输入、成本、完成指标和事件轨迹与此前结果全部一致，联合实验的行李账本和最终状态也逐份一致。该接口修复与此前确认实验使用的源码分开保存，避免把新代码哈希写入旧测量结果。

旧失败输出和源码均保留。首次联合实验的预测策略只完成 93 或 94 / 97 件；修正生命周期后六策略均完成 97 / 97 件。004、018、019 的 18 个定向分支也全部恢复 5 / 5 完成。这是已见场景回归，不能作为新的泛化证据。

## 3. 路由测量

### 同场景的小图对照

24 个场景 × 3 次重复 × 2 个候选生成器，共 144 个请求。72 对候选的边、出发/到达、卸载与空盘可用时刻完全一致；全部通过同一授权器并提交。交替执行两种生成器，使用相同的 horizon=48、展开上限=2000、K=3。

|生成器|平均请求时间|P95|最大|
|---|---:|---:|---:|
|逐时间展开参考|52.610 ms|60.314 ms|64.492 ms|
|区域门点生成器|0.827 ms|1.000 ms|1.528 ms|

计时包含生成、完整复验和首个候选提交，排除初态复制、场景构建、文件 IO 和通信。套件开始前清空缓存，随后允许复用。这是小图上与现有 Python 参考生成器的对照，不能写成对旧 G31 或机场全系统的加速结论。原始结果：[tiny summary](../experiments/ics_circulation_v3/tiny_matched_routing_20261009/summary.json)。

### 南宁真实拓扑的纯路由代理

使用 151 节点、227 条原始有向边，在 4 / 8 / 16 个合成控制分区上各取 100 个可达 OD，共 300 个独立请求。全部通过代理授权并提交，首个路径长度全部与静态最短路一致。

|合成分区数|有效请求|返回完整 K=3 的请求|本地请求 P95|最大|
|---|---:|---:|---:|---:|
|4|100 / 100|83|3.955 ms|5.590 ms|
|8|100 / 100|78|3.934 ms|4.741 ms|
|16|100 / 100|83|5.161 ms|16.440 ms|

其余请求明确返回部分候选集合，不将“未找到 3 条”写成不可达。原图 97→98 的记录容量为 0，代理中关闭，导致全部装载点—卸载点可达 OD 从 462 降至 396，**损失 66 个 OD**；抽样来自关闭后的 396 个，未把损失的 OD 悄悄算作成功。

这里节点容量固定为合成值 4、所有节点允许等待、服务时间从纯路由测量中排除；边时间向上取整为秒，原正容量仅按记录映射，未验证其真实占用语义。每次只有一盘，没有拥堵业务流和实际网络通信。因此 300 次均低于 100 ms 仅说明这个本地代理可运行，不能据此宣称机场端到端 100 ms 合同已经通过。[完整代理参数与结果](../experiments/ics_circulation_v3/nanning_routing_100od_20261009/summary.json)。

## 4. 预调与快慢联合闭环

四个机制场景、四种控制策略共 16 次运行，初态与真实未来配对，有限盘身份保持不变：

|机制场景|反应式成本|预测＋反应式成本|解释|
|---|---:|---:|---|
|长连接需要提前出发|8.8|0.8|等盘时间从 8 降为 0|
|已有旧在途供给|0|0|没有重复补盘|
|源节点近期用盘|5|5|没有挪走源节点所需盘|
|预测需求反转|0|20.6|已接受调拨不可撤回，额外等盘 14|

最后一行是真实保留的负结果：合法调拨不等于业务上必然有益。

另以 24 个场景比较基准/时间化解析两种快层，以及反应式、先路由后预调、先预调后路由三种慢层设置，共 144 次。生命周期修正后的结果如下：

|快层＋慢层|平均成本|完成|按时完成|
|---|---:|---:|---:|
|基准＋反应式|15.5417|97 / 97|48 / 97|
|基准＋先路由后预调|15.6208|97 / 97|48 / 97|
|基准＋先预调后路由|15.6208|97 / 97|48 / 97|
|时间化解析＋反应式|15.1250|97 / 97|49 / 97|
|时间化解析＋先路由后预调|15.2042|97 / 97|49 / 97|
|时间化解析＋先预调后路由|15.2042|97 / 97|49 / 97|

预测控制多发出 3 次空盘调拨，平均成本增加约 0.0792；本批场景没有显示两种协调顺序的差别。**完成率不是按时率**，此处也没有硬保护任务，不能以保护迟到为零推导保证成立。

结果分别见 [四机制实验](../experiments/ics_circulation_v3/phase2_prebalance_20261009/summary.json)、[联合修正回归](../experiments/ics_circulation_v3/phase2_joint_corrected_20261009/summary.json)。最后的同版本消息冲突校验另有 [预调语义一致性](../experiments/ics_circulation_v3/phase2_prebalance_interface_checked_20261009/semantic_comparison_to_prior_final.json) 和 [联合语义一致性](../experiments/ics_circulation_v3/phase2_joint_interface_checked_20261009/semantic_comparison_to_prior_final.json)；不覆盖前述历史记录。

## 5. 冻结模型后的学习确认实验

训练 / 验证 / 候选测试分别为 80 / 20 / 40 个源场景，另有 40 个独立完整部署场景。每个源场景的快照、候选与所有外生分支保持在同一集合。标签从 tick 2 的可达中途状态出发，对 4 个候选在 2 条共同未来下执行首个安全前缀，然后使用相同因果继续控制器。

正式生成 560 条候选记录、1,120 次真实分支回放；公开预测回放基准另花 560 次标签阶段模拟和 320 次部署嵌套模拟。6 个策略在独立场景完整执行 240 次。归一化仅拟合训练集，正则强度仅按验证集选择，模型在测试和部署前冻结。最终 direct α=100，residual α=10，23 个输入特征相同。

首次实验暴露生命周期错误后，使用 `confirm1` 名字空间生成新的候选测试和部署源场景；训练/验证不变，两份最终模型文件与首次实验**逐字节相同**。因此这里报告新确认场景，旧测试不回流调参。[确认实验 summary](../experiments/ics_circulation_v3/phase2_learning_confirmatory_20261009/summary.json)。

|策略|候选测试平均 regret ↓|独立完整部署平均成本 ↓|部署劣于基准的场景数|
|---|---:|---:|---:|
|基准候选|0.475|19.1275|0|
|旧库存解析|0.475|19.1275|0|
|时间化解析|0.025|18.2525|0|
|直接成本 ridge|0.050|18.2525|1|
|解析＋残差 ridge|0.075|18.2275|0|
|公开预测回放，额外计算|0.000|18.2275|0|

regret 相对于当前候选集合在两条标签未来上的平均最佳成本，不是全局最优值。所有部署任务均完成。残差部署仅在 40 场中的 1 场优于时间化解析，平均改善 0.025，约 0.14%；候选排名反而较差。预定 20 / 40 / 80 训练场景曲线中，残差测试 regret 为 0.050 / 0.050 / 0.075，没有显示随数据增多稳定改善。因此目前不能声称低样本优势或学习优于强解析对照。

计算成本也分别保存：完整场景平均墙钟时间，时间化解析 28.23 ms、残差 30.11 ms、预测回放 202.84 ms；这是完整 episode 的计时。标签阶段一次四候选预测回放评分 P95=97.63 ms、最大=108.59 ms。这两种计时口径不同，都不能替代真实端到端每请求的 100 ms 验收。

所有学习数据仍属于同一七节点合成拓扑族。它验证可执行的实验协议和模型比较，不证明跨机场推广。

## 7. 接入真实业务前还缺什么

下一步不宜继续以合成收益代替现场结论。需要取得或确认：真实初始托盘身份和库存、节点/接收容量与可等待位置、装卸及原空盘模块的服务和导出/接收接口、真实物流区与控制分区权限、预测身份/更新/取消/TTL 语义，以及 97→98 零容量边的实际状态。

在这些输入落实后，才可做南宁完整有限盘业务流接入、真实消息延迟/陈旧版本下的分区路由和故障恢复、严格逐件不增时保护、拥堵负载与跨天/跨拓扑验证。当前代码仍是研究原型；没有完成供应方集成、通用递归可行性证明或 TRE/TRC 保证。
